## 1.1 The 4 Programming Paradigms

Programming paradigms are fundamental styles of computer programming. Understanding their distinct characteristics is crucial for language classification and architectural design.

<Card>

### Definition 1.1.1 (Imperative Paradigm)

The **Imperative Paradigm** focuses on *how* to achieve a goal by describing a sequence of commands that change the program's state. 
- **Key Concepts:** State mutation, explicit loops, and sequential control flow.
- **Examples:** C, Java, Python.

</Card>

<Card>

### Definition 1.1.2 (Object-Oriented Paradigm)

The **Object-Oriented (OOP) Paradigm** organises software design around data, or objects, rather than functions and logic.
- **Abstraction:** Hiding complex reality while exposing only necessary parts.
- **Encapsulation:** Bundling data and methods, restricting direct access to internal state.
- **Inheritance:** Mechanism where a new class derives properties from an existing class.
- **Polymorphism:** Ability of different objects to respond to the same method call in their own way.
- **Examples:** Java, C++, C#.

</Card>

<Card>

### Definition 1.1.3 (Logic Paradigm)

The **Logic Paradigm** is based on formal logic. Programs are expressed as a set of facts and rules. Computation is a process of logical deduction and pattern matching.
- **Key Concepts:** Facts, rules, unification, and backtracking.
- **Examples:** Prolog, Datalog.

</Card>

<HighlightCard
  variant="neutral"
  title="Definition 1.1.4: The Functional Paradigm"
  description="The foundational model of Functional Programming, contrasting sharply with state-based paradigms."
>

The **Functional Paradigm** treats computation as the evaluation of mathematical functions and avoids changing state and mutable data. It is a *declarative* paradigm, focusing on *what* to compute rather than *how* to compute it.
- **Key Concepts:** Pure functions, immutability, and function composition.
- **Examples:** Haskell, Lisp, Erlang.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 1.1.1: Declarative vs. Imperative Execution"
  description="The fundamental distinction in control flow between Functional and Imperative paradigms."
>

- **Imperative Execution:** Relies on the Von Neumann fetch-execute cycle. The CPU repeatedly shuttles data across the shared bus between memory and registers (FETCH, DECODE, EXECUTE, STORE).
- **Functional Execution:** Relies on *graph reduction* and *β-reduction*. Expressions are evaluated by substituting arguments into function bodies until a normal form (value) is reached, completely abstracting away hardware memory management.

</HighlightCard>

## 6.2 Ad-Hoc Polymorphism & Typeclasses

**Ad-hoc polymorphism** (overloading) allows the same function name or operator to have *different implementations* depending on the type of its arguments. In Haskell, this is strictly governed by **Typeclasses**.

<HighlightCard
  variant="neutral"
  title="Definition 6.2.1: Defining Custom Typeclasses"
  description="A typeclass defines a set of functions (methods) that a type must implement to be considered a member."
>

```haskell
class MyEq a where
    (===) :: a -> a -> Bool
    (/==) :: a -> a -> Bool
    
    -- Default implementation (optional)
    x /== y = not (x === y)
```

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Example: Creating Instances for Custom ADTs</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Define the Data Type</StepTitle>
    ```haskell
    data TrafficLight = Red | Yellow | Green
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Implement the Instance</StepTitle>
    ```haskell
    instance MyEq TrafficLight where
        Red    === Red    = True
        Yellow === Yellow = True
        Green  === Green  = True
        _      === _      = False
    ```
  </Step>

  <Step number={3}>
    <StepTitle>Usage</StepTitle>
    `Red === Red` evaluates to `True`. The compiler resolves this to the specific `TrafficLight` instance.
  </Step>
</StepByStep>

### Definition 6.2.2 (Standard Typeclass Hierarchy)

- **`Eq`**: Types that can be tested for equality (`==`, `/=`).
- **`Ord`**: Types that can be ordered (`<`, `<=`, `>`, `>=`, `compare`). *Requires `Eq`*.
- **`Show`**: Types that can be converted to a `String` (`show`).
- **`Read`**: Types that can be parsed from a `String` (`read`).
- **`Num`**: Numeric types (`+`, `-`, `*`, `abs`, `signum`, `fromInteger`).
- **`Integral`**: Whole numbers (`div`, `mod`, `quot`, `rem`, `toInteger`). *Subclass of `Num`*.
- **`Fractional`**: Types that support true division (`/`, `recip`, `fromRational`). *Subclass of `Num`*.

</Card>

<HighlightCard
  variant="neutral"
  title="Advanced Theory: Hindley-Milner Unification"
  description="GHC infers types by finding a substitution for type variables that makes two types identical."
>

**Trace: `f x = x + True`**
1. Assign fresh variable: `x :: a`
2. `(+)` has type `Num n => n -> n -> n`. Constraint: `a ~ n` (and `Num n`).
3. `True :: Bool`. Constraint: `n ~ Bool`.
4. Compose: `a ~ n ~ Bool`. Check: Is `Bool` an instance of `Num`? **NO**.
5. **Type Error:** `No instance for (Num Bool)`.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Advanced Theory: Dictionary Passing"
  description="Typeclass constraints are compiled into explicit function arguments called dictionaries, guaranteeing zero runtime abstraction overhead."
>

```haskell
-- What you write:
sortBy :: Ord a => [a] -> [a]

-- What GHC compiles it to (conceptually):
data OrdDict a = OrdDict { dictCompare :: a -> a -> Ordering }
sortBy_compiled :: OrdDict a -> [a] -> [a]
```
When you call `sortBy [3,1,2]`, GHC automatically selects and passes the `OrdDict Int` record at compile time.

</HighlightCard>

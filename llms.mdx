# LLM Context & Integration

This document serves as the master instruction set and context guide for Large Language Models (LLMs) and AI agents interacting with the University CS Docs repository. If you are an AI assistant generating content, modifying code, or answering questions about this project, you must strictly adhere to the architectural patterns and output formats defined below.

## Project Context & Framework

This is a comprehensive, interactive documentation platform for Computer Science courses at the University of Botswana. It transforms static course materials into an engaging, searchable, and interactive learning experience.

### Technology Stack
- **Framework**: Next.js 15 (App Router)
- **Documentation Engine**: Fumadocs (handles routing, search, sidebar generation, and MDX rendering)
- **Language**: TypeScript (for components and quiz data), Python (for build automation)
- **Styling**: Tailwind CSS
- **Animations**: Framer Motion
- **Content Format**: MDX (Markdown + JSX)
- **Code Execution**: CodeSandbox Sandpack

### Directory Structure
- `content/docs/sem{X}/{course}/`: Contains the MDX files for course notes.
- `content/quiz-data/sem{X}/{course}/`: Contains the TypeScript files exporting quiz arrays.
- `components/`: Custom React components injected into the MDX pipeline.
- `apply-files.py`: A Python script that reads a JSON payload and writes the files to the filesystem.

## Custom MDX Components

The MDX files utilize specialized React components. When writing MDX, you must import and use these correctly:

1. **`<Quiz />`**: Renders an interactive multiple-choice quiz. It manages state, calculates scores, and provides feedback.
2. **`<Playground />`**: Wraps CodeSandbox Sandpack to allow users to edit and execute React/TypeScript code directly in the browser.
3. **`<SafeImage />`**: An image wrapper that gracefully handles broken links by displaying a styled fallback UI.

## The JSON Payload Workflow (CRITICAL)

To update or create notes and quizzes in this repository, you **must not** output raw text or use standard markdown code blocks for file generation. Instead, you must output a **SINGLE, VALID JSON OBJECT** that will be saved as `payload.json` and processed by `apply-files.py`.

### Strict JSON Formatting Rules
1. **No Markdown Wrappers**: Do not wrap the output in ` ```json ` or any other markdown formatting. Output only the raw JSON object.
2. **Keys**: The keys must be the exact relative file paths (e.g., `content/docs/sem3/csi243/01-paradigm-shift.mdx`).
3. **Values**: The values must be the raw string content of the files.
4. **Escaping**: 
   - All newlines inside the string values **must** be escaped as `\n`.
   - All double quotes inside the string values **must** be escaped as `\"`.
   - All backslashes must be escaped as `\\`.
5. **No Trailing Commas**: Ensure the JSON is strictly valid with no trailing commas.

## MDX Note Requirements

When generating an MDX file, it must follow this exact structure:

1. **Frontmatter**: Must include Fumadocs frontmatter at the very top:
   ```yaml
   ---
   title: "Chapter Title"
   description: "A brief description of the chapter."
   ---
   ```
2. **Imports**: Must include the exact imports for the Quiz component and its corresponding data file:
   ```tsx
   import { Quiz } from '@/components/quiz';
   import { quizData } from '@/content/quiz-data/sem3/csi243/{slug}-quiz';
   ```
3. **Content**: Use standard markdown, ` ```haskell ` or ` ```typescript ` code blocks, and Mermaid.js diagrams (` ```mermaid `) where applicable.
4. **Quiz Embedding**: Must end with the embedded quiz component:
   ```tsx
   <Quiz title="Chapter X Knowledge Check" questions={quizData} />
   ```

## TypeScript Quiz Data Requirements

When generating a quiz data file, it must follow these strict rules:

1. **Type Definition**: Must export the `Question` type and a `quizData` array.
2. **Interface**: Each question object must match this exact interface:
   ```typescript
   type Question = {
     question: string;
     options: string[];
     correctIndex: number;
     explanation?: string;
   };
   ```
3. **Options**: The `options` array must contain **exactly 4** plausible choices.
4. **Correct Index**: The `correctIndex` must be 0-indexed (0, 1, 2, or 3). You must randomize the position of the correct answer across the quiz to avoid bias.
5. **Explanations**: Always provide a clear, educational `explanation` string.

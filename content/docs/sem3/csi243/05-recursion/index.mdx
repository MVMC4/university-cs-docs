## Chapter 5: Recursion

Haskell has no `for` loop and no `while` loop. Repetition is expressed by **recursion**: a function defined in terms of itself.

This is not a limitation to work around. A recursive definition states *what* a value is rather than *how* to accumulate it, which is exactly the shift Chapter 1 described. But recursion has one hard requirement — it must stop — and most beginner failures come from getting that requirement wrong.

## The shape of every recursive definition

<Checklist title="Two parts, always" rules={[
  { type: 'must', text: 'A base case: defines the function for the first input values and terminates the recursion.' },
  { type: 'must', text: 'A recursive step: defines the function for other inputs in terms of itself, creating the loop.' },
  { type: 'avoid', text: 'Without a base case the function loops indefinitely.' },
  { type: 'note', text: 'Every recursive call must move the argument closer to the base case, or it will never be reached.' }
]} />

## Chapter outcomes

- Identify the base case and recursive step of a specification before writing any code.
- Explain why the order of equations matters in a recursive definition.
- Dry run a recursive call and show every reduction step.
- Write the same recursive function using conditionals, pattern matching, and guards.
- Recognise a definition that fails to terminate and say why.
- Report an out-of-domain argument with `error` rather than looping forever.

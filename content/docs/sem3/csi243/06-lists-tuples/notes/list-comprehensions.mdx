A **list comprehension** is a distinctive feature of Haskell. It allows a list to be created based on another list — describing the new list in terms of an existing one.

The syntax has two parts separated by a pipe:

```text
[ first part | second part ]
```

Read the pipe as **“such that.”**

```text
ghci> [x * 2 | x <- [1,2,3,4,5]]
[2,4,6,8,10]
```

Read aloud: “the list of `x * 2`, such that `x` is drawn from `[1,2,3,4,5]`.”

## 1. The first part: the output function

Everything **before** the pipe is the **output function**. It specifies what to apply to each input element. For every value that satisfies the second part, the output function is evaluated and its result is included in the constructed list.

```text
ghci> [x | x <- [1,2,3]]        -- output is the element itself
[1,2,3]
ghci> [x * x | x <- [1,2,3]]    -- output is the square
[1,4,9]
ghci> [(x, x * 2) | x <- [1,2,3]]  -- output is a tuple
[(1,2),(2,4),(3,6)]
```

The output function does not have to mention the generated variable at all, though it usually does.

## 2. The second part: generators and tests

Everything **after** the pipe specifies how to get the input elements. It can be a generator, one or more tests, or both.

### Generators

A **generator** has the form `symbol <- listExpression`. It says that the symbol takes each value from the list expression in turn.

```text
x <- [1..10]
```

Read: “`x` is drawn from the list `[1..10]`” — that is, `x` takes each integer between 1 and 10.

### Tests

**Tests** are comma-separated Boolean expressions, also called predicates or filters. Only values for which every test is `True` are used.

```text
ghci> [x | x <- [1..10], mod x 2 == 0]
[2,4,6,8,10]
```

Read: “the list of `x`, such that `x` is drawn from 1 to 10, and `x` is even.”

Several tests may be combined:

```text
ghci> [x | x <- [1..50], mod x 3 == 0, mod x 5 == 0]
[15,30,45]
```

Both conditions must hold, so this keeps multiples of 15.

## 4. Multiple generators

Multiple generators allow elements from two or more lists to be combined. Every combination is produced:

```text
ghci> [x + y | x <- [1,2,3], y <- [-3,0,3]]
[-2,1,4,-1,2,5,0,3,6]
```

Nine results, because three values of `x` each pair with three values of `y`.

**The rightmost generator varies fastest.** `x` is fixed at 1 while `y` runs through all three values, then `x` becomes 2, and so on — exactly like a nested loop with the second generator innermost.

```text
ghci> [(x, y) | x <- [1,2], y <- "ab"]
[(1,'a'),(1,'b'),(2,'a'),(2,'b')]
```

A later generator may depend on an earlier one, which avoids generating combinations you would only discard:

```text
ghci> [(x, y) | x <- [1..4], y <- [x..4]]
[(1,1),(1,2),(1,3),(1,4),(2,2),(2,3),(2,4),(3,3),(3,4),(4,4)]
```

Generators and tests may be interleaved, and a test placed early filters before the later generators run:

```text
ghci> [(x, y) | x <- [1..5], even x, y <- [1..2]]
[(2,1),(2,2),(4,1),(4,2)]
```

## 5. Comprehensions and recursion are interchangeable

Every comprehension can be written as a recursion, and vice versa. Compare the filter from the previous lesson:

```haskell
-- Recursive
positiveNumbers :: [Integer] -> [Integer]
positiveNumbers [] = []
positiveNumbers (x:xs)
  | x > 0     = x : positiveNumbers xs
  | otherwise = positiveNumbers xs

-- Comprehension
positiveNumbers' :: [Integer] -> [Integer]
positiveNumbers' xs = [x | x <- xs, x > 0]
```

```text
ghci> positiveNumbers' [-1,5,-3,8]
[5,8]
```

Both produce the same list. The comprehension states *what* the result is; the recursion states *how* to build it.

```haskell
-- Recursive
doubleAll :: [Integer] -> [Integer]
doubleAll []     = []
doubleAll (x:xs) = (x * 2) : doubleAll xs

-- Comprehension
doubleAll' :: [Integer] -> [Integer]
doubleAll' xs = [x * 2 | x <- xs]
```

<Callout type="info" title="When to prefer which">
A comprehension reads best when the result is “each element of that list, transformed and/or filtered.” Recursion is required when the result depends on more than one element at a time (as in `isSorted`), when elements must be combined into a single value (as in `sum`), or when the recursion is not over a list at all.
</Callout>

## 6. Comprehensions over tuples and strings

The generator pattern may itself be a pattern, which destructures as it generates:

```haskell
marks :: [(String, Integer)]
marks = [("Kago", 72), ("Naledi", 68), ("Thato", 91)]
```

```text
ghci> [name | (name, mark) <- marks, mark >= 70]
["Kago","Thato"]
ghci> [(name, mark + 5) | (name, mark) <- marks]
[("Kago",77),("Naledi",73),("Thato",96)]
```

Because a `String` is a list of `Char`, comprehensions work on text directly:

```text
ghci> [c | c <- "CSI243", c `elem` ['0'..'9']]
"243"
```

## 7. Common errors

| Attempt | Problem | Repair |
|---|---|---|
| `[x <- [1..5] \| x * 2]` | The two parts are the wrong way round | Output first, then pipe, then generator |
| `[x \| x <- [1..5]; even x]` | Tests are separated by commas | `[x \| x <- [1..5], even x]` |
| `[x \| x = [1..5]]` | A generator uses `<-`, not `=` | `x <- [1..5]` |
| `[x + y \| x <- [1,2]]` with `y` undefined | Every name must be generated or in scope | Add a generator for `y` |
| Result is empty unexpectedly | No element satisfies the tests | Check the predicate; try it alone at the prompt |
| Combinations in an unexpected order | The rightmost generator varies fastest | Reorder the generators |

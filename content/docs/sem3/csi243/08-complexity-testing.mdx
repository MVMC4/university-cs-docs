# Complexity, Laziness, and Space Leaks

Haskell's default evaluation strategy is **lazy** (or non-strict). This means expressions are not evaluated when they are bound to variables, but only when their results are actually needed.

## Lazy Evaluation and Thunks
When an expression is deferred, Haskell creates a **thunk**—a suspended computation or a pointer to code that will be evaluated later. 
- **Benefit**: Enables infinite data structures (e.g., `[1..]`) and avoids unnecessary computations (short-circuiting).
- **Cost**: Thunks consume memory. If not managed, they can lead to **space leaks**.

## Space Leaks and Strictness
Consider folding a massive list with the standard `foldl`:
```haskell
foldl (+) 0 [1, 2, 3, 4, 5]
-- Evaluates to: ((((0 + 1) + 2) + 3) + 4) + 5
```
Because `+` is lazy, Haskell builds a giant chain of unevaluated thunks. For a list of a million elements, this causes an $O(n)$ space leak and eventually a stack overflow.

**The Fix**: Always use `foldl'` (strict fold) from `Data.List`. The prime (`'`) indicates it evaluates the accumulator to **Weak Head Normal Form (WHNF)** at each step, preventing thunk buildup.

```haskell
import Data.List (foldl')

-- Evaluates strictly: 1, then 3, then 6, then 10, then 15. O(1) space.
sumStrict :: [Int] -> Int
sumStrict = foldl' (+) 0
```

## 7.1 Core Higher-Order Functions: The Holy Trinity

> 🌟 **CORE FOCUS:** `map`, `filter`, and `foldr` are the absolute foundation of declarative list processing in Haskell. They are heavily emphasized in the second half of the semester and will be central to lab assessments and exams. Master their signatures, behaviour, and evaluation traces.

Higher-Order Functions (HOFs) take functions as arguments or return them. They allow you to express *what* to compute rather than *how* to iterate.

### `map :: (a -> b) -> [a] -> [b]`
Applies a transformation function to every element in the list, preserving the list's structure.
```haskell
ghci> map (*2) [1,2,3]
[2,4,6]
ghci> map show [1,2,3]
["1","2","3"]
```

### `filter :: (a -> Bool) -> [a] -> [a]`
Keeps only the elements that satisfy a given predicate (boolean function), discarding the rest.
```haskell
ghci> filter even [1..10]
[2,4,6,8,10]
ghci> filter (>5) [1..10]
[6,7,8,9,10]
```

### `foldr` vs `foldl'`: Associativity & Strictness
Both reduce a list to a single value, but they differ fundamentally in evaluation order and strictness.

- **`foldr f z [x1, x2, x3]`** → `f x1 (f x2 (f x3 z))`  
  *Right-associative.* Lazy in its second argument, allowing it to work on **infinite lists** if the combining function short-circuits (like `||` or `:`).
- **`foldl' f z [x1, x2, x3]`** → `f (f (f z x1) x2) x3`  
  *Left-associative & strict.* Forces the accumulator at every step. Ideal for computing a single scalar (like a sum or product) over **finite lists** to guarantee O(1) space.

#### `foldr` Dry Run Trace
To understand how `foldr` builds right-associative expression trees, trace `foldr (+) 0 [1,2,3]`:
```text
  foldr (+) 0 [1,2,3]
=> 1 + (foldr (+) 0 [2,3])
=> 1 + (2 + (foldr (+) 0 [3]))
=> 1 + (2 + (3 + (foldr (+) 0 [])))
=> 1 + (2 + (3 + 0))       -- Base case reached
=> 1 + (2 + 3)
=> 1 + 5
=> 6
```

```haskell
import Data.List (foldl')

ghci> foldr (+) 0 [1,2,3]
6
ghci> foldl' (+) 0 [1,2,3]
6
```

> ⚠️ **Lab Tip:** For sums, products, or counters over finite lists, **always prefer `foldl'`** (or the built-in `sum`/`product`). Using lazy `foldr` or `foldl` for strict scalar accumulation will cause space leaks.

## 7.2 List Comprehensions

List comprehensions provide a declarative, set-builder-like syntax for generating and filtering lists. Under the hood, GHC compiles them directly into efficient `map`/`filter`/`concatMap` pipelines.

**Syntax:** `[expression | generator(s), predicate(s)]`

```haskell
-- Basic transformation (equivalent to map)
ghci> [x * 2 | x <- [1..5]]
[2,4,6,8,10]

-- With guards/filters (equivalent to filter)
ghci> [x * 2 | x <- [1..10], even x]
[4,8,12,16,20]

-- Multiple generators (Cartesian product)
ghci> [(x, y) | x <- [1,2], y <- ['a','b']]
[(1,'a'),(1,'b'),(2,'a'),(2,'b')]

-- Dependent generators (later generators can use earlier ones)
ghci> [(x,y) | x <- [1..3], y <- [x..3]]
[(1,1),(1,2),(1,3),(2,2),(2,3),(3,3)]
```

**Equivalence to HOFs:**  
`[x*2 | x <- [1..10], even x]` is functionally identical to `map (*2) (filter even [1..10])`.

oddSquares :: [Int]

consonants :: [Char]

**3. Pythagorean Triples (Dependent Generators)**
*   **Task:** Return tuples `(a, b, c)` where $a^2 + b^2 = c^2$ below 100. The lab explicitly notes that `(3,4,5)` and `(4,3,5)` are the same. We solve this by making the generator for `b` dependent on `a` (`b <- [a..c]`), ensuring $a \le b$.
```haskell
pythTriples :: [(Int, Int, Int)]
pythTriples = [ (a, b, c) | c <- [1..100], a <- [1..c], b <- [a..c], a^2 + b^2 == c^2 ]
```

**4. Student Marks Averaging (Pattern Matching in Comprehensions)**
*   **Task:** Extract test and assignment averages from a list of lists formatted as `[T1, T2, A1, A2, A3]`.
```haskell
marks :: [[Int]]
marks = [[20,35,67,89,11],[45,78,90,12,34],[90,67,89,56,78]]

averages :: [(Double, Double)]
averages = [ ( (fromIntegral (t1+t2))/2.0, (fromIntegral (a1+a2+a3))/3.0 ) 
           | [t1, t2, a1, a2, a3] <- marks ]
```
Notice how we pattern match the exact 5-element list structure `[t1, t2, a1, a2, a3]` directly inside the generator!

## 7.3 Standard Library Functions & Lab Applications

Haskell's `Prelude` and `Data.List` provide battle-tested functions for common patterns. Memorise their signatures and behaviour.

```haskell
-- zip: Pairs elements from two lists. Stops at the shortest list.
ghci> zip [1,2,3] ["a","b","c"]
[(1,"a"),(2,"b"),(3,"c")]

-- unzip: Reverses zip into a tuple of lists.
ghci> unzip [(1,"a"),(2,"b")]
([1,2],["a","b"])

-- take / drop: Extract or remove n elements from the start.
ghci> take 3 [1..10]
[1,2,3]
ghci> drop 2 [1..10]
[3,4,5,6,7,8,9,10]

-- span: Splits a list at the first predicate failure.
-- span p xs == (takeWhile p xs, dropWhile p xs)
ghci> span (< 5) [1,2,3,5,6,7]
([1,2,3],[5,6,7])

-- iterate: Infinite list of repeated function applications.
ghci> take 5 (iterate (*2) 1)
[1,2,4,8,16]
```

### Lab Application: `twoLists` (Standard vs Recursive)
In earlier labs, you may have implemented element-wise pairing manually. Haskell's `zip` is the idiomatic, production-ready alternative.

**Manual Recursive Implementation:**
```haskell
twoListsRecursive :: [a] -> [b] -> [(a, b)]
twoListsRecursive (x:xs) (y:ys) = (x, y) : twoListsRecursive xs ys
twoListsRecursive _ _ = []
```

**Standard Library Implementation:**
```haskell
-- Simply use the built-in zip!
twoListsStandard :: [a] -> [b] -> [(a, b)]
twoListsStandard = zip

ghci> twoListsStandard [1,2,3] [10,20,30]
[(1,10),(2,20),(3,30)]
```
Always prefer `zip` in practice: it is rigorously tested, handles edge cases cleanly, and is heavily optimised by GHC.

## 7.4 Advanced Theory: Fold as Catamorphism & Fusion

*(This section covers advanced compiler concepts and structural recursion theory. Focus on Sections 7.1–7.3 for core lab/exam preparation.)*

### `foldr` as Structural Replacement (Catamorphism)
A `fold` is not merely a loop — it is a structural replacement. `foldr f z` replaces every cons cell `(:)` in the list with the combining function `f`, and every empty list `[]` with the base value `z`.

```haskell
foldr f z [1, 2, 3]
=> f 1 (f 2 (f 3 z))       -- (:) replaced by f, [] replaced by z
```
This structural view explains why `foldr (:) []` is the identity function: it replaces each constructor with itself.

### GHC Rewrite Rules & Stream Fusion
GHC allows library authors to embed equational laws directly into compiled code via the `{-# RULES #-}` pragma. The compiler applies these as source-to-source transformations during optimisation.

```haskell
{-# RULES
  "map/map"  [~1]  forall f g xs.
    map f (map g xs) = map (f . g) xs
  #-}
```
**Why it matters:** Without fusion, `map f (map g xs)` allocates an intermediate list of size $n$, then traverses it again. The fusion rule rewrites it to `map (f . g) xs` — a single O(n) pass with zero intermediate allocations. Stream fusion extends this to eliminate memory allocation across entire producer-consumer pipelines (`map . filter . sum`), yielding performance comparable to hand-written C loops.

## 7.5 Compiler Error Examples

❌ **WRONG CODE (Fold base value type mismatch)**
```haskell
sumAndCount :: [Int] -> (Int, Int)
sumAndCount = foldr (\x (s, c) -> (s + x, c + 1)) 0
```
**GHC Error:**
```text
Couldn't match expected type '(Int, Int)' with actual type 'Integer'
In the second argument of 'foldr', namely '0'
```
✅ **CORRECTED CODE**
```haskell
sumAndCount :: [Int] -> (Int, Int)
sumAndCount = foldr (\x (s, c) -> (s + x, c + 1)) (0, 0)

ghci> sumAndCount [10, 20, 30]
(60,3)
```

❌ **WRONG CODE (Pipeline element type mismatch)**
```haskell
processBad :: [Int] -> [String]
processBad = map show . filter (> 0) . map (\x -> x ++ "!")
```
**GHC Error:**
```text
Couldn't match type 'Int' with '[Char]'
In the expression: x ++ "!"
Expected type: Int -> Int, Actual type: Int -> [Char]
```
✅ **CORRECTED CODE**
```haskell
processGood :: [Int] -> [String]
processGood = map show . filter (> 0) . map (+ 1)

ghci> processGood [-1, 0, 2, 4]
["3","5"]
```

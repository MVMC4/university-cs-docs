## 8.1 Functor & Law Verification

### Intuition: Contexts, Not Just Containers
Before writing code, discard the idea that a Functor is merely a "box" holding a value. A Functor represents a **computational context**. A list is a context of non-determinism (zero, one, or many values). `Maybe` is a context of possible failure. The function type `(r ->)` is a context of a read-only environment. 

### Formal Definition
```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
```
`fmap` applies a pure function to the value(s) inside the context, preserving the structure of the context itself.

### Worked Code
```haskell
-- GHCi session
ghci> fmap (+1) [1, 2, 3]
[2,3,4]
ghci> fmap (+1) (Just 5)
Just 6
ghci> fmap (+1) (*2) 3  -- Function context!
9
```

### Law Verification: List `[]`
A lawful Functor must satisfy two laws. We prove them for `[]` using structural induction.

**1. Identity Law:** `fmap id = id`
*Base Case:* `fmap id [] = [] = id []`
*Inductive Step:* Assume `fmap id xs = xs`.
`fmap id (x:xs) = id x : fmap id xs = x : xs = id (x:xs)`.

**2. Composition Law:** `fmap (f . g) = fmap f . fmap g`
*Base Case:* 
`fmap (f . g) [] = []`
`(fmap f . fmap g) [] = fmap f (fmap g []) = fmap f [] = []`.
*Inductive Step:* Assume `fmap (f . g) xs = fmap f (fmap g xs)`.
`fmap (f . g) (x:xs)`
`= (f . g) x : fmap (f . g) xs`
`= f (g x) : fmap f (fmap g xs)`  *(by Induction Hypothesis)*
`= fmap f (g x : fmap g xs)`
`= fmap f (fmap g (x:xs))`
`= (fmap f . fmap g) (x:xs)`.

> ⚠️ **Common Misconception:** "Functor means container."
> **Correction:** Functor means *mappable computational context*. The function type `(r ->)` is a Functor! `fmap f g = f . g`. It maps over the *output* of the function.

## 8.2 Applicative & Independent Effects

### Intuition: Applying Functions in a Context
While `fmap` applies a pure function to a wrapped value, what if the *function itself* is wrapped in a context? Applicative solves this. It is perfectly suited for **independent effects**, like validating multiple fields of a record where you want to accumulate all errors rather than failing on the first one.

### Formal Definition
```haskell
class Functor f => Applicative f where
    pure  :: a -> f a
    (<*>) :: f (a -> b) -> f a -> f b
```

### Worked Code: Error Accumulation
```haskell
-- Assuming a custom Validation Applicative that collects errors via Semigroup
data User = User { name :: String, age :: Int }

validateName :: String -> Validation [String] String
validateAge  :: Int -> Validation [String] Int

mkUser :: String -> Int -> Validation [String] User
mkUser n a = User <$> validateName n <*> validateAge a

-- GHCi session
ghci> mkUser "" (-5)
Failure ["Name cannot be empty", "Age must be positive"]
```
If we used a Monad (like standard `Either`), it would short-circuit and only report the first error. Applicative allows independent branches to execute and combine their contexts.

**Law Verification for Maybe:**
`pure f <*> x = fmap f x`
`Just f <*> x = fmap f x`. Holds perfectly by definition of `<*>` for `Maybe`.

## 8.3 Monad Laws & Kleisli Composition

### Intuition: Dependent Sequencing
Applicatives handle independent effects. Monads handle **dependent** computations—where the output of one step determines the structure of the next step. 

### Formal Definition
```haskell
class Applicative m => Monad m where
    return :: a -> m a
    (>>=)  :: m a -> (a -> m b) -> m b
```

### The Three Monad Laws
1. **Left Identity:** `return a >>= f ≡ f a`
2. **Right Identity:** `m >>= return ≡ m`
3. **Associativity:** `(m >>= f) >>= g ≡ m >>= (\x -> f x >>= g)`

### Verification for `Maybe`
**Left Identity:** `return a >>= f` → `Just a >>= f` → `f a`.
**Right Identity:** 
- `Nothing >>= return` → `Nothing`
- `Just x >>= return` → `return x` → `Just x`
**Associativity:** Holds because `>>=` simply unwraps the `Just` and passes it along; if it hits `Nothing`, both sides short-circuit to `Nothing`.

### Kleisli Composition `(>=>)`
Monads form a category where morphisms are functions `a -> m b`. The composition operator is `(>=>)`.
```haskell
(>=>) :: Monad m => (a -> m b) -> (b -> m c) -> (a -> m c)
(f >=> g) x = f x >>= g
```
The Monad laws are exactly the category laws (identity and associativity) for Kleisli arrows!

## 8.4 Concrete Monad Worked Examples

Students often fail exams because they only know Monads abstractly. Let's trace three concrete instances.

### 1. Maybe (Safe Division Pipeline)
```haskell
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)

pipeline :: Maybe Int
pipeline = Just 10 >>= safeDiv 2 >>= safeDiv 5

-- GHCi session
ghci> pipeline
Just 1
```
`Nothing` propagates through the chain of `>>=` without any explicit `case` checks or nested `if` statements.

### 2. List (Non-determinism)
```haskell
-- GHCi session
ghci> do { x <- [1,2]; y <- [10,20]; return (x+y) }
[11,21,12,22]
```
The List monad computes all possible combinations. The `do` notation desugars into nested `concatMap` operations.

### 3. Either String (Error Propagation)
```haskell
parseHex :: String -> Either String Int
parseHex s = maybe (Left "Bad hex") Right (readMaybe s)

pipeline :: Either String Int
pipeline = do
    a <- parseHex "A"
    b <- parseHex "2"
    return (a + b)

-- GHCi session
ghci> pipeline
Right 12
```
Failure at any step carries an explicit error message, unlike `Maybe`.

## 8.5 `do`-Notation Desugaring

A 4-action `do` block desugars mechanically. You must be able to do this by hand in an exam.

```haskell
do
 a <- act1
 b <- act2 a
 c <- act3 b
 return (a + b + c)
```
**Step 1:** `act1 >>= \a -> do { b <- act2 a; ... }`
**Step 2:** `act1 >>= \a -> act2 a >>= \b -> do { c <- act3 b; ... }`
**Step 3:** `act1 >>= \a -> act2 a >>= \b -> act3 b >>= \c -> return (a + b + c)`

Notice how every `<-` becomes a lambda argument for the next `>>=`.

## 8.6 Compiler Error Examples

❌ **WRONG CODE (Missing Monad Instance)**
```haskell
process :: [Int] -> [Int]
process xs = xs >>= \x -> Just (x + 1)
```
**GHC Error:**
```text
Couldn't match type ‘Maybe’ with ‘[]’
Expected type: [Int]
  Actual type: Maybe Int
```
✅ **CORRECTED CODE**
```haskell
process :: [Int] -> [Maybe Int]
process xs = xs >>= \x -> [Just (x + 1)]
```
*Explanation:* The left side of `>>=` is a List, so the right side *must* return a List.

❌ **WRONG CODE (`<-` outside `do`)**
```haskell
main = 
 name <- getLine
 putStrLn name
```
**GHC Error:**
```text
parse error on input ‘<-’
```
✅ **CORRECTED CODE**
```haskell
main = do
 name <- getLine
 putStrLn name
```
*Explanation:* `<-` is not a standalone binding operator; it is syntactic sugar exclusively valid inside a `do` block (or list comprehension).

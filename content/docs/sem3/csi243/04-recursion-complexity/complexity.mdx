## 4.3 Complexity of Functions

Understanding the time and space complexity of recursive algorithms is a syllabus mandate. In Haskell, the choice of recursion pattern directly dictates performance.

<HighlightCard
  variant="neutral"
  title="Theorem 4.3.1: The Cost of Concatenation (`++`)"
  description="The `++` operator has a time complexity of O(k), where k is the length of the left operand, because it must traverse the entire left list to reach its end."
>

For example, `[1, 2, 3] ++ [4]` requires traversing 3 elements to attach `[4]` to the final `[]` constructor.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 4.3.2: The O(n²) Trap of Naive Reversal"
  description="The naive `revList` implementation is O(n²) in time complexity."
>

In `revList (x:xs) = revList xs ++ [x]`, the recursive call `revList xs` returns a list of length $n-1$. Appending `[x]` to it using `++` takes $O(n-1)$ time. 
Summing this cost over all $n$ recursive steps yields: $O(n) + O(n-1) + \dots + O(1) = O(n^2)$.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 4.3.3: The Accumulator Pattern (Tail Recursion)"
  description="Passing an accumulator as an extra argument allows list reversal to be performed in O(n) time."
>

```haskell
revAcc :: [a] -> [a] -> [a]
revAcc []     acc = acc
revAcc (x:xs) acc = revAcc xs (x:acc)

revList :: [a] -> [a]
revList xs = revAcc xs []
```
Because the cons operator `:` operates in $O(1)$ time, each of the $n$ recursive steps takes constant time, resulting in an overall $O(n)$ time complexity.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Proof: Exponential Time Complexity of Naive Fibonacci</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Naive Implementation</StepTitle>
    ```haskell
    fib :: Int -> Int
    fib 0 = 0
    fib 1 = 1
    fib n = fib (n-1) + fib (n-2)
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Trace the Call Tree for `fib 4`</StepTitle>
    ```text
    fib 4
    = fib 3 + fib 2
    = (fib 2 + fib 1) + (fib 1 + fib 0)
    = ((fib 1 + fib 0) + 1) + (1 + 0)
    = ((1 + 0) + 1) + 1
    = (1 + 1) + 1
    = 3
    ```
  </Step>

  <Step number={3}>
    <StepTitle>Analyze the Redundancy</StepTitle>
    Notice that `fib 2` is computed twice, and `fib 1` is computed three times. The call tree branches into two at every step (except base cases).
  </Step>

  <Step number={4}>
    <StepTitle>Conclude the Complexity</StepTitle>
    The number of nodes in this call tree grows proportionally to the golden ratio $\phi^n$, which is bounded by $O(2^n)$. This exponential time complexity makes the naive implementation intractable for large $n$.
  </Step>
</StepByStep>

<Card>

### Definition 4.3.1 (Space Complexity and Thunks)

In Haskell, space complexity is influenced by lazy evaluation. A non-tail-recursive function like naive `fac n = n * fac (n-1)` builds a chain of unevaluated thunks (suspended computations) of size $O(n)$, leading to $O(n)$ space complexity. Tail-recursive functions with strict accumulators can achieve $O(1)$ auxiliary space complexity.

</Card>

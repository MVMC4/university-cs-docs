## 1. Data Types & Variables

Java is a **strongly typed** language, meaning every variable must be declared with a specific data type. This catches errors at compile-time rather than runtime.

### Primitive Data Types
These are the most basic data types built into Java. They hold simple values and are stored in the **Stack** memory for fast access.

<SafeImage 
  src="/images/primitive-types-chart.png" 
  alt="Java Primitive Data Types" 
  caption="Figure 2: The 8 primitive types with their sizes and ranges"
  className="w-full max-w-4xl mx-auto"
/>

| Type | Size | Range | Default | Example |
| :--- | :--- | :--- | :--- | :--- |
| `byte` | 1 byte | -128 to 127 | 0 | `byte b = 100;` |
| `short` | 2 bytes | -32,768 to 32,767 | 0 | `short s = 30000;` |
| `int` | 4 bytes | ±2 billion | 0 | `int i = 100000;` |
| `long` | 8 bytes | ±9 quintillion | 0L | `long l = 100000L;` |
| `float` | 4 bytes | 6-7 decimal digits | 0.0f | `float f = 5.75f;` |
| `double`| 8 bytes | 15 decimal digits | 0.0d | `double d = 19.99;` |
| `boolean`| 1 bit | true/false | false | `boolean b = true;` |
| `char` | 2 bytes | Unicode character | '\u0000' | `char c = 'A';` |

### Reference Data Types
These refer to objects and arrays. They are stored in the **Heap** memory, and the variable holds a *reference* (memory address) to the actual data.

<SafeImage 
  src="/images/stack-vs-heap-variables.png" 
  alt="Stack vs Heap Memory" 
  caption="Figure 3: Primitives on Stack, Objects on Heap"
  className="w-full max-w-3xl mx-auto"
/>

```java
// Reference types examples
String name = "Alice";           // String object
int[] numbers = {1, 2, 3};       // Array object
Scanner sc = new Scanner(System.in); // Scanner object
```

> **Important**: Strings are **NOT** primitives! They're immutable objects.

### Type Casting
Converting one data type to another.

**Widening (Implicit)** - Automatic, safe:
```java
int myInt = 9;
double myDouble = myInt; // 9.0 - no data loss
```

**Narrowing (Explicit)** - Manual, may lose data:
```java
double myDouble = 9.78;
int myInt = (int) myDouble; // 9 - decimal truncated!
```

## 2. Control Flow Statements

Control flow statements dictate the order in which your code is executed.

### Conditional Statements

#### `if`, `else if`, `else`
Used to execute blocks of code based on boolean conditions.

```java
int score = 85;

if (score >= 90) {
    System.out.println("Grade: A");
} else if (score >= 80) {
    System.out.println("Grade: B"); // Executes
} else if (score >= 70) {
    System.out.println("Grade: C");
} else {
    System.out.println("Grade: F");
}
```

<SafeImage 
  src="/images/if-else-flowchart.png" 
  alt="If-Else Flowchart" 
  caption="Figure 5: Decision tree for grade calculation"
  className="w-full max-w-2xl mx-auto"
/>

#### `switch` Statement
An alternative to long `if-else if` chains.

```java
String day = "WEDNESDAY";

switch (day) {
    case "MONDAY":
        System.out.println("Start of work week");
        break;
    case "WEDNESDAY":
        System.out.println("Midweek!"); // Executes
        break;
    case "FRIDAY":
        System.out.println("Weekend soon");
        break;
    default:
        System.out.println("Another day");
}
```

> **Note**: Without `break`, execution "falls through" to the next case!

### Loops

<SafeImage 
  src="/images/loop-types-diagram.png" 
  alt="Java Loop Types Comparison" 
  caption="Figure 6: When to use each loop type"
  className="w-full max-w-4xl mx-auto"
/>

1. **`for` Loop** - Known iterations:
```java
for (int i = 0; i < 5; i++) {
    System.out.println("Iteration: " + i);
}
```

2. **`while` Loop** - Condition-based:
```java
int count = 0;
while (count < 3) {
    System.out.println("Count: " + count);
    count++;
}
```

3. **`do-while` Loop** - Executes at least once:
```java
int i = 0;
do {
    System.out.println(i); // Prints 0
    i++;
} while (i < 0); // Condition false, but already ran once
```

4. **Enhanced `for-each` Loop** - Arrays/Collections:
```java
String[] fruits = {"Apple", "Banana", "Cherry"};
for (String fruit : fruits) {
    System.out.println(fruit);
}
```

## 3. Arrays

An array is a fixed-size, contiguous block of memory storing multiple values of the **same type**.

### 1D Arrays

<SafeImage 
  src="/images/array-memory-layout.png" 
  alt="Array Memory Layout" 
  caption="Figure 7: Contiguous memory allocation with index access"
  className="w-full max-w-3xl mx-auto"
/>

```java
// Declaration and Initialization
int[] numbers = new int[5];        // [0, 0, 0, 0, 0]
int[] primes = {2, 3, 5, 7, 11};   // Shorthand

// Accessing and Modifying
primes[0] = 13;                    // [13, 3, 5, 7, 11]
System.out.println(primes.length); // 5

// Traversing
for (int i = 0; i < primes.length; i++) {
    System.out.println(primes[i]);
}
```

### 2D Arrays (Matrices)

```java
// Create a 3x3 matrix
int[][] matrix = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};

// Access element at row 1, column 2 (value = 6)
int value = matrix[1][2];
```

<SafeImage 
  src="/images/2d-array-grid.png" 
  alt="2D Array Visualization" 
  caption="Figure 8: Matrix[row][column] indexing"
  className="w-full max-w-2xl mx-auto"
/>

```java
// Traversing 2D array
for (int row = 0; row < matrix.length; row++) {
    for (int col = 0; col < matrix[row].length; col++) {
        System.out.print(matrix[row][col] + " ");
    }
    System.out.println();
}
```

## 4. User-Defined Classes & Objects

Java is Object-Oriented. **Classes** are blueprints; **Objects** are instances.

### Anatomy of a Class

<SafeImage 
  src="/images/class-anatomy.png" 
  alt="Class Structure Diagram" 
  caption="Figure 9: Fields, constructors, and methods"
  className="w-full max-w-3xl mx-auto"
/>

```java
public class Car {
    // 1. Fields (State)
    private String model;
    private int year;

    // 2. Constructor (Initialization)
    public Car(String model, int year) {
        this.model = model;  // 'this' = current object
        this.year = year;
    }

    // 3. Methods (Behavior)
    public void drive() {
        System.out.println("The " + model + " is driving.");
    }
    
    // 4. Getters/Setters (Encapsulation)
    public String getModel() { return model; }
    public void setModel(String model) { this.model = model; }
}
```

### Instantiation

```java
Car myCar = new Car("Toyota", 2022);
myCar.drive(); // "The Toyota is driving."
```

## 5. The Four Pillars of OOP

### 1. Encapsulation
Bundling data and methods while restricting direct access.

**How**: `private` fields + `public` getters/setters  
**Why**: Protects internal state from unintended changes

<SafeImage 
  src="/images/encapsulation-capsule.png" 
  alt="Encapsulation Concept" 
  caption="Figure 11: Data hidden inside, controlled access via methods"
  className="w-full max-w-2xl mx-auto"
/>

### 2. Inheritance
A subclass acquires properties of a superclass.

```java
public class Animal {
    public void eat() { 
        System.out.println("Eating..."); 
    }
}

public class Dog extends Animal {
    public void bark() { 
        System.out.println("Woof!"); 
    }
}

Dog d = new Dog();
d.eat();  // Inherited from Animal
d.bark(); // Defined in Dog
```

<SafeImage 
  src="/images/inheritance-tree.png" 
  alt="Inheritance Hierarchy" 
  caption="Figure 12: Parent-child class relationship"
  className="w-full max-w-3xl mx-auto"
/>

### 3. Polymorphism
"Many forms" - methods behave differently based on the object.

**Compile-time (Overloading)**:
```java
public int add(int a, int b) { return a + b; }
public double add(double a, double b) { return a + b; }
```

**Run-time (Overriding)**:
```java
@Override
public void eat() { 
    System.out.println("Dog eating bones"); 
}
```

### 4. Abstraction
Hide complexity, show essentials.

**Abstract Class**:
```java
abstract class Shape {
    abstract double area(); // Must implement
    
    public void display() { 
        System.out.println("Area: " + area()); 
    }
}
```

**Interface**:
```java
interface Drivable {
    void drive();
    void stop();
}
```

## 7. Generics

Type-safe code that works with different object types.

### Why Generics?

**Without Generics** (Unsafe):
```java
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0); // Risky cast!
```

**With Generics** (Safe):
```java
List<String> list = new ArrayList<>();
list.add("Hello");
String s = list.get(0); // No cast needed!
```

<SafeImage 
  src="/images/generics-safety.png" 
  alt="Generics Type Safety" 
  caption="Figure 15: Compile-time checking prevents runtime errors"
  className="w-full max-w-3xl mx-auto"
/>

### Generic Classes

```java
public class Box<T> {
    private T item;

    public void setItem(T item) {
        this.item = item;
    }

    public T getItem() {
        return item;
    }
}

Box<Integer> intBox = new Box<>();
intBox.setItem(10);
```

### Bounded Type Parameters

```java
// T must extend Number
public <T extends Number> void printValue(T num) {
    System.out.println(num.doubleValue());
}
```

### Wildcards

1. **`? extends Number`** - Read-only (upper bound)
2. **`? super Integer`** - Write-only (lower bound)  
3. **`?`** - Any type (unbounded)

## 8. Memory Management: Stack vs. Heap

<SafeImage 
  src="/images/stack-heap-detailed.png" 
  alt="Stack and Heap Memory" 
  caption="Figure 17: Complete memory model with references and objects"
  className="w-full max-w-4xl mx-auto"
/>

### Stack Memory
- **Stores**: Primitives + object references
- **Speed**: Very fast (LIFO)
- **Lifetime**: Method scope
- **Size**: Limited (~1MB per thread)

### Heap Memory
- **Stores**: Actual objects and arrays
- **Speed**: Slower than stack
- **Lifetime**: Until no references exist
- **Management**: Garbage Collector (GC)

```java
public void example() {
    int x = 10;              // Stack: x = 10
    Car myCar;               // Stack: myCar (null reference)
    myCar = new Car();       // Heap: Car object created
                             // Stack: myCar → points to Heap
}                            // Stack cleared, Heap object 
                             // eligible for GC
```

> **Garbage Collection**: When no references point to a Heap object, the GC automatically deletes it.

## 1. Pointer Mechanics — The Right Mental Model

When manipulating linked list pointers, always follow this sequence: **save -> link new -> update predecessor**. Reversing this order loses references and causes memory leaks or null pointer exceptions.

<InteractiveStepper>
  <StepperStep title="Insert at Middle  --  Problem Setup">
    We have the list `1 → 3 → 5 → 7` and want to insert `4` after node with value `3`.

    We first traverse to find the predecessor node (value = 3):

    ```java
    Node curr = head;
    while (curr != null && curr.data != 3) {
        curr = curr.next;
    }
    // curr → node(3), curr.next → node(5)
    ```
  </StepperStep>
  <StepperStep title="Step 1: Create new node">
    ```java
    Node newNode = new Node(4);
    // newNode → [4 | null]
    ```

    State:
    ```
    curr → [3 | →] → [5 | →] → [7 | null]
    newNode → [4 | null]
    ```
  </StepperStep>
  <StepperStep title="Step 2: Connect new node's next BEFORE changing curr.next">
    This is the critical ordering. We must save the reference to node(5) inside newNode first.

    ```java
    newNode.next = curr.next;  // newNode → node(5)
    ```

    State:
    ```
    curr → [3 | →] → [5 | →] → [7 | null]
                 ↑
    newNode → [4 | →]
    ```

    Both `curr.next` and `newNode.next` point to node(5). Safe to update `curr.next` now.
  </StepperStep>
  <StepperStep title="Step 3: Update predecessor pointer">
    ```java
    curr.next = newNode;  // node(3) → node(4)
    ```

    Final state: `1 → 3 → 4 → 5 → 7` ✓

    If we had done `curr.next = newNode` FIRST in step 2, we would have lost the reference to node(5) permanently.
  </StepperStep>
</InteractiveStepper>

<InteractiveStepper>
  <StepperStep title="Delete Middle Node  --  Find Predecessor">
    Delete node with value `5` from `1 → 3 → 5 → 7`.

    Traverse to find the node BEFORE the target:

    ```java
    Node curr = head;
    while (curr.next != null && curr.next.data != 5) {
        curr = curr.next;
    }
    // curr → node(3), curr.next → node(5) [target]
    ```
  </StepperStep>
  <StepperStep title="Bypass the target node">
    ```java
    curr.next = curr.next.next;  // node(3) → node(7), skipping node(5)
    ```

    Final state: `1 → 3 → 7` ✓

    Node(5) is now unreferenced and will be garbage collected by the JVM.

    **Full single-method implementation:**
    ```java
    public Node deleteByValue(Node head, int target) {
        if (head == null) return null;
        if (head.data == target) return head.next; // Delete head case
        Node curr = head;
        while (curr.next != null && curr.next.data != target) {
            curr = curr.next;
        }
        if (curr.next != null) {
            curr.next = curr.next.next; // Bypass target
        }
        return head;
    }
    ```
  </StepperStep>
</InteractiveStepper>

  highlightCol="dll"
/>

<HighlightCard variant="neutral" title="DLL Deletion is O(1)  --  Here Is Why">

In an SLL, to delete node `C`, you must have a pointer to `B` (the predecessor) to do `B.next = D`. Finding B requires O(n) traversal.

In a DLL, node `C` already holds `C.prev → B`. So deletion from a DLL given only the node reference is:

```java
public void deleteNode(DLLNode node) {
    if (node.prev != null) node.prev.next = node.next;  // B.next → D
    if (node.next != null) node.next.prev = node.prev;  // D.prev → B
    // node is now disconnected — GC will collect it
}
```
O(1) with no traversal needed. This is why `LinkedHashMap` (Java's LRU cache backing structure) uses a DLL internally.
</HighlightCard>

## 3. Two-Pointer Techniques

Two-pointer algorithms solve many linked list problems in O(n) time and O(1) space that would otherwise require O(n) extra memory.

### Find Middle Node (Slow/Fast Pointers)

```java
public Node findMiddle(Node head) {
    Node slow = head;
    Node fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;        // moves 1 step
        fast = fast.next.next;   // moves 2 steps
    }
    return slow; // When fast reaches end, slow is at middle
}
```

**Why it works:** Fast moves at 2x the speed of slow. When fast reaches the end (n steps), slow has moved n/2 steps — exactly the middle.

### Floyd's Cycle Detection

```java
public boolean hasCycle(Node head) {
    Node slow = head;
    Node fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true; // They meet inside the cycle
    }
    return false; // fast reached null — no cycle
}
```

### Find Cycle Start (After Detecting a Cycle)

```java
public Node findCycleStart(Node head) {
    Node slow = head, fast = head;
    // Phase 1: detect cycle
    do { slow = slow.next; fast = fast.next.next; }
    while (slow != fast);
    // Phase 2: find cycle start
    slow = head;
    while (slow != fast) { slow = slow.next; fast = fast.next; }
    return slow; // Meeting point = cycle start
}
```

**Why phase 2 works:** After phase 1, the distance from head to cycle start equals the distance from the meeting point to cycle start (mathematical proof using modular arithmetic on cycle length). Moving both pointers at speed 1 brings them to the same node — the cycle start.

## 4. Reversing a Linked List — Iterative vs Recursive

<Tabs items={['Iterative O(1) space', 'Recursive O(n) space']}>
  <Tab>
  ```java
  public Node reverse(Node head) {
      Node prev = null;
      Node curr = head;
      while (curr != null) {
          Node nextTemp = curr.next; // Save next
          curr.next = prev;          // Reverse pointer
          prev = curr;               // Advance prev
          curr = nextTemp;           // Advance curr
      }
      return prev; // prev is the new head
  }
  ```
  Three-pointer technique: `prev`, `curr`, `nextTemp`. Each iteration: save -> reverse -> advance.
  </Tab>
  <Tab>
  ```java
  public Node reverseRecursive(Node head) {
      if (head == null || head.next == null) return head; // Base case
      Node newHead = reverseRecursive(head.next);         // Reverse rest
      head.next.next = head; // Make next node point back to current
      head.next = null;      // Remove old forward link
      return newHead;
  }
  ```
  Elegant but uses O(n) stack space for the recursive calls. For n &gt; ~5000, prefer iterative.
  </Tab>
</Tabs>

<PresetCard type="trap">
**Exam trap:** After reversing, the original `head` becomes the **tail** (its `next` must be set to null). Forgetting this creates a cycle at the end of the reversed list.
</PresetCard>

## 5. Generic Node — Correct Java Implementation

```java
// Correct: Generic node that works for any type
public class Node<T> {
    T data;
    Node<T> next;

    public Node(T data) {
        this.data = data;
        this.next = null;
    }
}

// Usage
Node<Integer> intNode = new Node<>(42);
Node<String> strNode = new Node<>("hello");
```

<Callout type="warn" title="Hardcoding data type to int is a toy implementation">
If your linked list only works with `int`, it cannot be used as a foundation for a generic stack, queue, or any real application. Always use generics — consistent with what you learned in Chapter 1.
</Callout>

# Java Collections Framework (JCF)

The JCF is Java's unified architecture for storing and manipulating groups of objects. Choosing the wrong collection type is one of the most common causes of subtle performance bugs.

<PresetCard type="exam">
**Exam Focus:** You must know which collection to pick for a given scenario AND justify it with complexity. "I used ArrayList" is a failing answer. "I used ArrayList because index-based access is O(1) and the data is not frequently inserted/deleted in the middle" is a passing answer.
</PresetCard>

## Part 2: Lists — Ordered Collections

### What is a List?

A `List` is an **ordered**, **indexed** collection that allows duplicate elements.

### ArrayList vs LinkedList

<Columns>
  <Column>
  ### ArrayList
  Backed by a resizable array. Excellent for random access, poor for mid-list insertion.

  ```java
  List<String> list = new ArrayList<>();
  list.add("Alice");
  list.add("Bob");
  String first = list.get(0); // O(1)
  list.add(0, "Zara");       // O(n) — shifts all elements
  ```

  **When to use:** You read/access by index more than you insert or delete.
  </Column>
  <Column>
  ### LinkedList
  Backed by a doubly linked list. Excellent for head/tail operations, poor for random access.

  ```java
  Deque<String> deque = new LinkedList<>();
  deque.addFirst("Alice"); // O(1)
  deque.addLast("Bob");    // O(1)
  deque.get(0);            // O(n) — must traverse
  ```

  **When to use:** You frequently insert/delete at the front or back (queue/deque use cases).
  </Column>
</Columns>

<HighlightCard variant="warning" title="ArrayList vs LinkedList  --  The Common Trap">

A LinkedList is NOT faster for all insertions. For inserting at a **known index in the middle**, ArrayList is faster in practice because:
1. ArrayList's `System.arraycopy()` is highly CPU-cache-friendly.
2. LinkedList must traverse O(n) nodes to reach the insertion point before the O(1) pointer update.

**Rule:** Use LinkedList only when you already hold a reference to the node (e.g., as a Deque from both ends).
</HighlightCard>

## Part 3: Maps — Key-Value Storage

### HashMap

The most commonly used map. Stores key-value pairs with O(1) average get/put.

```java
Map<String, Integer> wordCount = new HashMap<>();
wordCount.put("hello", 1);
wordCount.put("world", 2);

// getOrDefault — safe access without null check
int count = wordCount.getOrDefault("hello", 0); // 1

// Iterate entries
for (Map.Entry<String, Integer> entry : wordCount.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}
```

### TreeMap — Sorted Keys

```java
Map<String, Integer> sorted = new TreeMap<>();
sorted.put("banana", 2);
sorted.put("apple", 1);
sorted.put("cherry", 3);
// Iteration is always alphabetical: apple, banana, cherry
```

### The equals() + hashCode() Contract

<Callout type="warn" title="Critical Rule: Override Both or Neither">
If you use a custom object as a HashMap key, you **must** override both `equals()` and `hashCode()`. Overriding only `equals()` means two logically equal objects hash to different buckets — `get()` returns null even though the key was inserted.
</Callout>

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Student)) return false;
    Student s = (Student) o;
    return this.id == s.id;
}

@Override
public int hashCode() {
    return Integer.hashCode(this.id); // Must be consistent with equals
}
```

## Part 4: Sets — Unique Elements

```java
Set<String> visited = new HashSet<>();
visited.add("London");
visited.add("Paris");
visited.add("London"); // Ignored — already present

boolean been = visited.contains("Paris"); // O(1) — true
```

**TreeSet** keeps elements in natural sorted order (or by a provided `Comparator`):

```java
Set<Integer> sorted = new TreeSet<>();
sorted.add(5); sorted.add(1); sorted.add(3);
// Iteration: 1, 3, 5
```

## Part 5: Queue & PriorityQueue

### Standard Queue (FIFO)

```java
Queue<String> queue = new LinkedList<>();
queue.offer("First");  // enqueue
queue.offer("Second");
String head = queue.poll(); // dequeue — returns "First"
String peek = queue.peek(); // look without removing
```

### PriorityQueue — Always Access Min (or Max)

```java
// Min-heap (default): smallest element always at head
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.offer(5);
minHeap.offer(1);
minHeap.offer(3);
System.out.println(minHeap.poll()); // 1 — always the minimum

// Max-heap: use Comparator.reverseOrder()
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
```

### Custom Comparator for Complex Objects

```java
PriorityQueue<Patient> triage = new PriorityQueue<>(
    Comparator.comparingInt(Patient::getTriageScore).reversed()
              .thenComparingLong(Patient::getArrivalTime)
);
```

## Part 6: The Deque — Your Stack and Queue in One

<HighlightCard variant="neutral" title="Prefer ArrayDeque over Stack and LinkedList">

`java.util.Stack` extends `Vector` and is a legacy class — avoid it. `ArrayDeque` is the idiomatic replacement for both stacks and queues:

```java
// As a Stack (LIFO)
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);     // addFirst
stack.push(2);
int top = stack.pop();  // removeFirst — returns 2

// As a Queue (FIFO)
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);    // addLast
queue.offer(2);
int front = queue.poll(); // removeFirst — returns 1
```
</HighlightCard>

## Part 7: Comparable vs Comparator

Use `Comparable` when there is one natural ordering for a class. Use `Comparator` for alternate or context-specific orderings.

```java
// Comparable: the class defines its own natural order
public class Student implements Comparable<Student> {
    private int gpa;
    @Override
    public int compareTo(Student other) {
        return Double.compare(this.gpa, other.gpa); // ascending GPA
    }
}

// Comparator: external, flexible ordering
Comparator<Student> byName = Comparator.comparing(Student::getName);
Comparator<Student> byGpaDesc = Comparator.comparingDouble(Student::getGpa).reversed();

// Chain multiple criteria
Comparator<Student> combined = byGpaDesc.thenComparing(byName);
List<Student> roster = new ArrayList<>(students);
Collections.sort(roster, combined);
```

<PresetCard type="trap">
`Collections.sort()` requires `Comparable` or a `Comparator`. It sorts **in-place** and modifies the list. If you need a sorted copy, use `list.stream().sorted(comparator).collect(Collectors.toList())`.
</PresetCard>

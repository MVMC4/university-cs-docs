# Java Generics & Type Erasure

Generics provide compile-time type safety, eliminating the need for explicit casting and preventing `ClassCastException` at runtime.

---

## 1. Why Generics?

**Without Generics** (Unsafe):
```java
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0); // Risky cast!
```

**With Generics** (Safe):
```java
List<String> list = new ArrayList<>();
list.add("Hello");
String s = list.get(0); // No cast needed!
```

## 2. Generic Classes & Methods

```java
public class Box<T> {
    private T item;

    public void setItem(T item) {
        this.item = item;
    }

    public T getItem() {
        return item;
    }
}

Box<Integer> intBox = new Box<>();
intBox.setItem(10);
```

---

## 3. Bounded Type Parameters

You can restrict the types that can be passed as generic parameters.

```java
// T must extend Number (or be Number itself)
public <T extends Number> void printValue(T num) {
    System.out.println(num.doubleValue());
}
```

---

## 4. Wildcards & PECS (Producer Extends, Consumer Super)

Wildcards (`?`) allow methods to accept a broader range of generic types.

1. **`? extends T`** (Upper Bound): Read-only. The collection is a **Producer**.
2. **`? super T`** (Lower Bound): Write-only. The collection is a **Consumer**.
3. **`?`** (Unbounded): Any type.

<HighlightCard variant="neutral" title="The PECS Principle in Action">

```java
// We are reading from 'src' (Producer) and writing to 'dest' (Consumer)
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (T item : src) {
        dest.add(item);
    }
}
```
If we used `List<? extends T>` for `dest`, the compiler would block the `add()` operation because it cannot guarantee the exact subtype of the list.
</HighlightCard>

## 5. Type Erasure & The Array Restriction

To maintain backward compatibility with pre-Java 5 code, the JVM implements generics via **type erasure**. The compiler removes all type parameters, replacing them with their bounds or `Object`.

<Callout type="warn" title="The Generic Array Restriction">
You **cannot** instantiate a generic array in Java (e.g., `new T[10]` is illegal). 

**Why?** Arrays in Java are **reified** (they know their component type at runtime and enforce it via `ArrayStoreException`). Generics are **erased** (they do not exist at runtime). If `new T[]` were allowed, the JVM would not know the actual runtime type to enforce array safety.

**The Standard Workaround:**
When implementing data structures like `ArrayList` or `HashMap` from scratch, you must create an `Object` array and cast it, suppressing the unchecked warning.

```java
@SuppressWarnings("unchecked")
T[] elements = (T[]) new Object[capacity];
```
</Callout>

---

## Summary

- **Generics**: Enforce type safety at compile time.
- **Bounded Types**: Restrict generics to specific hierarchies (`<T extends Number>`).
- **PECS**: Use `? extends T` for reading (Producers) and `? super T` for writing (Consumers).
- **Type Erasure**: Generics are a compile-time illusion; at runtime, they revert to `Object` or their bound.

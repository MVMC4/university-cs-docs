## 3.2 Sorting Algorithms & Stability

While asymptotic analysis and recurrences tell us the theoretical limits of sorting, we must also master the concrete implementations, step-by-step execution traces, and the critical property of **stability**.

<HighlightCard
  variant="neutral"
  title="Definition 3.2.1: Algorithmic Stability"
  description="A sorting algorithm is 'stable' if it preserves the relative order of equal elements."
>

- **Stable:** Insertion Sort, Merge Sort.
- **Unstable:** Quick Sort, Heap Sort, Selection Sort.

**Why This Matters for Data Structures:**
Stability is crucial when sorting by multiple keys. For example, if you sort a list of students by GPA, and then sort the result by Name using a *stable* sort, the students with the same name will remain sorted by GPA. If the second sort is unstable, the GPA ordering is destroyed.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Algorithm 1: Insertion Sort & Best-Case Analysis</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static void insertionSort(int[] A) {
        for (int i = 1; i < A.length; i++) {
            int key = A[i];
            int j = i - 1;
            // Shift elements greater than key to the right
            while (j >= 0 && A[j] > key) {
                A[j + 1] = A[j];
                j--;
            }
            A[j + 1] = key;
        }
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Step-by-Step Trace</StepTitle>
    Initial: `[5, 2, 4, 6, 1, 3]`
    - `i=1, key=2`: `A[0]=5 > 2`. Shift 5. Insert 2. -> `[2, 5, 4, 6, 1, 3]`
    - `i=2, key=4`: `A[1]=5 > 4`. Shift 5. Insert 4. -> `[2, 4, 5, 6, 1, 3]`
    - `i=3, key=6`: `A[2]=5 < 6`. No shift. -> `[2, 4, 5, 6, 1, 3]`
    - `i=4, key=1`: Shift 6, 5, 4, 2. Insert 1. -> `[1, 2, 4, 5, 6, 3]`
    - `i=5, key=3`: Shift 6, 5, 4. Insert 3. -> `[1, 2, 3, 4, 5, 6]`
  </Step>

  <Step number={3}>
    <StepTitle>Best-Case Analysis (Nearly Sorted)</StepTitle>
    If the array is already sorted (or nearly sorted), the `while` loop condition `A[j] > key` is immediately false. The inner loop executes 0 times.
    Total comparisons = $n-1$. Total shifts = 0.
    **Best-Case Time Complexity:** $\Theta(n)$. This makes Insertion Sort the fastest algorithm for *nearly sorted* data.
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Algorithm 2: Merge Sort & Merge Trace</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static void mergeSort(int[] A, int left, int right) {
        if (left < right) {
            int mid = left + (right - left) / 2;
            mergeSort(A, left, mid);
            mergeSort(A, mid + 1, right);
            merge(A, left, mid, right);
        }
    }

    private static void merge(int[] A, int left, int mid, int right) {
        int n1 = mid - left + 1;
        int n2 = right - mid;
        int[] L = new int[n1];
        int[] R = new int[n2];

        System.arraycopy(A, left, L, 0, n1);
        System.arraycopy(A, mid + 1, R, 0, n2);

        int i = 0, j = 0, k = left;
        while (i < n1 && j < n2) {
            if (L[i] <= R[j]) { // <= ensures stability!
                A[k++] = L[i++];
            } else {
                A[k++] = R[j++];
            }
        }
        while (i < n1) A[k++] = L[i++];
        while (j < n2) A[k++] = R[j++];
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Step-by-Step Merge Trace</StepTitle>
    Suppose we are merging two sorted halves: `L = [2, 4, 5]` and `R = [1, 3, 6]`.
    - `i=0, j=0`: `L[0]=2`, `R[0]=1`. `2 <= 1` is False. `A[0] = 1`, `j=1`.
    - `i=0, j=1`: `L[0]=2`, `R[1]=3`. `2 <= 3` is True. `A[1] = 2`, `i=1`.
    - `i=1, j=1`: `L[1]=4`, `R[1]=3`. `4 <= 3` is False. `A[2] = 3`, `j=2`.
    - `i=1, j=2`: `L[1]=4`, `R[2]=6`. `4 <= 6` is True. `A[3] = 4`, `i=2`.
    - `i=2, j=2`: `L[2]=5`, `R[2]=6`. `5 <= 6` is True. `A[4] = 5`, `i=3`.
    - Left array exhausted. Copy remaining `R`: `A[5] = 6`.
    Result: `[1, 2, 3, 4, 5, 6]`.
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Algorithm 3: Quick Sort (Lomuto Partition) & Partition Trace</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static void quickSort(int[] A, int low, int high) {
        if (low < high) {
            int pivotIndex = partition(A, low, high);
            quickSort(A, low, pivotIndex - 1);
            quickSort(A, pivotIndex + 1, high);
        }
    }

    private static int partition(int[] A, int low, int high) {
        int pivot = A[high]; // Choose last element as pivot
        int i = low - 1;     // Index of smaller element

        for (int j = low; j < high; j++) {
            if (A[j] <= pivot) {
                i++;
                // Swap A[i] and A[j]
                int temp = A[i]; A[i] = A[j]; A[j] = temp;
            }
        }
        // Swap A[i+1] and A[high] (pivot)
        int temp = A[i + 1]; A[i + 1] = A[high]; A[high] = temp;
        return i + 1;
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Step-by-Step Partition Trace</StepTitle>
    Initial: `[8, 3, 1, 7, 0, 5]`. Pivot = `5` (last element). `i = -1`.
    - `j=0, A[0]=8`: `8 <= 5` False.
    - `j=1, A[1]=3`: `3 <= 5` True. `i=0`. Swap `A[0]` and `A[1]`. -> `[3, 8, 1, 7, 0, 5]`
    - `j=2, A[2]=1`: `1 <= 5` True. `i=1`. Swap `A[1]` and `A[2]`. -> `[3, 1, 8, 7, 0, 5]`
    - `j=3, A[3]=7`: `7 <= 5` False.
    - `j=4, A[4]=0`: `0 <= 5` True. `i=2`. Swap `A[2]` and `A[4]`. -> `[3, 1, 0, 7, 8, 5]`
    - Loop ends. Swap pivot `A[5]` with `A[i+1]` (`A[3]`). -> `[3, 1, 0, 5, 8, 7]`
    Pivot `5` is now at index 3. Left side `[3, 1, 0]` are all $\le 5$. Right side `[8, 7]` are all $> 5$.
  </Step>
</StepByStep>

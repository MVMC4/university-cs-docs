## 3.1 Recursion Mechanics & Structural Induction

Recursion is not merely a coding technique; it is a mathematical concept grounded in the mechanics of the call stack and provable via structural induction.

<HighlightCard
  variant="neutral"
  title="Definition 3.1.1: The Call Stack & Activation Records"
  description="Each recursive call creates an activation record (stack frame) on the call stack."
>

An activation record contains:
1. Return address (where to resume execution).
2. Parameters and local variables.
3. Control link (pointer to the caller's activation record).

The space complexity of a recursive algorithm is $O(h)$, where $h$ is the maximum depth of the recursion tree (height of the call stack).

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definition 3.1.2: Tail Recursion"
  description="A recursive call is 'tail-recursive' if it is the very last operation performed in the function, with no pending operations upon return."
>

**Compiler Optimization**: Languages with Tail Call Optimization (TCO) can reuse the current activation record for the tail call, reducing space complexity from $O(h)$ to $O(1)$.
*Note: The Java Virtual Machine (JVM) does **not** guarantee TCO, so tail-recursive Java methods still consume $O(h)$ stack space and risk `StackOverflowError`.*

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Proof Technique: Structural Induction</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Framework</StepTitle>

    To prove a property $P(x)$ holds for all recursively defined data structures (e.g., linked lists, trees):
    1. **Base Case:** Prove $P$ holds for the simplest structure (e.g., a `null` reference or a single `Leaf` node).
    2. **Inductive Hypothesis (IH):** Assume $P$ holds for all proper sub-structures (e.g., the `left` and `right` subtrees).
    3. **Inductive Step:** Prove $P$ holds for the constructed structure (e.g., a `Node` combining the subtrees) using the IH.
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Mandatory Proof: Full Binary Tree Leaf Property</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Theorem</StepTitle>

    In a full binary tree (where every node has either 0 or 2 children), the number of leaf nodes $L$ is exactly one more than the number of internal nodes $I$ (i.e., $L = I + 1$).
  </Step>

  <Step number={2}>
    <StepTitle>Base Case</StepTitle>

    Consider a tree consisting of only a single root node. It has $L = 1$ leaf and $I = 0$ internal nodes.
    The equation holds: $1 = 0 + 1$. $\blacksquare$
  </Step>

  <Step number={3}>
    <StepTitle>Inductive Hypothesis</StepTitle>

    Assume the property holds for all full binary trees with fewer than $k$ internal nodes. That is, for any such subtree $T$, $L_T = I_T + 1$.
  </Step>

  <Step number={4}>
    <StepTitle>Inductive Step</StepTitle>

    Consider a full binary tree $T$ with $k$ internal nodes ($k > 0$). Since $k > 0$, the root must have exactly two children, which are the roots of two full binary subtrees, $T_1$ and $T_2$.
    Let $T_1$ have $I_1$ internal nodes and $L_1$ leaves.
    Let $T_2$ have $I_2$ internal nodes and $L_2$ leaves.
    By the IH, $L_1 = I_1 + 1$ and $L_2 = I_2 + 1$.
    
    The total number of internal nodes in $T$ is $I = I_1 + I_2 + 1$ (the $+1$ accounts for the root of $T$).
    The total number of leaves in $T$ is $L = L_1 + L_2$ (the root of $T$ is an internal node, not a leaf).
    
    Substituting the IH into the equation for $L$:
    $L = (I_1 + 1) + (I_2 + 1) = I_1 + I_2 + 2$.
    
    Since $I = I_1 + I_2 + 1$, we know $I_1 + I_2 = I - 1$.
    Substitute this back:
    $L = (I - 1) + 2 = I + 1$. $\blacksquare$
  </Step>
</StepByStep>

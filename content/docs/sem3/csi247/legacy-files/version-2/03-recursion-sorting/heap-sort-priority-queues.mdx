## 3.3 Heap Sort: Bridging Sorting & Priority Queues

Heap Sort is not merely a standalone sorting algorithm; it is the direct application of the **Priority Queue (Max-Heap)** data structure to the sorting problem. It bridges the gap between abstract data structures and concrete algorithmic efficiency.

<HighlightCard
  variant="neutral"
  title="Definition 3.3.1: The Heap Sort Algorithm"
  description="Heap Sort operates in two distinct phases: building the heap, and repeatedly extracting the maximum."
>

1. **Phase 1: Build Max-Heap**
   Treat the unsorted array as a complete binary tree. Use Floyd's Bottom-Up Heapify to convert it into a valid Max-Heap in $O(n)$ time.
2. **Phase 2: Extract and Sort**
   The maximum element is always at the root ($A[0]$). Swap it with the last element of the heap ($A[n-1]$). Reduce the heap size by 1, and call `siftDown` on the new root to restore the Max-Heap property. Repeat $n-1$ times.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: The `siftDown` Operation"
  description="The exact code required to restore the Max-Heap property during Phase 2. Students must be able to write this from memory."
>

```java
// The core operation of Phase 2: Restoring the Max-Heap property
private static <T extends Comparable<T>> void siftDown(T[] arr, int i, int heapSize) {
    int max = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    // Check if left child exists and is greater than the current max
    if (left < heapSize && arr[left].compareTo(arr[max]) > 0) {
        max = left;
    }
    
    // Check if right child exists and is greater than the current max
    if (right < heapSize && arr[right].compareTo(arr[max]) > 0) {
        max = right;
    }

    // If the largest element is not the root, swap and continue sifting down
    if (max != i) {
        T temp = arr[i];
        arr[i] = arr[max];
        arr[max] = temp;
        
        // Recursively sift down the affected subtree
        siftDown(arr, max, heapSize);
    }
}
```
**Crucial Details:**
- `heapSize`: We must pass the current logical size of the heap, not `arr.length`, because Phase 2 progressively shrinks the heap as elements are moved to the sorted portion at the end of the array.
- `Comparable<T>`: The generic type must be constrained to `Comparable` so we can use `compareTo()` to determine the largest element.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Complexity Analysis of Heap Sort</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Phase 1 Cost</StepTitle>
    Building the Max-Heap using Floyd's algorithm takes exactly $O(n)$ time.
  </Step>

  <Step number={2}>
    <StepTitle>Phase 2 Cost</StepTitle>
    We perform $n-1$ extractions. Each extraction involves a swap ($O(1)$) and a `siftDown` operation. The height of the heap is $\log_2 n$, so each `siftDown` takes $O(\log n)$ time.
    Total cost for Phase 2: $(n-1) \times O(\log n) = O(n \log n)$.
  </Step>

  <Step number={3}>
    <StepTitle>Total Time Complexity</StepTitle>
    $T(n) = O(n) + O(n \log n) = O(n \log n)$.
    Crucially, this is the **worst-case** complexity, unlike Quick Sort.
  </Step>

  <Step number={4}>
    <StepTitle>Space Complexity</StepTitle>
    Heap Sort operates directly on the input array. It requires no auxiliary arrays (unlike Merge Sort). Thus, its auxiliary space complexity is strictly $O(1)$ (in-place).
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="The Bridge: Sorting as Priority Queue Extraction"
  description="Heap Sort proves that sorting is mathematically equivalent to inserting all elements into a Priority Queue and extracting them in order."
>

If we use a standard Priority Queue (Max-Heap) to sort an array:
1. Insert all $n$ elements: $n \times O(\log n) = O(n \log n)$.
2. Extract the maximum $n$ times: $n \times O(\log n) = O(n \log n)$.
Total time: $O(n \log n)$.

**Optimization:** Heap Sort optimizes the insertion phase by using Floyd's $O(n)$ bottom-up heapify instead of $n$ individual $O(\log n)$ insertions. Furthermore, it reuses the vacated space at the end of the array to store the extracted maximums, achieving $O(1)$ auxiliary space.

</HighlightCard>

<Card>

### Definition 3.3.2: Heap Sort vs. Merge Sort vs. Quick Sort

- **Merge Sort:** Guaranteed $O(n \log n)$, but requires $O(n)$ auxiliary space. Stable.
- **Quick Sort:** Average $O(n \log n)$, worst-case $O(n^2)$. In-place ($O(\log n)$ stack space). Unstable. Excellent cache locality.
- **Heap Sort:** Guaranteed $O(n \log n)$ worst-case. In-place ($O(1)$ space). Unstable. Poor cache locality due to scattered memory accesses during `siftDown`.

</Card>

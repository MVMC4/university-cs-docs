## 1.5 Searching Algorithms & Loop Invariants

Before we can sort or traverse complex structures, we must master the fundamental act of searching. Furthermore, to prove that our search algorithms are correct, we use **Loop Invariants**, a formal mathematical technique similar to induction.

<Card>

### A Brief Note on Computational Complexity (P vs. NP)
While this course focuses on algorithm design and analysis, it is worth noting that determining the absolute lower bounds for many problems falls under Computational Complexity Theory. The famous **P vs. NP** problem asks whether every problem whose solution can be quickly verified (NP) can also be quickly solved (P). For practical data structures, we assume P $\neq$ NP, meaning that for NP-Complete problems (like the Traveling Salesperson Problem), we must rely on heuristics or approximation algorithms, as no $O(n^k)$ exact algorithm is known to exist.

</Card>

<HighlightCard
  variant="neutral"
  title="Definition 1.5.1: Loop Invariants"
  description="A formal method to prove the correctness of iterative algorithms. An invariant is a condition that holds true before the loop, after every iteration, and upon termination."
>

To prove a loop invariant, we must show three properties:
1. **Initialization:** The invariant is true before the first iteration.
2. **Maintenance:** If the invariant is true before an iteration, it remains true before the next iteration.
3. **Termination:** When the loop terminates, the invariant, combined with the termination condition, gives a useful property that proves the algorithm is correct.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Algorithm 1: Linear Search & Loop Invariant Proof</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static int linearSearch(int[] A, int key) {
        for (int i = 0; i < A.length; i++) {
            if (A[i] == key) {
                return i; // Found
            }
        }
        return -1; // Not found
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>The Loop Invariant</StepTitle>
    "At the start of each iteration of the `for` loop (for index `i`), the subarray `A[0..i-1]` does not contain the `key`."
  </Step>

  <Step number={3}>
    <StepTitle>Proof of Correctness</StepTitle>
    - **Initialization:** Before the first iteration, `i = 0`. The subarray `A[0..-1]` is empty, so it trivially does not contain `key`.
    - **Maintenance:** Assume `A[0..i-1]` does not contain `key`. In the current iteration, we check `A[i]`. If `A[i] == key`, the loop terminates (returns `i`). If `A[i] != key`, then `A[0..i]` does not contain `key`. We increment `i`, so for the next iteration, `A[0..i-1]` (which is the old `A[0..i]`) does not contain `key`.
    - **Termination:** The loop terminates in two ways:
      1. `A[i] == key`: We return `i`, which is correct.
      2. `i == A.length`: The loop terminates. By the invariant, `A[0..n-1]` does not contain `key`. We return `-1`, which is correct. $\blacksquare$
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Algorithm 2: Binary Search & Loop Invariant Proof</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static int binarySearch(int[] A, int key) {
        int low = 0;
        int high = A.length - 1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2; // Prevents integer overflow
            
            if (A[mid] == key) {
                return mid;
            } else if (A[mid] < key) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return -1;
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>The Loop Invariant</StepTitle>
    "If the `key` exists in the sorted array `A`, it must be located within the subarray `A[low..high]`."
  </Step>

  <Step number={3}>
    <StepTitle>Proof of Correctness</StepTitle>
    - **Initialization:** Before the first iteration, `low = 0` and `high = n - 1`. The subarray `A[0..n-1]` is the entire array. If `key` exists, it is trivially in this range.
    - **Maintenance:** Assume the invariant holds: if `key` exists, it is in `A[low..high]`. We calculate `mid`.
      - If `A[mid] == key`, we return `mid` (correct).
      - If `A[mid] < key`, because `A` is sorted, `key` cannot be in `A[low..mid]`. We set `low = mid + 1`. The new search space `A[mid+1..high]` still contains `key` if it exists.
      - If `A[mid] > key`, because `A` is sorted, `key` cannot be in `A[mid..high]`. We set `high = mid - 1`. The new search space `A[low..mid-1]` still contains `key` if it exists.
      In all cases, the invariant is maintained.
    - **Termination:** The loop terminates when `low > high`. The subarray `A[low..high]` is empty. By the invariant, if `key` exists, it must be in this empty subarray, which is impossible. Therefore, `key` does not exist in `A`, and we correctly return `-1`. $\blacksquare$
  </Step>
</StepByStep>

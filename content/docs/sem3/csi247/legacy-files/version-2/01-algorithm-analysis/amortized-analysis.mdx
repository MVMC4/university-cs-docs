## 1.4 Amortized Analysis & ArrayList Worst-Case

Amortized analysis guarantees the *average* performance of each operation in the worst case, over a sequence of operations. This is crucial for understanding dynamic arrays (`ArrayList`).

<HighlightCard
  variant="neutral"
  title="Definition 1.4.1: The Aggregate Method"
  description="Prove that a sequence of $n$ operations takes worst-case time $T(n)$. The amortized cost per operation is $T(n)/n$."
>

If $n$ operations take $O(n)$ total time, the amortized cost per operation is $O(n)/n = O(1)$.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Crucial Exam Proof: ArrayList Dynamic Resizing (Aggregate Method)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Scenario</StepTitle>

    An `ArrayList` starts with capacity 1. Insertion costs 1. If the array is full, it allocates a new array of double the size and copies all elements. Prove $N$ insertions take $O(N)$ total time.
  </Step>

  <Step number={2}>
    <StepTitle>Identify Expansion Points</StepTitle>

    Expansions occur at insertions $i = 1, 2, 4, 8, 16, \dots, 2^k$ where $2^k \le N$.
  </Step>

  <Step number={3}>
    <StepTitle>Count the Copying Loop</StepTitle>

    When the array resizes to capacity $C$, the `System.arraycopy` loop runs $C$ times.
    The total copying cost over $N$ insertions is bounded by the geometric series:
    $$1 + 2 + 4 + 8 + \dots + 2^{\lfloor \log_2 N \rfloor} = \sum_{j=0}^{\lfloor \log_2 N \rfloor} 2^j$$
  </Step>

  <Step number={4}>
    <StepTitle>Apply Geometric Series Formula</StepTitle>

    The sum is $2^{\lfloor \log_2 N \rfloor + 1} - 1 < 2N$.
  </Step>

  <Step number={5}>
    <StepTitle>Calculate Total Time and Amortized Cost</StepTitle>

    Total time $T(N) \le N$ (for basic insertions) $+ 2N$ (for copying loops) $= 3N = O(N)$.
    Amortized cost per insertion $= T(N)/N = 3N/N = O(1)$. $\blacksquare$
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="Definition 1.4.2: The Potential Method"
  description="Defines a potential function $\Phi(D_i)$ mapping the data structure state to a real number. The amortized cost is $\hat{a}_i = a_i + \Phi(D_i) - \Phi(D_{i-1})$."
>

If we can define $\Phi$ such that $\Phi(D_i) \ge \Phi(D_0)$ for all $i$, then the sum of amortized costs bounds the sum of actual costs.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Crucial Exam Proof: ArrayList Dynamic Resizing (Potential Method)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Define the Potential Function</StepTitle>

    Let $\Phi(D_i)$ be the potential of the data structure after $i$ operations. 
    We define $\Phi(D_i) = 2s_i - c_i$, where $s_i$ is the number of elements (size) and $c_i$ is the current capacity.
    Note that for all $i > 0$, the array is at least half full, so $c_i \le 2s_i$, meaning $\Phi(D_i) \ge 0$.
  </Step>

  <Step number={2}>
    <StepTitle>Case 1: Normal Insert (No Resize)</StepTitle>

    Actual cost $a_i = 1$. The size increases by 1 ($s_i = s_{i-1} + 1$), and capacity is unchanged ($c_i = c_{i-1}$).
    Calculate the change in potential:
    $\Delta\Phi = \Phi(D_i) - \Phi(D_{i-1}) = (2s_i - c_i) - (2s_{i-1} - c_{i-1})$
    $\Delta\Phi = 2(s_{i-1} + 1) - c_{i-1} - 2s_{i-1} + c_{i-1} = 2$.
    Amortized cost $\hat{a}_i = a_i + \Delta\Phi = 1 + 2 = 3$.
  </Step>

  <Step number={3}>
    <StepTitle>Case 2: Insert with Resize</StepTitle>

    Actual cost $a_i = s_{i-1} + 1$ (copy $s_{i-1}$ elements + 1 new element). 
    Because it resized, the array was full: $s_{i-1} = c_{i-1}$. The new capacity is $c_i = 2c_{i-1}$.
    Calculate the change in potential:
    $\Delta\Phi = (2s_i - c_i) - (2s_{i-1} - c_{i-1})$
    $\Delta\Phi = 2(s_{i-1} + 1) - 2c_{i-1} - 2s_{i-1} + c_{i-1} = 2 - c_{i-1}$.
    Amortized cost $\hat{a}_i = a_i + \Delta\Phi = (s_{i-1} + 1) + (2 - c_{i-1})$.
    Since $s_{i-1} = c_{i-1}$, this simplifies to:
    $\hat{a}_i = (c_{i-1} + 1) + 2 - c_{i-1} = 3$.
  </Step>

  <Step number={4}>
    <StepTitle>Conclusion</StepTitle>

    In both cases, the amortized cost $\hat{a}_i$ is strictly bounded by the constant 3. 
    Since $\Phi(D_i) \ge \Phi(D_0)$, the sum of amortized costs bounds the sum of actual costs. 
    Therefore, the amortized complexity of insertion is $O(1)$. $\blacksquare$
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="Worst-Case Analysis: ArrayList.remove(int index)"
  description="Why removal is $O(n)$ worst-case, despite $O(1)$ amortized insertion."
>

Unlike appending to the end, removing an element from the middle of an `ArrayList` requires shifting all subsequent elements to the left to fill the gap.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Analysis: ArrayList Shifting Loop</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>

    ```java
    // Inside remove(int index)
    int numMoved = size - index - 1;
    if (numMoved > 0) {
        System.arraycopy(elementData, index + 1, elementData, index, numMoved);
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>Loop Counting</StepTitle>

    If we remove the element at `index = 0`, the `arraycopy` loop must shift $n-1$ elements.
    The loop executes exactly $n-1$ times.
  </Step>

  <Step number={3}>
    <StepTitle>Asymptotic Bound</StepTitle>

    The worst-case number of operations is proportional to $n$. Therefore, `remove(int index)` is strictly $\Theta(n)$ worst-case.
  </Step>
</StepByStep>

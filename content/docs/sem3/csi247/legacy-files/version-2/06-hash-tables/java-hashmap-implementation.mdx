## 6.3 Java HashMap Implementation & The Contract

While the mathematics of collision resolution is fundamental, the practical implementation of a Hash Table in Java hinges entirely on the `hashCode()` and `equals()` contract. Violating this contract is the #1 source of bugs when using custom objects as keys.

<HighlightCard
  variant="neutral"
  title="The Golden Rule: The hashCode/equals Contract"
  description="The absolute mathematical and logical requirements for using objects as HashMap keys."
>

1. **Consistency:** If `a.equals(b)` is `true`, then `a.hashCode() == b.hashCode()` **MUST** be `true`.
2. **Collision Tolerance:** If `a.equals(b)` is `false`, their hash codes **CAN** be equal (this is just a collision), but it degrades performance to $O(n)$.
3. **Stability:** An object's `hashCode()` must remain constant throughout its lifetime in the map.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Right vs. Wrong Implementations</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Wrong Way: Overriding equals() but not hashCode()</StepTitle>
    ```java
    public class Student {
        String id;
        // ...
        @Override
        public boolean equals(Object o) {
            return this.id.equals(((Student)o).id);
        }
        // MISSING hashCode()!
        // Inherits Object.hashCode() which returns unique memory addresses.
        // Two equal Students will have different hash codes -> Map fails to find the key!
    }
    ```
  </Step>

  <Step number={2}>
    <StepTitle>The Wrong Way: Returning a Constant hashCode()</StepTitle>
    ```java
    @Override
    public int hashCode() { return 1; }
    ```
    This is technically valid (satisfies the contract), but forces every single object into bucket 1. The HashMap degenerates into a single linked list, making all operations $O(n)$.
  </Step>

  <Step number={3}>
    <StepTitle>The Right Way: Using java.util.Objects</StepTitle>
    ```java
    public class Student {
        String id;
        String name;

        @Override
        public boolean equals(Object o) {
            if (this == o) return true;
            if (o == null || getClass() != o.getClass()) return false;
            Student student = (Student) o;
            return Objects.equals(id, student.id) &&
                   Objects.equals(name, student.name);
        }

        @Override
        public int hashCode() {
            return Objects.hash(id, name);
        }
    }
    ```
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="The Danger of Mutable Keys"
  description="Why you must NEVER use a mutable object (or an object whose hash-dependent fields can change) as a HashMap key."
>

If you insert a key into a HashMap, the map calculates its `hashCode()` and places it in a specific bucket.
If you later **mutate** the key's state such that its `hashCode()` changes, the object is now sitting in the **wrong bucket**.
When you call `map.get(key)`, it will calculate the *new* hash code, look in the *new* bucket, and return `null`, effectively losing the entry forever.

**Rule:** Always use immutable objects (like `String`, `Integer`, or records) as HashMap keys.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: SeparateChainingHashMap<K, V>"
  description="A bulletproof, production-ready implementation showing the Node class, bucket array, and collision resolution via linked lists."
>

```java
import java.util.Objects;

public class SeparateChainingHashMap<K, V> {
    private static final int DEFAULT_CAPACITY = 16;
    private static final double LOAD_FACTOR_THRESHOLD = 0.75;

    // Static nested class for the linked list nodes
    private static class Node<K, V> {
        final K key; // Key is final to prevent mutation!
        V value;
        Node<K, V> next;

        Node(K key, V value, Node<K, V> next) {
            this.key = key;
            this.value = value;
            this.next = next;
        }
    }

    private Node<K, V>[] table;
    private int size;

    // CRITICAL FIX: Generic array creation workaround
    @SuppressWarnings("unchecked")
    public SeparateChainingHashMap(int capacity) {
        table = (Node<K, V>[]) new Node[capacity];
        size = 0;
    }

    public SeparateChainingHashMap() {
        this(DEFAULT_CAPACITY);
    }

    private int bucketIndex(K key) {
        if (key == null) return 0;
        // BULLETPROOF FIX: Math.abs(Integer.MIN_VALUE) is negative!
        // We use bitwise AND to mask the sign bit, ensuring a positive hash.
        int hash = key.hashCode();
        return (hash & 0x7FFFFFFF) % table.length;
    }

    public void put(K key, V value) {
        if ((double) size / table.length >= LOAD_FACTOR_THRESHOLD) {
            resize();
        }

        int index = bucketIndex(key);
        Node<K, V> current = table[index];

        // Traverse the chain to check if key already exists
        while (current != null) {
            if (Objects.equals(current.key, key)) {
                current.value = value; // Update existing value
                return;
            }
            current = current.next;
        }

        // Key not found, insert at the head of the chain
        table[index] = new Node<>(key, value, table[index]);
        size++;
    }

    public V get(K key) {
        int index = bucketIndex(key);
        Node<K, V> current = table[index];

        while (current != null) {
            if (Objects.equals(current.key, key)) {
                return current.value;
            }
            current = current.next;
        }
        return null; // Key not found
    }

    public V remove(K key) {
        int index = bucketIndex(key);
        Node<K, V> current = table[index];
        Node<K, V> prev = null;

        while (current != null) {
            if (Objects.equals(current.key, key)) {
                // Unlink the node
                if (prev == null) {
                    table[index] = current.next; // Removing head
                } else {
                    prev.next = current.next;    // Removing middle/tail
                }
                size--; // CRITICAL: Decrement size exactly when unlinked
                return current.value;
            }
            prev = current;
            current = current.next;
        }
        return null; // Key not found, size unchanged
    }

    // CRITICAL FIX: Generic array creation workaround in resize
    @SuppressWarnings("unchecked")
    private void resize() {
        Node<K, V>[] oldTable = table;
        table = (Node<K, V>[]) new Node[oldTable.length * 2];
        size = 0; // Reset size, put() will increment it

        // Rehash all existing entries into the new table
        for (Node<K, V> head : oldTable) {
            Node<K, V> current = head;
            while (current != null) {
                put(current.key, current.value);
                current = current.next;
            }
        }
    }
}
```

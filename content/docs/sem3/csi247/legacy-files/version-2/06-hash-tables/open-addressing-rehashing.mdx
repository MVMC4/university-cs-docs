## 6.2 Open Addressing & Rehashing

In Open Addressing, all elements are stored in the array itself. When a collision occurs, we probe for the next available slot.

<HighlightCard
  variant="neutral"
  title="Definition 6.2.1: Linear Probing & Primary Clustering"
  description="Probe sequence: $(h(k) + i) \pmod m$. Suffers from Primary Clustering."
>

**Primary Clustering:** Long runs of occupied slots build up. New keys are more likely to fall into these clusters, making them grow even faster. This degrades performance to $O(n)$ even at moderate load factors.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definition 6.2.2: Quadratic Probing & Secondary Clustering"
  description="Probe sequence: $(h(k) + c_1 i + c_2 i^2) \pmod m$. Reduces primary clustering but suffers from secondary clustering."
>

**Secondary Clustering:** Keys that hash to the same initial index will follow the exact same probe sequence, creating clusters.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Theorem: Quadratic Probing Guarantee</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Theorem</StepTitle>
    Quadratic probing is guaranteed to find an empty slot if the load factor $\lambda < 0.5$ and the table size $m$ is a prime number.
  </Step>

  <Step number={2}>
    <StepTitle>Why $m$ Must Be Prime</StepTitle>
    If $m$ is not prime, the sequence $(h(k) + i^2) \pmod m$ may enter a cycle and fail to probe all slots, even if the table is less than half full. When $m$ is prime, the first $m/2$ probes (for $i = 0$ to $m/2 - 1$) are mathematically guaranteed to generate distinct indices modulo $m$.
  </Step>

  <Step number={3}>
    <StepTitle>Proof of Empty Slot</StepTitle>
    Since $\lambda < 0.5$, the number of elements $n < m/2$.
  </Step>

  <Step number={4}>
    <StepTitle>Conclusion</StepTitle>
    By the Pigeonhole Principle, since we probe $m/2$ distinct locations and there are fewer than $m/2$ elements in the table, at least one probed location must be empty. $\blacksquare$
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="Definition 6.2.3: Double Hashing"
  description="Probe sequence: $(h_1(k) + i \cdot h_2(k)) \pmod m$. Eliminates clustering."
>

By using a second hash function $h_2(k)$ to determine the step size, the probe sequence depends on the key itself, effectively eliminating both primary and secondary clustering.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definition 6.2.4: Rehashing & Amortized Cost Proof"
  description="When $\lambda$ exceeds a threshold (e.g., 0.75), the table must be resized. The amortized cost remains $O(1)$."
>

- **Cost:** Allocating a new array (usually $2m$) and re-inserting all $n$ elements takes $O(n)$ time.
- **Amortized Cost Proof (Aggregate Method):**
  Consider $N$ insertions into a table that doubles in size. Resizes occur when the table reaches capacities $1, 2, 4, 8, \dots, N$.
  The total copy cost is the sum of the array sizes at each resize:
  $$1 + 2 + 4 + \dots + N < 2N$$
  The total time for $N$ insertions is the $N$ basic insertions plus the total copy cost:
  $$T(N) \le N + 2N = 3N = O(N)$$
  Therefore, the amortized cost per insertion is $T(N)/N = 3N/N = O(1)$.

</HighlightCard>

## 4.3 Stack ADT & Applications

The Stack is a restricted linear structure that enforces a strict Last-In, First-Out (LIFO) access pattern.

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: ArrayStack"
  description="Array-based stack with automatic resizing and generic type support."
>

```java
import java.util.NoSuchElementException;

public class ArrayStack<T> {
    private static final int DEFAULT_CAPACITY = 10;
    private Object[] elements;
    private int top;

    public ArrayStack() {
        elements = new Object[DEFAULT_CAPACITY];
        top = -1;
    }

    public void push(T item) {
        if (top == elements.length - 1) {
            resize();
        }
        elements[++top] = item;
    }

    @SuppressWarnings("unchecked")
    public T pop() {
        if (isEmpty()) {
            throw new NoSuchElementException("Stack is empty");
        }
        T item = (T) elements[top];
        elements[top] = null; // Prevent memory leak
        top--;
        return item;
    }

    @SuppressWarnings("unchecked")
    public T peek() {
        if (isEmpty()) {
            throw new NoSuchElementException("Stack is empty");
        }
        return (T) elements[top];
    }

    public boolean isEmpty() {
        return top == -1;
    }

    public int size() {
        return top + 1;
    }

    private void resize() {
        int newCapacity = elements.length * 2;
        Object[] newArray = new Object[newCapacity];
        System.arraycopy(elements, 0, newArray, 0, elements.length);
        elements = newArray;
    }
}
```

**Key Features:**
1. **Amortized O(1) push**: Resizing doubles capacity, spreading the O(n) copy cost over n insertions
2. **Memory leak prevention**: Setting `elements[top] = null` after pop allows garbage collection
3. **Generic type safety**: Uses `@SuppressWarnings("unchecked")` for the cast from Object[] to T

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: NodeStack"
  description="Linked list-based stack with no capacity limits."
>

```java
public class NodeStack<T> {
    private static class Node<T> {
        T item;
        Node<T> next;

        Node(T item, Node<T> next) {
            this.item = item;
            this.next = next;
        }
    }

    private Node<T> top;
    private int size;

    public void push(T item) {
        top = new Node<>(item, top);
        size++;
    }

    public T pop() {
        if (top == null) {
            throw new NoSuchElementException("Stack is empty");
        }
        T item = top.item;
        top = top.next;
        size--;
        return item;
    }

    public T peek() {
        if (top == null) {
            throw new NoSuchElementException("Stack is empty");
        }
        return top.item;
    }

    public boolean isEmpty() {
        return top == null;
    }

    public int size() {
        return size;
    }
}
```

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definitive Trade-off Matrix: Array vs. Linked-List Stacks & Queues"
  description="A comprehensive comparison of the underlying implementations for linear ADTs."
>

| Feature | Array-Based (Stack / Circular Queue) | Linked-List-Based (NodeStack / LinkedQueue) |
| :--- | :--- | :--- |
| **Time Complexity (Push/Enqueue)** | $O(1)$ amortized (due to resizing copies) | $O(1)$ worst-case (no resizing) |
| **Time Complexity (Pop/Dequeue)** | $O(1)$ worst-case | $O(1)$ worst-case |
| **Space Overhead** | **Low.** Only the elements + small object header. No per-element pointers. | **High.** 24+ bytes per element (object header + `next`/`prev` pointers + padding). |
| **Cache Locality** | **Excellent.** Contiguous memory allows CPU hardware prefetching. | **Poor.** Nodes are scattered across the heap, causing frequent cache misses. |
| **Capacity Limits** | Fixed initial capacity (requires resizing or bounded capacity). | Dynamic. Grows/shrinks exactly as needed, no resizing copies. |

**Conclusion:** 
- Use **Array-based** implementations (like `ArrayStack` or `CircularQueue`) for 95% of use cases due to superior cache locality and lower memory overhead.
- Use **Linked-List-based** implementations only when strict $O(1)$ worst-case push/insertion is required and resizing pauses are unacceptable, or when memory is highly fragmented.

</HighlightCard>

  <StepByStepTitle>Application: Balanced Parenthesis Matching</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Algorithm</StepTitle>
    ```java
    public static boolean isBalanced(String expression) {
        ArrayStack<Character> stack = new ArrayStack<>();

        for (char c : expression.toCharArray()) {
            if (c == '(' || c == '{' || c == '[') {
                stack.push(c);
            } else if (c == ')' || c == '}' || c == ']') {
                if (stack.isEmpty()) {
                    return false; // Closing without opening
                }
                char open = stack.pop();
                if (!matches(open, c)) {
                    return false; // Mismatched pair
                }
            }
        }

        return stack.isEmpty(); // True if all opened are closed
    }

    private static boolean matches(char open, char close) {
        return (open == '(' && close == ')') ||
               (open == '{' && close == '}') ||
               (open == '[' && close == ']');
    }
    ```
  </Step>

    <StepTitle>Example Trace</StepTitle>

    ```java
    Step 4: ']' -> pop '[' -> matches -> stack: ['(', '{']
    Step 5: '}' -> pop '{' -> matches -> stack: ['(']
    Step 6: ')' -> pop '(' -> matches -> stack: []

    Result: true (stack is empty)
    ```

<HighlightCard
  variant="neutral"
  title="Definition 4.3.1: Operator Precedence & Associativity"
  description="The rules that dictate when to pop operators from the stack during the Shunting-yard algorithm."
>

| Operator | Precedence | Associativity |
| :--- | :---: | :---: |
| `^` (Exponentiation) | 3 | **Right** |
| `*`, `/`, `%` | 2 | Left |
| `+`, `-` | 1 | Left |
| `(` | 0 | - |

**The Golden Rule for Popping:**
While the stack is not empty and the top operator is not `(`:
- If the incoming operator is **Left-Associative** (e.g., `+`, `*`), pop the top operator if its precedence is **greater than or equal to** (`>=`) the incoming operator's precedence.
- If the incoming operator is **Right-Associative** (e.g., `^`), pop the top operator **only if** its precedence is **strictly greater than** (`>`) the incoming operator's precedence.

*Why?* For `2^3^2`, we want `2^(3^2)`. If we pop the first `^` when we see the second `^`, we would incorrectly evaluate `(2^3)^2`. Right-associativity delays the evaluation.

</HighlightCard>

## 4.4 Advanced Linear Structures

By relaxing or combining the restrictions of Stacks and Queues, we unlock powerful data structures capable of solving complex sliding window and scheduling problems in optimal time.

<HighlightCard
  variant="neutral"
  title="Definition 4.4.1: The Deque (Double-Ended Queue)"
  description="A linear structure that allows insertion and deletion at BOTH the front and the rear in $O(1)$ time."
>

- **Operations:** `addFirst`, `addLast`, `removeFirst`, `removeLast`.
- **Implementation:** Typically implemented as a doubly linked list with sentinel nodes, or a modified circular array.
- **Use Cases:** Palindrome checking, work-stealing algorithms, and sliding window problems.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definition 4.4.2: Monotonic Deques"
  description="A Deque that maintains its elements in strictly increasing or decreasing order, enabling $O(n)$ solutions to sliding window extremum problems."
>

To find the maximum in every sliding window of size $k$:
1. The Deque stores **indices** of elements, not values.
2. **Invariant:** Elements corresponding to the indices in the Deque are in strictly decreasing order of their values.
3. **Maintenance:** Before adding index `i`, remove all indices from the rear of the Deque whose corresponding values are $\le arr[i]$. These elements can never be the maximum as long as `arr[i]` is in the window.
4. **Window Expiry:** Remove indices from the front if they fall outside the current window bounds ($\le i - k$).

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Complexity Proof: Sliding Window Maximum</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Amortized Analysis</StepTitle>
    Although there is a nested `while` loop to remove elements from the rear of the Deque, each index is added to the Deque exactly once and removed at most once.
  </Step>

  <Step number={2}>
    <StepTitle>Total Operations</StepTitle>
    For an array of size $n$, there are exactly $n$ `addLast` operations and at most $n$ `removeLast` operations.
  </Step>

  <Step number={3}>
    <StepTitle>Conclusion</StepTitle>
    The total number of Deque operations is bounded by $2n$. Therefore, the time complexity is strictly $O(n)$, a massive improvement over the naive $O(nk)$ approach.
  </Step>
</StepByStep>

### Definition 4.4.3: Priority Queues & Binary Heaps

A **Priority Queue** is an ADT where each element has a priority, and elements are dequeued based on priority rather than arrival order. 
- **Implementation:** The most efficient implementation is a **Binary Heap** (a complete binary tree satisfying the heap property).
- **Time Complexity:** $O(\log n)$ for insertion and extraction of the min/max element. $O(1)$ for peeking at the extremum.
- **Space Complexity:** $O(n)$, typically stored in a flat array where children of node `i` are at `2i + 1` and `2i + 2`.

</Card>

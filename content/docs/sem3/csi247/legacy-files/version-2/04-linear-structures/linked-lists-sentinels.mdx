## 4.1 Linked Lists & Sentinel Invariants

The choice of underlying memory layout dictates the performance characteristics of linear data structures. We must rigorously evaluate the trade-offs between contiguous arrays and scattered heap allocations.

<HighlightCard
  variant="neutral"
  title="Definition 4.1.1: Memory Trade-offs"
  description="Comparing Array vs. Linked representations with actual Java object overhead."
>

**Array-Based (ArrayList):**
- Contiguous memory allocation
- $O(1)$ random access via index arithmetic
- Excellent CPU cache locality
- Object overhead: 1 array header + $n$ element references
- Insertion/deletion requires $O(n)$ element shifts

**Linked (Node-Based):**
- Scattered heap allocations connected via pointers
- $O(1)$ insertion/deletion given a pointer to the node
- $O(n)$ search time
- **Object overhead per node:** 16 bytes (object header) + 8 bytes (item reference) + 8 bytes (next reference) = 32 bytes minimum per element
- Poor cache locality due to scattered memory addresses

</HighlightCard>

<Card>

### Definition 4.1.2: Linked List Variations

- **Singly Linked:** Each node points only to the next. Space overhead: 1 pointer per node.
- **Doubly Linked:** Each node points to both next and previous. Space overhead: 2 pointers per node.
- **Circular Linked:** The last node points back to the first. Enables continuous traversal.

</Card>

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: Doubly Linked List with Sentinels"
  description="A production-ready implementation showing sentinel nodes, static inner class, and memory efficiency."
>

```java
public class DoublyLinkedList<T> {
    // Sentinel nodes - never hold data, always exist
    private final Node<T> head;
    private final Node<T> tail;
    private int size;

    // Static nested class to avoid implicit outer reference
    private static class Node<T> {
        T item;
        Node<T> prev;
        Node<T> next;

        Node(T item, Node<T> prev, Node<T> next) {
            this.item = item;
            this.prev = prev;
            this.next = next;
        }
    }

    public DoublyLinkedList() {
        // Initialize sentinels
        head = new Node<>(null, null, null);
        tail = new Node<>(null, head, null);
        head.next = tail;
        size = 0;
    }

    // Insert at the beginning - O(1)
    public void addFirst(T item) {
        Node<T> newNode = new Node<>(item, head, head.next);
        head.next.prev = newNode;
        head.next = newNode;
        size++;
    }

    // Insert at the end - O(1)
    public void addLast(T item) {
        Node<T> newNode = new Node<>(item, tail.prev, tail);
        tail.prev.next = newNode;
        tail.prev = newNode;
        size++;
    }

    // Remove first element - O(1)
    public T removeFirst() {
        if (size == 0) throw new NoSuchElementException();
        Node<T> node = head.next;
        node.prev.next = node.next;
        node.next.prev = node.prev;
        size--;
        return node.item;
    }

    public int size() {
        return size;
    }

    public boolean isEmpty() {
        return size == 0;
    }
}
```

**Key Observations:**
1. **Sentinel nodes** eliminate all null checks - `head.next` and `tail.prev` are never null
2. **Static nested class** prevents the 8-byte implicit reference to the outer class per node
3. **Uniform insertion logic** - no special cases for empty list or head/tail insertion

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Memory Analysis: Why Sentinels Save More Than They Cost</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Cost</StepTitle>
    Two sentinel nodes cost 2 × 32 bytes = 64 bytes of overhead.
  </Step>

  <Step number={2}>
    <StepTitle>The Savings</StepTitle>
    Without sentinels, every insertion requires conditional branches:
    ```java
    if (head == null) {
        head = newNode;
        tail = newNode;
    } else {
        // normal insertion
    }
    ```
    These branches cause CPU pipeline stalls and prevent branch prediction optimization.
  </Step>

  <Step number={3}>
    <StepTitle>The Benefit</StepTitle>
    With sentinels, insertion is always the same 4 pointer assignments, allowing the CPU to optimize the hot path. The 64-byte overhead is negligible for any list with more than a few elements.
  </Step>
</StepByStep>

## 4.2 Complete Implementation with Iterator

To truly understand data structures, we must build them from scratch using Java's generics, inner classes, and iterator patterns.

<HighlightCard
  variant="neutral"
  title="Complete Java Implementation: LinkedList with Fail-Fast Iterator"
  description="A production-ready implementation showing modCount, expectedModCount, and ConcurrentModificationException."
>

```java
import java.util.ConcurrentModificationException;
import java.util.Iterator;
import java.util.NoSuchElementException;

public class LinkedList<T> implements Iterable<T> {
    private Node<T> head;
    private int size;
    private int modCount = 0; // Tracks structural modifications

    private static class Node<T> {
        T item;
        Node<T> next;

        Node(T item, Node<T> next) {
            this.item = item;
            this.next = next;
        }
    }

    public void add(T item) {
        head = new Node<>(item, head);
        size++; // CRITICAL FIX: Must increment size!
        modCount++; // Increment modification count
    }

    public int size() {
        return size;
    }

    // Implement Iterable to support for-each loop
    @Override
    public Iterator<T> iterator() {
        return new LinkedListIterator();
    }

    // Fail-fast Iterator implementation
    private class LinkedListIterator implements Iterator<T> {
        private Node<T> current = head;
        private int expectedModCount = modCount; // Capture modCount at creation

        @Override
        public boolean hasNext() {
            checkForComodification();
            return current != null;
        }

        @Override
        public T next() {
            checkForComodification();
            if (current == null) {
                throw new NoSuchElementException();
            }
            T item = current.item;
            current = current.next;
            return item;
        }

        @Override
        public void remove() {
            throw new UnsupportedOperationException();
        }

        // Fail-fast mechanism
        private void checkForComodification() {
            if (modCount != expectedModCount) {
                throw new ConcurrentModificationException(
                    "List was modified during iteration!"
                );
            }
        }
    }

    // PECS: Producer Extends - allows Collection<Integer> to be added to LinkedList<Number>
    public void addAll(java.util.Collection<? extends T> c) {
        for (T item : c) {
            add(item); // add() handles size++ and modCount++ internally
        }
    }
}
```

**Key Features & Fixes:**
1. **`size++` in `add()`**: The previous version forgot to increment the size counter, which would cause `size()` to always return 0.
2. **`modCount`**: Incremented on every structural modification (add, remove).
3. **`expectedModCount`**: Captured by iterator at creation time.
4. **`ConcurrentModificationException`**: Thrown immediately if the list is modified during iteration.
5. **PECS**: `? extends T` allows safe covariance when adding collections.

<HighlightCard

  title="Memory Overhead Analysis"
  description="Actual Java object memory layout for LinkedList vs ArrayList."
>

**LinkedList Node (per element):**
- Object header: 12 bytes (compressed oops)
- `item` reference: 4 bytes
- `next` reference: 4 bytes
- Padding: 4 bytes (to align to 8-byte boundary)
- **Total: 24 bytes per element**

**ArrayList (shared overhead):**
- Object header: 12 bytes
- `elementData` reference: 4 bytes
- `size` int: 4 bytes
- `modCount` int: 4 bytes
- **Array overhead:** 16 bytes + (4 bytes × capacity)
- **Total per element: 4 bytes** (just the reference in the array)

**Conclusion:** LinkedList uses **6× more memory** per element than ArrayList (24 bytes vs 4 bytes), plus the cost of scattered memory allocations.

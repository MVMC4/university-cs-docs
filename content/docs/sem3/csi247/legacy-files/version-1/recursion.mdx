# Recursion and Algorithmic Problem Solving

Recursion is when a function calls itself to solve smaller versions of the same problem. Think of it like Russian nesting dolls—each doll contains a smaller version of itself until you reach the tiniest one.

> **Simple Explanation**: Recursion = Solving a big problem by solving smaller copies of the same problem.

---

## 1. Understanding the Call Stack

When a function calls itself, Java needs to remember where it was. It does this using a **stack** (like a stack of plates).

### Visual: How the Stack Works

<SafeImage

  className="max-w-md mx-auto"
/>

**Key Idea**: 
- Each function call = add a plate (push)
- Each function return = remove a plate (pop)
- Too many calls = stack overflows (plates fall!)

### Example: Factorial Step-by-Step

```java
public int factorial(int n) {
    if (n == 1) return 1;  // Base case
    return n * factorial(n - 1);
}

// factorial(4) creates this stack:
```

<SafeImage 
  src="/images/csi247/factorial-stack.png" 
  alt="Factorial call stack visualization" 
  caption="Figure 2: factorial(4) builds a stack of 4 frames, then unwinds" 
  className="max-w-full h-auto"
/>

**What Happens**:
1. `factorial(4)` waits for `factorial(3)`
2. `factorial(3)` waits for `factorial(2)`
3. `factorial(2)` waits for `factorial(1)`
4. `factorial(1)` returns 1 (base case!)
5. Stack unwinds: `2*1=2`, `3*2=6`, `4*6=24`

### StackOverflowError

```java
// DANGER: No base case!
public void infiniteRecursion() {
    infiniteRecursion();  // Calls itself forever
}
```

  src="/images/csi247/stack-overflow.png"

  caption="Figure 3: Without a base case, the stack grows until it crashes" 
  className="max-w-full h-auto"
/>

**Why it crashes**: The stack has limited memory (~1MB). Too many function calls = out of memory.

## 2. The Two Rules of Recursion

Every recursive function needs **two parts**:

### Rule 1: Base Case (The Stop Button)

The condition that stops the recursion.

```java
if (n == 1) return 1;  // STOP here!
```

**Without it**: Infinite loop leads to StackOverflowError

### Rule 2: Recursive Case (The Progress)

The part that calls itself with a **smaller** problem.

```java
return n * factorial(n - 1);  // n-1 is smaller than n
```

**Without progress**: Never reaches base case leads to StackOverflowError

### Good vs Bad Examples

```java
// GOOD: Has base case AND makes progress
public int factorial(int n) {
    if (n <= 1) return 1;           // Base case
    return n * factorial(n - 1);    // Progress: n-1
}

// BAD: No base case
public int bad1(int n) {
    return n * bad1(n - 1);  // Never stops!
}

// BAD: No progress toward base case
public int bad2(int n) {
    if (n == 0) return 1;
    return n * bad2(n);  // n doesn't change!
}
```

## 3. Recursion vs Iteration

Many problems can be solved **both ways**. Let's compare:

### Example: Factorial

**Recursive Approach**:
```java
public int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

**Iterative Approach**:
```java
public int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

### Comparison Table

| Aspect | Recursion | Iteration |
|--------|-----------|-----------|
| **Code** | Shorter, cleaner | Longer, more verbose |
| **Memory** | Uses stack `O(n)` | Uses variables `O(1)` |
| **Speed** | Slower (function calls) | Faster |
| **Readability** | Easier for recursive problems | Easier for simple loops |
| **Risk** | StackOverflow if too deep | No stack risk |

### When to Use Which?

**Use Recursion When:**
- Problem is naturally recursive (trees, graphs, nested data)
- Code clarity is more important than speed
- Depth is limited (won't cause stack overflow)

**Use Iteration When:**
- Performance matters
- Simple counting/looping
- Depth could be very large

## 4. Classic Examples

### Example 1: Fibonacci Numbers

Fibonacci: Each number is the sum of the two before it.

`0, 1, 1, 2, 3, 5, 8, 13, 21...`

**Naive Recursive (SLOW!)**:
```java
public int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

<SafeImage 
  src="/images/csi247/fib-tree.png" 
  alt="Fibonacci recursion tree" 
  caption="Figure 4: fib(5) recalculates fib(3) twice and fib(2) three times—very inefficient!" 
  className="max-w-full h-auto"
/>

**Problem**: Recalculates the same values over and over!
- `fib(5)` needs `fib(4)` and `fib(3)`
- `fib(4)` needs `fib(3)` and `fib(2)` — `fib(3)` again!

**Better: Memoization (Caching)**:
```java
int[] memo = new int[100];  // Cache

public int fib(int n) {
    if (n <= 1) return n;
    
    if (memo[n] != 0) return memo[n];  // Use cached value
    
    memo[n] = fib(n-1) + fib(n-2);  // Calculate and cache
    return memo[n];
}
```

**Even Better: Iterative**:
```java
public int fib(int n) {
    if (n <= 1) return n;
    
    int prev2 = 0;  // fib(0)
    int prev1 = 1;  // fib(1)
    
    for (int i = 2; i <= n; i++) {
        int current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }
    
    return prev1;
}
```

### Example 2: Binary Search

Search a **sorted** array by repeatedly dividing in half.

<SafeImage 
  src="/images/csi247/binary-search.png" 
  alt="Binary search visualization" 
  caption="Figure 6: Each step cuts the search space in half—find target in O(log n) time" 
  className="max-w-full h-auto"
/>

**Recursive**:
```java
public int binarySearch(int[] arr, int left, int right, int target) {
    if (left > right) return -1;  // Not found
    
    int mid = left + (right - left) / 2;
    
    if (arr[mid] == target) return mid;           // Found!
    if (arr[mid] > target) {
        return binarySearch(arr, left, mid-1, target);  // Search left
    }
    return binarySearch(arr, mid+1, right, target);     // Search right
}
```

**Iterative** (preferred):
```java
public int binarySearch(int[] arr, int target) {
    int left = 0, right = arr.length - 1;
    
    while (left <= right) {
        int mid = left + (right - left) / 2;
        
        if (arr[mid] == target) return mid;
        if (arr[mid] > target) right = mid - 1;
        else left = mid + 1;
    }
    
    return -1;
}
```

### Example 3: Merge Sort

Sort by dividing array in half, sorting each half, then merging.

<SafeImage 
  src="/images/csi247/merge-sort.png" 
  alt="Merge sort visualization" 
  caption="Figure 7: Divide until single elements, then merge back in sorted order" 
  className="max-w-full h-auto"
/>

```java
public void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;  // Base case: 1 element
    
    int mid = left + (right - left) / 2;
    
    mergeSort(arr, left, mid);       // Sort left half
    mergeSort(arr, mid+1, right);    // Sort right half
    merge(arr, left, mid, right);    // Merge sorted halves
}
```

**Time**: `O(n log n)`  
**Space**: `O(n)` for temporary arrays

## 5. Analyzing Recursive Algorithms

Understanding how fast recursive algorithms run is crucial. Here are four methods:

### Method 1: The Recursion Tree Method (Visual)

Draw the recursion as a tree and add up the work at each level.

**Example**: Merge Sort `T(n) = 2T(n/2) + n`

<SafeImage 
  src="/images/csi247/recursion-tree-merge.png" 
  alt="Merge sort recursion tree" 
  caption="Figure 8: Each level does n work, and there are log n levels, so total = n log n" 
  className="max-w-full h-auto"
/>

**How to analyze**:
1. **Level 0**: 1 problem of size n, work = n
2. **Level 1**: 2 problems of size n/2, work = n/2 + n/2 = n
3. **Level 2**: 4 problems of size n/4, work = n/4 * 4 = n
4. **Continue**: Each level does n work
5. **How many levels?**: Keep dividing by 2 until we reach 1: `log₂(n)` levels
6. **Total work**: `n * log₂(n) = O(n log n)`

**Example**: Binary Search `T(n) = T(n/2) + 1`

<SafeImage 
  src="/images/csi247/recursion-tree-binary.png" 
  alt="Binary search recursion tree" 
  caption="Figure 9: Each level does constant work, log n levels, total = O(log n)" 
  className="max-w-full h-auto"
/>

1. **Each level**: Does 1 unit of work (compare mid element)
2. **Levels**: `log₂(n)` (keep dividing by 2)
3. **Total**: `1 * log₂(n) = O(log n)`

### Method 2: The Master Theorem (Formula)

The Master Theorem gives you a quick formula for divide-and-conquer recurrences:

**Formula**: `T(n) = a * T(n/b) + f(n)`

Where:
- `a` = number of subproblems
- `b` = factor to divide input size (each subproblem is size n/b)
- `f(n)` = work to divide and combine (outside the recursive calls)

**The Three Cases**:

<SafeImage 
  src="/images/csi247/master-theorem.png" 
  alt="Master Theorem visualization" 
  caption="Figure 10: Three cases based on comparing f(n) with n^(log_b(a))" 
  className="max-w-full h-auto"
/>

**Case 1: Most work at leaves**
- If `f(n)` is **small** compared to `n^(log_b(a))`
- Specifically: `f(n) = O(n^(log_b(a) - ε))` for some ε > 0
- Then: `T(n) = Θ(n^(log_b(a)))`
- **Meaning**: The recursive calls dominate

**Example**: `T(n) = 8T(n/2) + n²`
- a = 8, b = 2, f(n) = n²
- `n^(log_b(a)) = n^(log₂(8)) = n³`
- n² is smaller than n³, so Case 1 applies
- **Answer**: `T(n) = Θ(n³)`

**Case 2: Work evenly distributed**
- If `f(n)` is **about the same** as `n^(log_b(a))`
- Specifically: `f(n) = Θ(n^(log_b(a)) * log^k(n))` for k >= 0
- Then: `T(n) = Θ(n^(log_b(a)) * log^(k+1)(n))`
- **Meaning**: Work is balanced across all levels

**Example**: `T(n) = 2T(n/2) + n` (Merge Sort)
- a = 2, b = 2, f(n) = n
- `n^(log_b(a)) = n^(log₂(2)) = n¹ = n`
- f(n) = n is the same as n, so Case 2 applies (k=0)
- **Answer**: `T(n) = Θ(n log n)`

**Example**: `T(n) = 2T(n/2) + n log n`
- a = 2, b = 2, f(n) = n log n
- `n^(log_b(a)) = n`
- f(n) = n log n = `Θ(n * log¹(n))`, so k=1
- **Answer**: `T(n) = Θ(n log²(n))`

**Case 3: Most work at root**
- If `f(n)` is **large** compared to `n^(log_b(a))`
- Specifically: `f(n) = Ω(n^(log_b(a) + ε))` for some ε > 0
- AND the regularity condition: `a * f(n/b) <= c * f(n)` for some c < 1
- Then: `T(n) = Θ(f(n))`
- **Meaning**: The divide/combine work dominates

**Example**: `T(n) = 2T(n/2) + n²`
- a = 2, b = 2, f(n) = n²
- `n^(log_b(a)) = n^(log₂(2)) = n`
- n² is larger than n, so Case 3 might apply
- Check regularity: `2 * (n/2)² = 2 * n²/4 = n²/2 <= c * n²` for c = 1/2 < 1 ✓
- **Answer**: `T(n) = Θ(n²)`

### Quick Reference Table

| Recurrence | a | b | `n^(log_b(a))` | f(n) | Case | Result |
|------------|---|---|--------------|------|------|--------|
| `T(n) = T(n/2) + 1` | 1 | 2 | `n⁰ = 1` | 1 | Case 2 | `O(log n)` |
| `T(n) = 2T(n/2) + n` | 2 | 2 | n | n | Case 2 | `O(n log n)` |
| `T(n) = 8T(n/2) + n²` | 8 | 2 | n³ | n² | Case 1 | `O(n³)` |
| `T(n) = 2T(n/2) + n²` | 2 | 2 | n | n² | Case 3 | `O(n²)` |
| `T(n) = 3T(n/4) + n` | 3 | 4 | n^0.79 | n | Case 3 | `O(n)` |

### Method 3: Substitution Method (Proof by Induction)

Guess the answer, then prove it's correct using mathematical induction.

**Example**: Prove `T(n) = 2T(n/2) + n` is `O(n log n)`

**Step 1: Guess**
Guess: `T(n) <= c * n log n` for some constant c

**Step 2: Base Case**
For small n (like n=1), check if it holds:
- `T(1) = 1` (usually)
- `c * 1 * log(1) = c * 1 * 0 = 0`
- Need `T(1) <= 0`, which might not hold, so adjust: `T(n) <= c * n log n + d`

**Step 3: Inductive Step**
Assume it's true for smaller values: `T(n/2) <= c * (n/2) log(n/2)`

Now prove for T(n):
```
T(n) = 2T(n/2) + n
     <= 2[c * (n/2) log(n/2)] + n           (by induction hypothesis)
     = c * n log(n/2) + n
     = c * n (log n - log 2) + n
     = c * n log n - c * n + n
     = c * n log n - n(c - 1)
```

For this to be `<= c * n log n`, we need:
- `n(c - 1) >= 0`
- `c >= 1`

So if we choose `c >= 1`, the proof works!

**Conclusion**: `T(n) = O(n log n)` ✓

### Method 4: Iteration Method (Expand the Recurrence)

Repeatedly substitute the recurrence into itself until you see a pattern.

**Example**: `T(n) = 2T(n/2) + n`

```
T(n) = 2T(n/2) + n
     = 2[2T(n/4) + n/2] + n
     = 4T(n/4) + n + n
     = 4[2T(n/8) + n/4] + 2n
     = 8T(n/8) + n + n + n
     = 8T(n/8) + 3n
     ...
     = 2^k * T(n/2^k) + k*n
```

When does it stop? When `n/2^k = 1`, so `k = log₂(n)`

```
T(n) = 2^(log n) * T(1) + n log n
     = n * 1 + n log n
     = n + n log n
     = O(n log n)
```

## 6. Backtracking: Try, Explore, Undo

Backtracking is recursion for **trying different options** and undoing bad choices.

**Pattern**:
1. **Choose** an option
2. **Explore** recursively
3. **Un-choose** (backtrack) if it doesn't work

### Example: N-Queens Problem

Place N queens on a chessboard so none attack each other.

<SafeImage 
  src="/images/csi247/nqueens.png" 
  alt="N-Queens solution" 
  caption="Figure 11: 4-Queens solution—no two queens share a row, column, or diagonal" 
  className="max-w-md mx-auto"
/>

```java
public void solveNQueens(int n) {
    char[][] board = new char[n][n];
    backtrack(board, 0);
}

private void backtrack(char[][] board, int row) {
    // Base case: All rows filled
    if (row == board.length) {
        printBoard(board);
        return;
    }
    
    // Try each column
    for (int col = 0; col < board.length; col++) {
        if (isValid(board, row, col)) {
            // CHOOSE: Place queen
            board[row][col] = 'Q';
            
            // EXPLORE: Next row
            backtrack(board, row + 1);
            
            // UN-CHOOSE: Remove queen (backtrack)
            board[row][col] = '.';
        }
    }
}
```

### Example: Generate Permutations

Generate all arrangements of a string.

```java
public void permute(String str, String prefix) {
    // Base case: No characters left
    if (str.length() == 0) {
        System.out.println(prefix);
        return;
    }
    
    // Try each character as next
    for (int i = 0; i < str.length(); i++) {
        String remaining = str.substring(0, i) + str.substring(i + 1);
        permute(remaining, prefix + str.charAt(i));
    }
}

// permute("ABC", "") prints:
// ABC, ACB, BAC, BCA, CAB, CBA
```

## 7. Real-World Applications

Recursion isn't just theory—it's used everywhere!

### Application 1: File System Traversal

Finding all files in a folder and its subfolders.

<SafeImage 
  src="/images/csi247/file-tree.png"

```java
public void findFiles(File folder, String extension) {
    for (File file : folder.listFiles()) {
        if (file.isDirectory()) {
            findFiles(file, extension);  // Recurse into subfolder
        } else if (file.getName().endsWith(extension)) {
            System.out.println(file);
        }
    }
}
```

## 9. Common Mistakes and How to Fix Them

### Mistake 1: Forgetting Base Case

```java
// WRONG
public int factorial(int n) {
    return n * factorial(n - 1);  // Never stops!
}

// CORRECT
public int factorial(int n) {
    if (n <= 1) return 1;  // Base case!
    return n * factorial(n - 1);
}
```

### Mistake 2: Not Making Progress

```java
// WRONG
public int bad(int n) {
    if (n == 0) return 1;
    return n * bad(n);  // n doesn't change!
}

// CORRECT
public int good(int n) {
    if (n == 0) return 1;
    return n * good(n - 1);  // n decreases
}
```

### Mistake 3: Too Much Memory

```java
// SLOW: Creates new array each call
public void process(int[] arr) {
    int[] smaller = Arrays.copyOfRange(arr, 1, arr.length);
    process(smaller);  // O(n²) space!
}

// FAST: Use indices
public void process(int[] arr, int start) {
    process(arr, start + 1);  // O(n) space
}
```

## Summary

- **Base Case**: Always have a stopping condition  
- **Progress**: Each call must move toward the base case  
- **Recursion vs Iteration**: Recursion is cleaner, iteration is faster  
- **Backtracking**: Choose, Explore, Un-choose  
- **Memory**: Recursion uses stack space `O(n)`  
- **Analysis Methods**: Recursion tree (visual), Master theorem (formula), Substitution (proof), Iteration (expansion)  
- **Applications**: File systems, trees, JSON parsing, games  

**Key Takeaway**: Recursion is a tool. Use it when it makes code clearer, but watch out for stack overflow!

# Java Collections Framework (JCF)

The Java Collections Framework is like a toolbox for storing and organizing data. Just like you use different containers for different purposes (backpack for books, fridge for food), Java provides different collections for different needs.

> **Why Learn This?**
> Imagine you're building Instagram:
> - **List**: Store posts in order (timeline)
> - **Set**: Store unique hashtags (no duplicates)
> - **Map**: Link usernames to user profiles (fast lookup)
> 
> Choosing the right collection makes your app fast and efficient!

---

## Part 1: Understanding Collections - The Big Picture

### What is a Collection?

A collection is simply a container that holds multiple items. Think of it like:
- A shopping list (List)
- A bag of marbles (Set - no duplicates)
- A phone book (Map - name → number)

### The Two Main Families

Java Collections has **two separate families**:

1. **Collection Interface** (for single values)
   - List: Ordered, allows duplicates
   - Set: Unordered, no duplicates
   - Queue: First-in-first-out

2. **Map Interface** (for key-value pairs)
   - HashMap: Fast lookup by key
   - TreeMap: Sorted by key
   - LinkedHashMap: Ordered by insertion

## Part 2: Lists - Ordered Collections

### What is a List?

**Simple Explanation**: A list is like a numbered list. Each item has a position (index) starting from 0.

**Real-World Examples**:
- Shopping list: [Milk, Bread, Eggs]
- Playlist: [Song 1, Song 2, Song 3]
- Todo list: [Task 1, Task 2, Task 3]

**Key Features**:
- **Ordered**: Items stay in the order you add them
- **Allows duplicates**: You can have [Milk, Bread, Milk]
- **Access by index**: Get item at position 0, 1, 2, etc.

---

### 1. ArrayList (The Most Common List)

**Simple Explanation**: ArrayList is like a resizable array. It grows automatically when you add more items.

**Real-World Analogy**: Imagine a bookshelf that automatically adds more shelves when you run out of space.

**How It Works**:
- Stores items in a continuous block of memory (like an array)
- When full, creates a bigger array and copies everything over
- Fast to read: Can jump directly to any position
- Slow to insert/delete in the middle: Need to shift items

**Step-by-Step Example**:

```java
// Create an ArrayList
ArrayList<String> fruits = new ArrayList<>();

// Add items
fruits.add("Apple");   // Index 0: [Apple]
fruits.add("Banana");  // Index 1: [Apple, Banana]
fruits.add("Cherry");  // Index 2: [Apple, Banana, Cherry]

// Access items
String first = fruits.get(0);  // "Apple"

// Insert in middle (slow - shifts items)
fruits.add(1, "Blueberry");  // [Apple, Blueberry, Banana, Cherry]

// Remove item (slow - shifts items)
fruits.remove(2);  // [Apple, Blueberry, Cherry]
```

  src="/images/csi247/arraylist-operations.png" 
  alt="ArrayList Operations Visualization" 
  caption="Figure 2: ArrayList - fast access by index, but slow insert/delete in middle (requires shifting)" 
  className="max-w-full h-auto"

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Get item** | O(1) - Instant | Direct access like array |
| **Add to end** | O(1) - Fast | Just append (usually) |
| **Insert in middle** | O(n) - Slow | Must shift all items right |
| **Delete from middle** | O(n) - Slow | Must shift all items left |
| **Search** | O(n) - Slow | Must check each item |

**When to Use**:
- You need fast access by index
- You mostly add/remove from the end
- You don't insert/delete in the middle often

**Code Example**:
```java
List<String> names = new ArrayList<>();
names.add("Alice");
names.add("Bob");
names.add("Charlie");

// Fast: Get by index
String name = names.get(1);  // "Bob" - instant!

// Slow: Insert in middle (shifts Bob and Charlie)
names.add(1, "David");  // [Alice, David, Bob, Charlie]
```

### 2. LinkedList (The Flexible List)

**Simple Explanation**: LinkedList connects items like a chain. Each item knows about the next (and previous) item.

**Real-World Analogy**: A treasure hunt where each clue tells you where to find the next clue.

**How It Works**:
- Each item (node) contains:
  - The data
  - Reference to next node
  - Reference to previous node (doubly-linked)
- Items are scattered in memory (not continuous)
- Connected by references (like links in a chain)

**Step-by-Step Example**:

```java
LinkedList<String> tasks = new LinkedList<>();

// Add items
tasks.add("Wake up");      // [Wake up]
tasks.add("Brush teeth");  // [Wake up] → [Brush teeth]
tasks.add("Eat breakfast"); // [Wake up] → [Brush teeth] → [Eat breakfast]

// Insert in middle (fast - just change links)
tasks.add(1, "Make bed");  // [Wake up] → [Make bed] → [Brush teeth] → [Eat breakfast]

// Remove item (fast - just change links)
tasks.remove(2);  // [Wake up] → [Make bed] → [Eat breakfast]
```

<SafeImage 
  src="/images/csi247/linkedlist-structure.png" 
  alt="LinkedList Structure" 
  caption="Figure 3: LinkedList - each node points to next and previous nodes. Fast insert/delete, slow access." 
  className="max-w-full h-auto"
/>

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Get item** | O(n) - Slow | Must traverse from start |
| **Add to end** | O(1) - Fast | Just update last node's link |
| **Insert in middle** | O(1) - Fast* | Just change links (*after finding position) |
| **Delete from middle** | O(1) - Fast* | Just change links (*after finding position) |
| **Search** | O(n) - Slow | Must check each node |

**When to Use**:
- You frequently insert/delete in the middle
- You don't need fast access by index
- You're implementing a Queue or Stack

**Code Example**:
```java
LinkedList<Integer> numbers = new LinkedList<>();

// Add to front and back (both fast)
numbers.addFirst(1);    // [1]
numbers.addLast(2);     // [1] → [2]
numbers.addLast(3);     // [1] → [2] → [3]

// Remove from front (fast)
numbers.removeFirst();  // [2] → [3]

// Insert in middle
numbers.add(1, 5);      // [2] → [5] → [3]
```

### ArrayList vs LinkedList - Which to Choose?

<SafeImage 
  src="/images/csi247/arraylist-vs-linkedlist.png" 
  alt="ArrayList vs LinkedList Comparison" 
  caption="Figure 4: ArrayList vs LinkedList - ArrayList is faster for access, LinkedList is faster for insert/delete" 
  className="max-w-full h-auto"
/>

| Feature | ArrayList | LinkedList |
|---------|-----------|------------|
| **Get by index** | O(1) - Instant | O(n) - Slow |
| **Add to end** | O(1) - Fast | O(1) - Fast |
| **Insert in middle** | O(n) - Slow (shift) | O(1) - Fast (change links) |
| **Delete from middle** | O(n) - Slow (shift) | O(1) - Fast (change links) |
| **Memory** | Less (just array) | More (stores links) |
| **Use when** | Random access needed | Frequent insert/delete |

**Rule of Thumb**:
- **Use ArrayList 90% of the time** - it's faster for most operations
- **Use LinkedList** only if you're constantly inserting/deleting in the middle

## Part 3: Sets - Unique Collections

### What is a Set?

**Simple Explanation**: A set is like a bag that doesn't allow duplicates. If you try to add the same item twice, it ignores the second one.

**Real-World Examples**:
- Unique hashtags: #love, #instagood, #photooftheday (no duplicates)
- Unique visitors to a website
- Unique words in a document

**Key Features**:
- **No duplicates**: Each item appears only once
- **Unordered** (usually): Items don't stay in insertion order
- **Fast lookup**: Can quickly check if an item exists

---

### 3. HashSet (The Fast Set)

**Simple Explanation**: HashSet uses a hash table (like a super-fast filing system) to store unique items.

**Real-World Analogy**: Imagine a library where each book has a unique code. You can instantly find if a book exists by looking up its code.

**How It Works**:
1. When you add an item, it calculates a "hash code" (like a fingerprint)
2. Uses the hash code to decide which "bucket" to put it in
3. To check if item exists, calculate hash and look in that bucket

**Step-by-Step Example**:

```java
HashSet<String> uniqueWords = new HashSet<>();

// Add items
uniqueWords.add("hello");   // Hash: 1234 → Bucket 3
uniqueWords.add("world");   // Hash: 5678 → Bucket 7
uniqueWords.add("hello");   // Already exists! Ignored

// Result: ["hello", "world"] - no duplicates!

// Fast lookup
boolean exists = uniqueWords.contains("hello");  // true - instant!
```

<SafeImage 
  src="/images/csi247/hashset-buckets.png" 
  alt="HashSet Bucket Structure" 
  caption="Figure 5: HashSet uses buckets based on hash codes for O(1) average lookup time" 
  className="max-w-full h-auto"
/>

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Add** | O(1) - Instant | Calculate hash, put in bucket |
| **Remove** | O(1) - Instant | Calculate hash, remove from bucket |
| **Contains** | O(1) - Instant | Calculate hash, check bucket |
| **Size** | O(1) - Instant | Just return counter |

**When to Use**:
- You need unique items
- You need fast lookup (check if exists)
- You don't care about order

**Code Example**:
```java
// Remove duplicates from a list
List<String> names = Arrays.asList("Alice", "Bob", "Alice", "Charlie", "Bob");
Set<String> uniqueNames = new HashSet<>(names);
// Result: [Alice, Bob, Charlie] - duplicates removed!

// Check if word exists in dictionary
Set<String> dictionary = new HashSet<>();
dictionary.add("apple");
dictionary.add("banana");

boolean isWord = dictionary.contains("apple");  // true - very fast!
```

### 4. TreeSet (The Sorted Set)

**Simple Explanation**: TreeSet keeps items sorted automatically (like a phone book sorted alphabetically).

**Real-World Analogy**: A contact list that automatically sorts names alphabetically as you add them.

**How It Works**:
- Uses a Red-Black Tree (a self-balancing binary search tree)
- Every time you add an item, it finds the correct sorted position
- Always maintains sorted order

**Step-by-Step Example**:

```java
TreeSet<Integer> numbers = new TreeSet<>();

// Add items in random order
numbers.add(50);
numbers.add(20);
numbers.add(80);
numbers.add(10);

// Automatically sorted!
System.out.println(numbers);  // [10, 20, 50, 80]

// Get first and last
System.out.println(numbers.first());   // 10 (smallest)
System.out.println(numbers.last());    // 80 (largest)

// Get items in range
System.out.println(numbers.subSet(20, 80));  // [20, 50]
```

<SafeImage 
  src="/images/csi247/treeset-structure.png" 
  alt="TreeSet Red-Black Tree Structure" 
  caption="Figure 6: TreeSet uses a Red-Black Tree to maintain sorted order with O(log n) operations" 
  className="max-w-full h-auto"
/>

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Add** | O(log n) - Fast | Find position in tree |
| **Remove** | O(log n) - Fast | Find and remove from tree |
| **Contains** | O(log n) - Fast | Search tree |
| **Get first/last** | O(log n) - Fast | Navigate tree |

**When to Use**:
- You need unique items
- You need items sorted
- You need range queries (get all items between X and Y)

**Code Example**:
```java
TreeSet<String> names = new TreeSet<>();
names.add("Charlie");
names.add("Alice");
names.add("Bob");

// Automatically sorted alphabetically
System.out.println(names);  // [Alice, Bob, Charlie]

// Get names starting with A-M
System.out.println(names.headSet("M"));  // [Alice, Bob]
```

### 5. LinkedHashSet (The Ordered Set)

**Simple Explanation**: LinkedHashSet remembers the order you added items (unlike HashSet which is random).

**Real-World Analogy**: A guest list that remembers who arrived first, second, third, etc.

**How It Works**:
- Combines HashSet (fast lookup) with LinkedList (maintains order)
- Each item has a link to the next item added

**Step-by-Step Example**:

```java
LinkedHashSet<String> fruits = new LinkedHashSet<>();

// Add items
fruits.add("Apple");
fruits.add("Banana");
fruits.add("Cherry");
fruits.add("Apple");  // Duplicate - ignored

// Maintains insertion order!
System.out.println(fruits);  // [Apple, Banana, Cherry]
```

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Add** | O(1) - Instant | Like HashSet + update link |
| **Remove** | O(1) - Instant | Like HashSet + update links |
| **Contains** | O(1) - Instant | Like HashSet |

**When to Use**:
- You need unique items
- You need to maintain insertion order
- You need fast lookup

---

### Set Comparison

| Feature | HashSet | TreeSet | LinkedHashSet |
|---------|---------|---------|---------------|
| **Order** | Random | Sorted | Insertion order |
| **Speed** | O(1) - Fastest | O(log n) - Slower | O(1) - Fast |
| **Null allowed** | Yes (1) | No | Yes (1) |
| **Use when** | Speed matters | Need sorted | Need order + speed |

## Part 4: Maps - Key-Value Pairs

### What is a Map?

**Simple Explanation**: A map stores pairs of items: a key and a value. You look up the value using the key.

**Real-World Examples**:
- Phone book: Name (key) → Phone number (value)
- Dictionary: Word (key) → Definition (value)
- Student database: Student ID (key) → Student record (value)

**Key Features**:
- **Key-Value pairs**: Each entry has a key and a value
- **Unique keys**: Each key appears only once
- **Fast lookup**: Find value by key quickly

---

### 6. HashMap (The Fast Map)

**Simple Explanation**: HashMap is like a super-fast lookup table. You give it a key, it instantly gives you the value.

**Real-World Analogy**: A coat check at a museum. You give them your coat, they give you a ticket (key). Later, you show the ticket and instantly get your coat (value).

**How It Works**:
1. Calculate hash code of the key
2. Use hash to find the right "bucket"
3. Store key-value pair in that bucket
4. To retrieve: calculate hash, find bucket, return value

**Step-by-Step Example**:

```java
HashMap<String, Integer> ages = new HashMap<>();

// Add key-value pairs
ages.put("Alice", 25);    // Key: "Alice", Value: 25
ages.put("Bob", 30);      // Key: "Bob", Value: 30
ages.put("Charlie", 35);  // Key: "Charlie", Value: 35

// Get value by key (fast!)
Integer aliceAge = ages.get("Alice");  // 25 - instant!

// Update value
ages.put("Alice", 26);  // Alice is now 26

// Check if key exists
boolean hasBob = ages.containsKey("Bob");  // true

// Remove entry
ages.remove("Charlie");  // Charlie removed
```

<SafeImage 
  src="/images/csi247/hashmap-structure.png" 
  alt="HashMap Bucket Structure" 
  caption="Figure 7: HashMap stores key-value pairs in buckets based on hash codes for O(1) lookup" 
  className="max-w-full h-auto"
/>

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Put (add)** | O(1) - Instant | Calculate hash, store in bucket |
| **Get** | O(1) - Instant | Calculate hash, find in bucket |
| **Remove** | O(1) - Instant | Calculate hash, remove from bucket |
| **ContainsKey** | O(1) - Instant | Calculate hash, check bucket |

**When to Use**:
- You need fast key-value lookup
- You don't care about order
- Keys are unique

**Important: JDK 8 Treeification**

In Java 8+, HashMap has a special feature to prevent attacks:

**Problem**: If many keys have the same hash code (collision), they all go in the same bucket as a linked list. This makes lookup slow: O(n).

**Solution**: When a bucket has 8 or more items, HashMap converts the linked list into a Red-Black Tree. This makes lookup fast again: O(log n).

```java
// Normal: Linked list in bucket
Bucket 5: [Entry1] → [Entry2] → [Entry3]  // O(n) lookup

// After 8 collisions: Tree in bucket
Bucket 5: Tree structure  // O(log n) lookup

// When items drop below 6, converts back to list
```

**Code Example**:
```java
// Count word frequencies
HashMap<String, Integer> wordCount = new HashMap<>();

String[] words = {"hello", "world", "hello", "java", "world", "hello"};

for (String word : words) {
    wordCount.put(word, wordCount.getOrDefault(word, 0) + 1);
}

// Result: {hello=3, world=2, java=1}
```

### 7. TreeMap (The Sorted Map)

**Simple Explanation**: TreeMap keeps entries sorted by key (like a dictionary sorted alphabetically).

**Real-World Analogy**: A phone book where names are always kept in alphabetical order.

**How It Works**:
- Uses a Red-Black Tree
- Automatically sorts entries by key
- Can use natural ordering (alphabetical) or custom comparator

**Step-by-Step Example**:

```java
TreeMap<String, Integer> scores = new TreeMap<>();

// Add in random order
scores.put("Charlie", 85);
scores.put("Alice", 95);
scores.put("Bob", 78);

// Automatically sorted by name!
System.out.println(scores);
// {Alice=95, Bob=78, Charlie=85}

// Get first and last entry
System.out.println(scores.firstEntry());  // Alice=95
System.out.println(scores.lastEntry());   // Charlie=85

// Get range of entries
System.out.println(scores.subMap("Alice", "Charlie"));
// {Alice=95, Bob=78}
```

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Put** | O(log n) - Fast | Find position in tree |
| **Get** | O(log n) - Fast | Search tree |
| **Remove** | O(log n) - Fast | Find and remove from tree |

**When to Use**:
- You need sorted keys
- You need range queries (get all keys between X and Y)
- You need first/last key operations

### 8. LinkedHashMap (The Ordered Map)

**Simple Explanation**: LinkedHashMap remembers the order you added entries (or access order).

**Real-World Analogy**: A browser history that remembers which pages you visited and in what order.

**How It Works**:
- Combines HashMap (fast lookup) with LinkedList (maintains order)
- Can track insertion order or access order

**Step-by-Step Example**:

```java
// Insertion order (default)
LinkedHashMap<String, String> capitals = new LinkedHashMap<>();
capitals.put("USA", "Washington D.C.");
capitals.put("UK", "London");
capitals.put("France", "Paris");

// Maintains insertion order
System.out.println(capitals.keySet());
// [USA, UK, France]

// Access order (for LRU cache)
LinkedHashMap<String, String> cache = new LinkedHashMap<>(16, 0.75f, true);
cache.put("A", "Value A");
cache.put("B", "Value B");
cache.get("A");  // Access A - moves to end

// Order: [B, A] - A moved to end because accessed
```

**When to Use**:
- You need fast lookup
- You need to maintain insertion order
- Building an LRU cache (with accessOrder=true)

## Part 5: Advanced Collections

### 9. ConcurrentHashMap (Thread-Safe Map)

**Simple Explanation**: ConcurrentHashMap is like HashMap but safe to use when multiple threads access it at the same time.

**Real-World Analogy**: A library with multiple librarians. Each librarian can help different customers simultaneously without interfering with each other.

**The Problem with HashMap in Multi-threading**:

```java
// DANGER: HashMap is NOT thread-safe!
HashMap<String, Integer> map = new HashMap<>();

// Thread 1: map.put("A", 1);
// Thread 2: map.put("B", 2);
// Result: Data corruption, infinite loops, or crashes!
```

**How ConcurrentHashMap Solves This**:

**JDK 7 Approach**: Divided map into 16 segments. Each segment has its own lock. Threads can write to different segments simultaneously.

**JDK 8+ Approach**: Uses CAS (Compare-And-Swap) and locks only the specific bucket being modified. Much faster!

<SafeImage 
  src="/images/csi247/concurrenthashmap-segments.png" 
  alt="ConcurrentHashMap Segments" 
  caption="Figure 8: ConcurrentHashMap allows multiple threads to write simultaneously by locking only specific buckets" 
  className="max-w-full h-auto"
/>

**Step-by-Step Example**:

```java
ConcurrentHashMap<String, Integer> wordCount = new ConcurrentHashMap<>();

// Multiple threads can safely update
ExecutorService executor = Executors.newFixedThreadPool(10);

for (int i = 0; i < 10; i++) {
    executor.submit(() -> {
        wordCount.merge("hello", 1, Integer::sum);
    });
}

// All threads complete safely
executor.shutdown();
System.out.println(wordCount.get("hello"));  // 10
```

**Speed Comparison**:

| Operation | Speed | Why? |
|-----------|-------|------|
| **Get** | O(1) - Fast | No locking needed for reads |
| **Put** | O(1) - Fast | Locks only specific bucket |
| **Remove** | O(1) - Fast | Locks only specific bucket |

**When to Use**:
- Multiple threads access the map
- High concurrency needed
- Better performance than synchronized HashMap

**Code Example**:
```java
// Thread-safe word count
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

// Safe even with multiple threads
map.putIfAbsent("key", 0);  // Only put if not exists
map.compute("key", (k, v) -> v + 1);  // Atomic update
map.merge("key", 1, Integer::sum);  // Atomic merge
```

### 10. CopyOnWriteArrayList (Thread-Safe List)

**Simple Explanation**: CopyOnWriteArrayList creates a new copy of the list every time you modify it. Safe for reading while writing.

**Real-World Analogy**: A photo album. When you want to add a photo, you make a copy of the entire album, add the photo to the copy, then replace the old album with the new one. Meanwhile, people can still look at the old album.

**How It Works**:
1. To add/remove: Create a copy of the entire array
2. Modify the copy
3. Replace the old array reference with the new one
4. Readers always see a consistent snapshot

**When to Use**:
- Many reads, few writes
- Iterating while modifying
- Listener lists (event handlers)

**Code Example**:
```java
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();

// Safe to iterate while modifying
for (String item : list) {
    list.add("new item");  // Safe! Doesn't affect current iteration
}
```

## Part 6: Special Features

### Fail-Fast vs Fail-Safe Iterators

**Fail-Fast Iterator**:

**Simple Explanation**: If you modify the collection while iterating, it immediately throws an error.

**Example**:
```java
List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));

// WRONG: Throws ConcurrentModificationException
for (String s : list) {
    if (s.equals("B")) {
        list.remove(s);  // CRASH! Modifying while iterating
    }
}

// RIGHT: Use iterator's remove method
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("B")) {
        it.remove();  // Safe! Iterator knows about removal
    }
}
```

**Fail-Safe Iterator**:

**Simple Explanation**: Works on a copy of the collection, so modifications don't affect iteration.

**Example**:
```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.put("A", 1);
map.put("B", 2);

// Safe to modify while iterating
for (String key : map.keySet()) {
    map.put("C", 3);  // No exception! Works on snapshot
}
```

### LRU Cache with LinkedHashMap

**Simple Explanation**: LRU (Least Recently Used) cache automatically removes the oldest unused item when full.

**Real-World Example**: Browser cache - keeps recently visited pages, removes old ones when space is needed.

**Implementation**:

```java
public class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        // accessOrder = true: Move accessed items to end (most recently used)
        super(capacity, 0.75f, true);
        this.capacity = capacity;
    }

    // Called after every put()
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        // Remove oldest entry if size exceeds capacity
        return size() > capacity;
    }
}

// Usage
LRUCache<String, String> cache = new LRUCache<>(3);
cache.put("A", "Value A");
cache.put("B", "Value B");
cache.put("C", "Value C");
cache.get("A");  // Access A - moves to end (most recently used)
cache.put("D", "Value D");  // Removes B (least recently used)

// Result: {A, C, D} - B was removed
```

## Summary

**Lists** (ordered, allows duplicates):
- **ArrayList**: Fast access, use 90% of the time
- **LinkedList**: Fast insert/delete in middle

**Sets** (unique items):
- **HashSet**: Fastest, random order
- **TreeSet**: Sorted order
- **LinkedHashSet**: Insertion order

**Maps** (key-value pairs):
- **HashMap**: Fastest, random order
- **TreeMap**: Sorted by key
- **LinkedHashMap**: Insertion/access order
- **ConcurrentHashMap**: Thread-safe

**Key Principles**:
1. Choose based on your needs (speed, order, uniqueness)
2. Use ArrayList and HashMap for most cases
3. Use concurrent collections for multi-threading
4. Understand tradeoffs (speed vs memory vs features)

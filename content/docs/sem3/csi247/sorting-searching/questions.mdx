# Practice Questions: Sorting & Searching

<ExamQuestion title="Question 1: Custom Multi-Key Sorting [12 Marks]">
  <SubQuestion part="a" prompt={<>Write a <code>Comparator&lt;Flight&gt;</code> sorting by destination (A-Z), then departureTime (descending), then price (ascending). [6]</>} solution={<>Chain comparators: <code>Comparator.comparing(Flight::getDest).thenComparing(Flight::getTime, Comparator.reverseOrder()).thenComparingDouble(Flight::getPrice)</code>.</>} />
  <SubQuestion part="b" prompt={<>Implement the <code>merge()</code> function of Merge Sort utilizing this custom Comparator. [6]</>} solution={<>Standard merge logic, but replace <code>arr[i] &lt;= arr[j]</code> with <code>comparator.compare(arr[i], arr[j]) &lt;= 0</code>.</>} />
</ExamQuestion>

<ExamQuestion title="Question 2: Rotated Array Binary Search [10 Marks]">
  <SubQuestion part="a" prompt={<>Write an O(log N) algorithm to find a target string in a lexicographically sorted but rotated array. [7]</>} solution={<>Find the pivot (minimum element) using binary search. Then determine which sorted half the target belongs to and run standard binary search on that half.</>} />
  <SubQuestion part="b" prompt={<>How does it handle duplicates like [banana, apple, banana, banana]? Does it guarantee O(log N)? [3]</>} solution={<>No. With duplicates, you cannot reliably determine which half is sorted when arr[mid] == arr[high]. You must decrement high linearly, degrading worst-case to O(N).</>} />
</ExamQuestion>

<ExamQuestion title="Question 3: Quick Sort Worst-Case Mitigation [10 Marks]">
  <SubQuestion part="a" prompt={<>Implement Median-of-Three pivot selection. Find median of low, mid, high, swap to high, return it. [6]</>} solution={<>Compare the three elements, sort them logically, and place the middle value at the high index.</>} />
  <SubQuestion part="b" prompt={<>Trace partitioning on [45, 12, 89, 33, 77, 21, 50] using Median-of-Three. [4]</>} solution={<>Low=45, Mid=33, High=50. Median is 45. Swap 45 to end. Array becomes [12, 33, 21, 50, 77, 89, 45]. Partition around 45.</>} />
</ExamQuestion>

<ExamQuestion title="Question 4: Radix Sort vs Comparison Sorts [8 Marks]">
  <SubQuestion part="a" prompt={<>Explain LSD Radix Sort for 10 million 9-digit IDs. Time complexity in terms of N and D? [5]</>} solution={<>Sort by least significant digit using Counting Sort as a stable subroutine. Repeat D times. Time: O(D * (N + k)) where k is base 10.</>} />
  <SubQuestion part="b" prompt={<>Why is Radix theoretically faster here despite similar Big-O? [3]</>} solution={<>D is a small constant (9). Comparison sorts have a hidden constant factor for object comparisons and memory indirection, whereas Radix uses simple integer math and sequential memory access.</>} />
</ExamQuestion>

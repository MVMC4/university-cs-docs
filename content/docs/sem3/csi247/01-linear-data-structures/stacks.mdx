## 1.3 Stacks

A Stack is a restricted linear structure enforcing a strict Last-In-First-Out (LIFO) access pattern. It is the foundational mechanism for recursion, parsing, and depth-first exploration.

<HighlightCard
  variant="neutral"
  title="Definition 1.3.1: LIFO Architecture & Bounds"
  description="Elements are added and removed exclusively from the 'top'."
>

- **Push:** Adds an element to the top.
- **Pop:** Removes and returns the top element.
- **Stack Overflow:** Attempting to push onto a full array-based stack (exceeding allocated bounds).
- **Stack Underflow:** Attempting to pop from an empty stack (violating structural integrity).

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 1.3.1: Call Stack Execution & Recursive Unwinding"
  description="How the JVM uses a stack to manage method invocations and memory."
>

Every time a method is invoked, the JVM pushes an **Activation Record** (stack frame) onto the Call Stack. This frame stores:
1. Local variables and parameters.
2. The return address (where to resume execution upon completion).
When a method returns, its frame is popped, and execution resumes at the stored return address. This mechanical push/pop cycle is what makes **recursive unwinding** possible, allowing base cases to propagate computed results back up the chain of callers.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Lab Scenario: Infix to Postfix Conversion (Shunting-Yard)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Logic</StepTitle>
    Stacks are used to temporarily hold operators while waiting for their operands, strictly respecting mathematical precedence and associativity rules. Operands are immediately sent to the output queue.
  </Step>

  <Step number={2}>
    <StepTitle>Trace Example: `A + B * C - D`</StepTitle>
    - Read `A`: Output `A`.
    - Read `+`: Push `+` to stack. Stack: `[+]`
    - Read `B`: Output `B`.
    - Read `*`: `*` has higher precedence than `+`. Push `*`. Stack: `[+, *]`
    - Read `C`: Output `C`.
    - Read `-`: `-` has lower precedence than `*`. Pop `*` to output. `-` has equal precedence to `+` (left-associative). Pop `+` to output. Push `-`. Stack: `[-]`
    - Read `D`: Output `D`.
    - End of expression: Pop remaining stack. Pop `-`.
  </Step>

  <Step number={3}>
    <StepTitle>Final Postfix Result</StepTitle>
    `A B C * + D -` (Evaluates unambiguously as $((A + (B \times C)) - D)$).
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="Exam Concept: Balanced Parenthesis Matching"
  description="Using a stack to validate structural integrity."
>

To check if an expression like `{[()]}` is balanced:
1. Push opening brackets `(`, `{`, `[` onto the stack.
2. When encountering a closing bracket, pop the stack. If the stack is empty (Underflow) or the popped bracket does not match the closing bracket type, the expression is invalid.
3. At the end of the string, the stack must be completely empty.

</HighlightCard>

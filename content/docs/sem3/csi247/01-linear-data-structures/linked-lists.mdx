## 1.2 Linked Lists

Linked lists abandon the constraint of contiguous memory in favor of scattered heap allocations connected via pointers. This allows for dynamic sizing and $O(1)$ structural modifications, but imposes strict sequential access constraints.

<HighlightCard
  variant="neutral"
  title="Definition 1.2.1: Node Architecture & Null Termination"
  description="The fundamental building block of linked structures."
>

A **Node** is a composite data structure containing:
1. **Payload:** The data value.
2. **Pointer(s):** Memory addresses referencing the next (and optionally previous) node.
- **Head Reference:** The singular entry point to the entire sequence.
- **Null Termination:** The final node's forward pointer is explicitly set to `null`, signaling the absolute boundary of the sequence.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 1.2.1: Sequential Access Constraints"
  description="The mathematical impossibility of $O(1)$ random access in linked structures."
>

Unlike arrays, linked lists lack a mathematical indexing formula because nodes are scattered arbitrarily across the heap. To access the $k$-th element, the CPU **must** sequentially traverse $k$ pointers starting from the head.
**Time Complexity of Access:** $O(k)$, which degrades to strictly $O(n)$ in the worst case.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Lab Scenario: Counting Internal Nodes (Exam Classic)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Problem</StepTitle>
    Write a method that traverses a singly linked list and returns the total count of *internal* nodes, strictly **excluding** the first (head) and last (tail) nodes.
  </Step>

  <Step number={2}>
    <StepTitle>The Edge Cases</StepTitle>
    If the list is empty (`head == null`), has only 1 node (`head.next == null`), or has exactly 2 nodes, the count of strictly internal nodes is `0`.
  </Step>

  <Step number={3}>
    <StepTitle>The Implementation</StepTitle>
    ```java
    public int countInternalNodes() {
        // Handle 0 or 1 node lists
        if (head == null || head.next == null) {
            return 0; 
        }
        
        int count = 0;
        Node current = head.next; // Skip the head node
        
        // Traverse until we hit the LAST node (where current.next is null)
        while (current.next != null) {
            count++;
            current = current.next;
        }
        
        return count;
    }
    ```
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Required Skill: Safe Pointer Severing & Reconnecting</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Insertion Logic (After `currentNode`)</StepTitle>
    To insert a `newNode` safely without orphaning the remainder of the list:
    1. `newNode.next = currentNode.next;` (Bridge the new node to the rest of the chain)
    2. `currentNode.next = newNode;` (Sever the old link and connect current to new)
    *Fatal Error:* Reversing these steps will overwrite `currentNode.next` before it can be bridged, permanently orphaning the rest of the list.
  </Step>

  <Step number={2}>
    <StepTitle>Deletion Logic (Bypassing `targetNode`)</StepTitle>
    Assuming we hold a reference to `prevNode`:
    1. `prevNode.next = targetNode.next;` (Bypass the target entirely)
    2. `targetNode.next = null;` (Sever target's forward link to assist the Garbage Collector)
  </Step>
</StepByStep>

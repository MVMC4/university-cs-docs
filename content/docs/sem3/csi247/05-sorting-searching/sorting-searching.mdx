# Searching and Sorting Algorithms

Welcome to your complete guide to searching and sorting! We'll start simple and build up to advanced algorithms.

> **Why Learn This?** 
> Imagine finding a name in a phone book with 1 million entries:
> - **Without sorting**: Check every name → 1 million checks (takes hours!)
> - **With sorting + binary search**: Only 20 checks (takes seconds!)
> 
> That's the power of good algorithms!

---

## Part 1: Searching - Finding What You Need

### What is Searching?

Searching means finding a specific item in a collection. Like finding:
- A contact in your phone
- A word in a dictionary
- A product on Amazon

There are two main ways to search:

---

### 1. Linear Search (The Simple Way)

**Simple Explanation**: Check every item one by one until you find what you're looking for.

**Real-World Example**: Looking for your keys by checking every room in your house one by one.

**How It Works**:
1. Start from the first item
2. Is this what I'm looking for? 
   - Yes → Found it! 
   - No → Move to the next item
3. Repeat until found or no more items

**Step-by-Step Example**:
Find the number `7` in `[3, 5, 7, 9, 11]`

```
Step 1: Check position 0 → Is 3 = 7? No
Step 2: Check position 1 → Is 5 = 7? No
Step 3: Check position 2 → Is 7 = 7? YES! Found at position 2
```

**Code**:
```java
public int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) {
            return i;  // Found it!
        }
    }
    return -1;  // Not found
}
```

**Speed**:
- **Best case**: 1 check (item is first)
- **Worst case**: n checks (item is last or not there)
- **Average**: n/2 checks

**When to use**:
- Small lists (less than 50 items)
- List is not sorted
- You only search once

---

### 2. Binary Search (The Fast Way)

**Simple Explanation**: Instead of checking every item, cut the search space in half each time. Like looking up a word in a dictionary - you don't start from page 1, you open to the middle and go forward or backward.

**Real-World Example**: Guessing a number between 1-100. You'd say "50" first, then based on "higher" or "lower", you'd say "25" or "75", cutting the range in half each time.

**Important**: The list MUST be sorted first!

**How It Works**:
1. Look at the middle item
2. Is it what I want?
   - Yes → Found it!
   - No → Is my target smaller or larger?
     - Smaller → Search the left half
     - Larger → Search the right half
3. Repeat with the half you chose

**Step-by-Step Example**:
Find `23` in sorted array `[2, 5, 8, 12, 16, 23, 38, 45, 56, 67, 78]`

```
Array has 11 items, indices 0 to 10

Step 1: Middle is at index 5 → arr[5] = 23
        Is 23 = 23? YES! Found in 1 step!
        
Example 2: Find 16
Step 1: Middle is index 5 → arr[5] = 23
        Is 16 = 23? No
        Is 16 < 23? Yes → Search left half [2, 5, 8, 12, 16]
        
Step 2: New middle is index 2 → arr[2] = 8
        Is 16 = 8? No
        Is 16 > 8? Yes → Search right half [12, 16]
        
Step 3: New middle is index 3 → arr[3] = 12
        Is 16 = 12? No
        Is 16 > 12? Yes → Search right
        
Step 4: Only one item left → arr[4] = 16
        Found it in 4 steps!
```

<SafeImage 
  src="/images/sem3/csi247/05-sorting-searching/binary-search-simple.png" 
  alt="Binary Search Visualization" 
  caption="Figure 2: Binary search cuts the search space in half each time - much faster!" 
  className="max-w-full h-auto"

**Code**:
```java
public int binarySearch(int[] arr, int target) {
    int left = 0;
    int right = arr.length - 1;
    
    while (left <= right) {
        // Find middle (safe from overflow)
        int mid = left + (right - left) / 2;
        
        if (arr[mid] == target) {
            return mid;  // Found!
        }
        
        if (arr[mid] < target) {
            left = mid + 1;  // Search right half
        } else {
            right = mid - 1;  // Search left half
        }
    }
    
    return -1;  // Not found
}
```

**Speed Comparison**:

| Array Size | Linear Search | Binary Search |
|------------|---------------|---------------|
| 10 items | Up to 10 checks | Up to 4 checks |
| 100 items | Up to 100 checks | Up to 7 checks |
| 1,000 items | Up to 1,000 checks | Up to 10 checks |
| 1,000,000 items | Up to 1M checks | Up to 20 checks |
| 1,000,000,000 items | Up to 1B checks | Up to 30 checks |

**Binary search is incredibly fast!** Even with 1 billion items, it only takes 30 checks!

**When to use**:
- List is sorted
- Large datasets
- You search many times

## Part 2: Sorting - Organizing Your Data

### What is Sorting?

Sorting means arranging items in a specific order (usually ascending or descending).

**Why Sort?**
- Makes searching faster (binary search needs sorted data)
- Easier to find duplicates
- Required for many algorithms
- Makes data easier to understand

**Common Types of Sorting**:
1. **Ascending**: Smallest to largest `[1, 2, 3, 4, 5]`
2. **Descending**: Largest to smallest `[5, 4, 3, 2, 1]`
3. **Alphabetical**: A to Z `[Apple, Banana, Cherry]`

---

### Simple Sorting Algorithms (Easy to Understand)

These are slower but easier to learn. Good for small lists.

---

### 1. Bubble Sort

**Simple Explanation**: Repeatedly swap adjacent items if they're in the wrong order. Larger items "bubble" to the end like bubbles rising in water.

**Real-World Analogy**: Imagine students lining up by height. Each student compares with the person next to them and swaps if needed. After one pass, the tallest student is at the end. Repeat until everyone is in order.

**How It Works**:
1. Compare first two items
2. Are they in the right order?
   - No → Swap them
   - Yes → Leave them
3. Move to the next pair
4. After one pass, the largest item is at the end
5. Repeat until no swaps needed

**Step-by-Step Example**:
Sort `[5, 1, 4, 2, 8]` from smallest to largest

```
Pass 1:
Compare 5 and 1 → 5 > 1, so SWAP → [1, 5, 4, 2, 8]
Compare 5 and 4 → 5 > 4, so SWAP → [1, 4, 5, 2, 8]
Compare 5 and 2 → 5 > 2, so SWAP → [1, 4, 2, 5, 8]
Compare 5 and 8 → 5 < 8, NO SWAP → [1, 4, 2, 5, 8]
Result after Pass 1: [1, 4, 2, 5, 8]
(5 is now in the correct position at the end)

Pass 2:
Compare 1 and 4 → 1 < 4, NO SWAP → [1, 4, 2, 5, 8]
Compare 4 and 2 → 4 > 2, so SWAP → [1, 2, 4, 5, 8]
Compare 4 and 5 → 4 < 5, NO SWAP → [1, 2, 4, 5, 8]
Result after Pass 2: [1, 2, 4, 5, 8]

Pass 3:
Compare 1 and 2 → NO SWAP
Compare 2 and 4 → NO SWAP
No swaps needed → Array is sorted!

Final: [1, 2, 4, 5, 8]
```

  caption="Figure 3: Bubble Sort - larger elements bubble to the end with each pass" 
  className="max-w-full h-auto"

**Code**:
```java
public void bubbleSort(int[] arr) {
    int n = arr.length;
    boolean swapped;
    
    for (int i = 0; i < n - 1; i++) {
        swapped = false;
        
        // Compare adjacent elements
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                // Swap if wrong order
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        
        // If no swaps, array is sorted
        if (!swapped) break;
    }
}
```

**Speed**: 
- **Best case**: O(n) - already sorted
- **Average/Worst case**: O(n²) - very slow for large lists

**When to use**: 
- Learning purposes only
- Very small lists (less than 20 items)
- Almost sorted data

---

### 2. Selection Sort

**Simple Explanation**: Find the smallest item and put it at the beginning. Then find the next smallest and put it in the second position. Repeat.

**Real-World Analogy**: Picking the shortest student from a group and putting them first in line. Then picking the next shortest from the remaining students, and so on.

**How It Works**:
1. Find the smallest item in the entire list
2. Swap it with the first item
3. Find the smallest item in the remaining list
4. Swap it with the second item
5. Repeat until sorted

**Step-by-Step Example**:
Sort `[64, 25, 12, 22, 11]`

```
Pass 1: Find smallest in [64, 25, 12, 22, 11]
        Smallest is 11 (at position 4)
        Swap 11 with 64 (first position)
        Result: [11, 25, 12, 22, 64]
        Sorted part: [11]

Pass 2: Find smallest in [25, 12, 22, 64]
        Smallest is 12 (at position 2)
        Swap 12 with 25 (second position)
        Result: [11, 12, 25, 22, 64]
        Sorted part: [11, 12]

Pass 3: Find smallest in [25, 22, 64]
        Smallest is 22 (at position 3)
        Swap 22 with 25 (third position)
        Result: [11, 12, 22, 25, 64]
        Sorted part: [11, 12, 22]

Pass 4: Find smallest in [25, 64]
        Smallest is 25 (already in position)
        No swap needed
        Result: [11, 12, 22, 25, 64]
        
Final: [11, 12, 22, 25, 64] - Sorted!
```

<SafeImage 
  src="/images/sem3/csi247/05-sorting-searching/selection-sort-visual.png" 
  alt="Selection Sort Visualization" 
  caption="Figure 4: Selection Sort - finds the minimum element and places it at the beginning" 
  className="max-w-full h-auto"
/>

**Code**:
```java
public void selectionSort(int[] arr) {
    int n = arr.length;
    
    for (int i = 0; i < n - 1; i++) {
        // Find the minimum element in unsorted part
        int minIdx = i;
        
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        
        // Swap the found minimum with first element
        int temp = arr[minIdx];
        arr[minIdx] = arr[i];
        arr[i] = temp;
    }
}
```

**Speed**: 
- **Always**: O(n²) - slow for large lists

**When to use**: 
- Small lists (less than 50 items)
- When you want to minimize the number of swaps
- Simple implementation needed

### 3. Insertion Sort

**Simple Explanation**: Build the sorted list one item at a time. Take each item and insert it in the correct position among the already-sorted items.

**Real-World Analogy**: Sorting playing cards in your hand. You pick up one card at a time and insert it in the correct position among the cards you're already holding.

**How It Works**:
1. Start with the second item (first item is already "sorted")
2. Compare it with items before it
3. Shift larger items one position to the right
4. Insert the current item in the correct position
5. Move to the next item and repeat

**Step-by-Step Example**:
Sort `[12, 11, 13, 5, 6]`

```
Initial: [12, 11, 13, 5, 6]
         ^
         First item (12) is considered sorted

Step 1: Pick 11 (second item)
        Compare 11 < 12? Yes
        Shift 12 right: [12, 12, 13, 5, 6]
        Insert 11: [11, 12, 13, 5, 6]
        Sorted part: [11, 12]

Step 2: Pick 13 (third item)
        Compare 13 < 12? No
        13 is already in correct position
        Result: [11, 12, 13, 5, 6]
        Sorted part: [11, 12, 13]

Step 3: Pick 5 (fourth item)
        Compare 5 < 13? Yes, shift 13 right
        Compare 5 < 12? Yes, shift 12 right
        Compare 5 < 11? Yes, shift 11 right
        Insert 5: [5, 11, 12, 13, 6]
        Sorted part: [5, 11, 12, 13]

Step 4: Pick 6 (fifth item)
        Compare 6 < 13? Yes, shift 13 right
        Compare 6 < 12? Yes, shift 12 right
        Compare 6 < 11? Yes, shift 11 right
        Compare 6 < 5? No
        Insert 6: [5, 6, 11, 12, 13]
        
Final: [5, 6, 11, 12, 13] - Sorted!
```

<SafeImage 
  src="/images/sem3/csi247/05-sorting-searching/insertion-sort-visual.png" 
  alt="Insertion Sort Visualization" 
  caption="Figure 5: Insertion Sort - builds the sorted array one element at a time, like sorting cards in your hand" 
  className="max-w-full h-auto"
/>

**Code**:
```java
public void insertionSort(int[] arr) {
    int n = arr.length;
    
    for (int i = 1; i < n; i++) {
        int key = arr[i];  // Current element to insert
        int j = i - 1;
        
        // Move elements greater than key one position ahead
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        
        // Insert key at correct position
        arr[j + 1] = key;
    }
}
```

**Speed**: 
- **Best case**: O(n) - already sorted
- **Average/Worst case**: O(n²)

**When to use**: 
- Small lists (less than 50 items)
- Nearly sorted data (very fast in this case!)
- Online sorting (data arrives one at a time)

**Advantage**: Very fast for nearly sorted data!

### Advanced Sorting Algorithms (Fast and Efficient)

These are faster but more complex. Used in real applications.

---

### 4. Merge Sort

**Simple Explanation**: Divide the list in half, sort each half, then merge the two sorted halves back together.

**Real-World Analogy**: You have a messy deck of cards. Split it in half, give one half to a friend to sort, sort your half, then merge the two sorted halves together.

**How It Works**:
1. **Divide**: Split the list in half
2. **Conquer**: Sort each half (recursively)
3. **Combine**: Merge the two sorted halves

**Step-by-Step Example**:
Sort `[38, 27, 43, 3, 9, 82, 10]`

```
DIVIDE PHASE:
[38, 27, 43, 3, 9, 82, 10]
        ↓ Split in half
[38, 27, 43, 3]        [9, 82, 10]
    ↓                      ↓
[38, 27]    [43, 3]    [9, 82]    [10]
  ↓          ↓          ↓         ↓
[38] [27]  [43] [3]   [9] [82]  [10]
(Now each piece has 1 element - already sorted!)

MERGE PHASE:
Merge [38] and [27] → [27, 38]
Merge [43] and [3] → [3, 43]
Merge [9] and [82] → [9, 82]
[10] stays as [10]

Now merge pairs:
Merge [27, 38] and [3, 43]:
  Compare 27 vs 3 → Take 3
  Compare 27 vs 43 → Take 27
  Compare 38 vs 43 → Take 38
  Take remaining 43
  Result: [3, 27, 38, 43]

Merge [9, 82] and [10]:
  Compare 9 vs 10 → Take 9
  Compare 82 vs 10 → Take 10
  Take remaining 82
  Result: [9, 10, 82]

Final merge:
Merge [3, 27, 38, 43] and [9, 10, 82]:
  Compare 3 vs 9 → Take 3
  Compare 27 vs 9 → Take 9
  Compare 27 vs 10 → Take 10
  Compare 27 vs 82 → Take 27
  Compare 38 vs 82 → Take 38
  Compare 43 vs 82 → Take 43
  Take remaining 82
  Result: [3, 9, 10, 27, 38, 43, 82]

Final: [3, 9, 10, 27, 38, 43, 82] - Sorted!
```

**Code**:
```java
public void mergeSort(int[] arr, int left, int right) {
    if (left < right) {
        // Find middle point
        int mid = left + (right - left) / 2;
        
        // Sort left half
        mergeSort(arr, left, mid);
        
        // Sort right half
        mergeSort(arr, mid + 1, right);
        
        // Merge the sorted halves
        merge(arr, left, mid, right);
    }
}

private void merge(int[] arr, int left, int mid, int right) {
    // Create temporary arrays
    int n1 = mid - left + 1;
    int n2 = right - mid;
    
    int[] L = new int[n1];
    int[] R = new int[n2];
    
    // Copy data to temporary arrays
    for (int i = 0; i < n1; i++)
        L[i] = arr[left + i];
    for (int j = 0; j < n2; j++)
        R[j] = arr[mid + 1 + j];
    
    // Merge the temporary arrays back
    int i = 0, j = 0, k = left;
    
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) {
            arr[k] = L[i];
            i++;
        } else {
            arr[k] = R[j];
            j++;
        }
        k++;
    }
    
    // Copy remaining elements
    while (i < n1) {
        arr[k] = L[i];
        i++;
        k++;
    }
    
    while (j < n2) {
        arr[k] = R[j];
        j++;
        k++;
    }
}
```

**Speed**: 
- **Always**: O(n log n) - fast and consistent!

**When to use**: 
- Need guaranteed fast performance
- Stable sort required (preserves order of equal elements)
- Sorting linked lists
- External sorting (data doesn't fit in memory)

**Advantages**: 
- Always O(n log n) - never slows down
- Stable sort
- Good for large datasets

**Disadvantages**: 
- Needs extra memory O(n)
- Slower than QuickSort in practice

### 5. Quick Sort

**Simple Explanation**: Pick a "pivot" element, put all smaller elements to the left and all larger elements to the right, then repeat on the left and right parts.

**Real-World Analogy**: Organizing books on a shelf. Pick one book as a pivot (say, "M"). Put all books A-L to the left, and all books N-Z to the right. Then repeat the process on each side.

**How It Works**:
1. **Pick a pivot** (usually last or middle element)
2. **Partition**: Rearrange so smaller elements are left, larger are right
3. **Recursively sort** the left and right parts

**Step-by-Step Example**:
Sort `[10, 7, 8, 9, 1, 5]` using last element as pivot

```
Initial: [10, 7, 8, 9, 1, 5]
         Pivot = 5 (last element)

PARTITION:
We want: [elements < 5] [5] [elements > 5]

Start: [10, 7, 8, 9, 1, 5]
       ↑
       i (tracks position for smaller elements)
       
j scans from left to right:

j=0: arr[0]=10, is 10 < 5? No, don't move
j=1: arr[1]=7, is 7 < 5? No, don't move
j=2: arr[2]=8, is 8 < 5? No, don't move
j=3: arr[3]=9, is 9 < 5? No, don't move
j=4: arr[4]=1, is 1 < 5? YES!
     Swap with arr[i] (which is arr[0]=10)
     Result: [1, 7, 8, 9, 10, 5]
     i moves to position 1

After scanning, swap pivot (5) with arr[i] (7):
Result: [1, 5, 8, 9, 10, 7]

Now 5 is in correct position!
Left of 5: [1] (all smaller)
Right of 5: [8, 9, 10, 7] (all larger)

Now recursively sort left and right:
Left [1]: Already sorted (1 element)
Right [8, 9, 10, 7]: 
  Pivot = 7
  Partition: [7, 9, 10, 8]
  7 is in correct position
  Left: [] (empty)
  Right: [9, 10, 8]
  
  Sort [9, 10, 8]:
  Pivot = 8
  Partition: [8, 10, 9]
  8 is in correct position
  Right: [10, 9]
  
  Sort [10, 9]:
  Pivot = 9
  Partition: [9, 10]
  Done!

Final: [1, 5, 7, 8, 9, 10] - Sorted!
```

```java
public void quickSort(int[] arr, int low, int high) {
    if (low < high) {
        // Partition and get pivot index
        int pi = partition(arr, low, high);
        
        // Recursively sort elements before and after partition
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

private int partition(int[] arr, int low, int high) {
    // Choose rightmost element as pivot
    int pivot = arr[high];
    int i = low - 1;  // Index of smaller element
    
    for (int j = low; j < high; j++) {
        // If current element is smaller than pivot
        if (arr[j] < pivot) {
            i++;
            // Swap arr[i] and arr[j]
            int temp = arr[i];
            arr[i] = arr[j];
            arr[j] = temp;
        }
    }
    
    // Swap pivot with element at i+1
    int temp = arr[i + 1];
    arr[i + 1] = arr[high];
    arr[high] = temp;
    
    return i + 1;  // Return pivot's position
}
```

**Speed**: 
- **Best/Average case**: O(n log n) - very fast!
- **Worst case**: O(n²) - rare (happens when array is already sorted)

**When to use**: 
- General purpose sorting (fastest on average)
- Large datasets
- Memory is limited (in-place sorting)

**Advantages**: 
- Very fast in practice (2-3x faster than MergeSort)
- In-place (doesn't need extra memory)
- Cache-friendly

**Disadvantages**: 
- Worst case O(n²) (but rare with good pivot selection)
- Not stable
- Recursive (can cause stack overflow for very large arrays)

### 6. Heap Sort

**Simple Explanation**: Build a special tree structure called a "heap" where the largest element is always at the top. Repeatedly remove the top element and rebuild the heap.

**Real-World Analogy**: Imagine a priority queue at a hospital. The most critical patient is always at the front. After treating them, the next most critical moves to the front.

**How It Works**:
1. **Build a max heap** (tree where parent ≥ children)
2. **Swap** the root (largest) with the last element
3. **Reduce heap size** and restore heap property
4. **Repeat** until heap is empty

**Speed**: 
- **Always**: O(n log n)

**When to use**: 
- Need guaranteed O(n log n)
- Limited memory (in-place)
- Finding k largest/smallest elements

### Which One Should You Choose?

**For small lists (n < 50)**:
- Use **Insertion Sort** - simple and fast for small data

**For large lists**:
- Use **QuickSort** - fastest on average
- Use **MergeSort** - if you need guaranteed speed
- Use **HeapSort** - if memory is limited

**For nearly sorted data**:
- Use **Insertion Sort** - almost O(n) speed!

**For learning**:
- Start with **Bubble Sort** - easiest to understand
- Then **Selection Sort** - simple concept
- Then **Insertion Sort** - practical for small data
- Finally **MergeSort/QuickSort** - real-world algorithms

## Part 4: Real-World Applications

### Where Are These Used?

**1. Databases**
- **B-Tree indexes** use binary search for fast lookups
- **Sorting** for ORDER BY queries

**2. Search Engines**
- **Binary search** in inverted indexes
- **Merge sort** to combine search results

**3. E-Commerce**
- **Sorting** products by price, rating, etc.
- **Binary search** for price range filters

**4. Operating Systems**
- **Priority queues** (heap sort) for task scheduling
- **Sorting** files by name, date, size

**5. Games**
- **Sorting** high scores
- **Spatial sorting** for collision detection

## Summary

**Searching**:
- **Linear Search**: Simple, O(n), for small/unsorted data
- **Binary Search**: Fast, O(log n), requires sorted data

**Sorting**:
- **Simple sorts** (Bubble, Selection, Insertion): O(n²), easy to learn
- **Advanced sorts** (Merge, Quick, Heap): O(n log n), used in practice

**Key Takeaways**:
1. Always sort your data if you need to search it many times
2. Use built-in sorting functions in real code
3. Understand these algorithms to choose the right tool
4. Practice implementing them to understand how they work

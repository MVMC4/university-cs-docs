# Sorting Algorithms

Sorting is the act of rearranging a collection into a defined order. It is a prerequisite for Binary Search, and understanding sorting complexity is the foundation of algorithmic analysis.

## Algorithm Complexity — The Full Picture

Before diving into implementations, know what you are aiming for:

<CaseAnalysis title="Sorting Algorithm Complexity Reference">
  <Case
    condition="Simple Algorithms  --  O(n^2)"
    explanation="Bubble, Selection, and Insertion Sort all have quadratic worst-case complexity. They are simple to implement and have low overhead, making them competitive on small or nearly-sorted arrays."
  >
    | Algorithm | Best | Average | Worst | Space | Stable? |
    |---|---|---|---|---|---|
    | Bubble Sort | O(n) | O(n^2) | O(n^2) | O(1) | ✅ Yes |
    | Selection Sort | O(n^2) | O(n^2) | O(n^2) | O(1) | ❌ No |
    | Insertion Sort | **O(n)** | O(n^2) | O(n^2) | O(1) | ✅ Yes |

    **Key insight:** Insertion Sort's O(n) best-case makes it the winner for nearly-sorted data. It is used internally by Java's `Arrays.sort()` for small arrays (n &lt; 7).
  </Case>
  <Case
    condition="Efficient Algorithms  --  O(n log n)"
    explanation="Merge Sort, Quick Sort, and Heap Sort all achieve O(n log n) average complexity  --  provably optimal for comparison-based sorting. They differ critically in space usage and worst-case behaviour."
  >
    | Algorithm | Best | Average | Worst | Space | Stable? |
    |---|---|---|---|---|---|
    | Merge Sort | O(n log n) | O(n log n) | O(n log n) | **O(n)** | ✅ Yes |
    | Quick Sort | O(n log n) | O(n log n) | **O(n^2)** | O(log n) | ❌ No |
    | Heap Sort | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ No |

    **Key insight:** Merge Sort is the only algorithm here that guarantees O(n log n) in ALL cases. Quick Sort's O(n^2) worst-case occurs when the pivot is always the minimum or maximum element (already-sorted input with naive pivot).
  </Case>
  <Case
    condition="The Lower Bound  --  Why We Cannot Do Better"
    explanation="Any sorting algorithm that works by comparing elements requires at least Omega(n log n) comparisons in the worst case. This is a mathematical proof, not a limitation of current algorithms."
  >
    **Proof sketch:** A comparison sort can be modelled as a decision tree. Sorting n elements has n! possible orderings. A binary tree with n! leaves has height at least log2(n!) ~ n log n (by Stirling's approximation). Therefore no comparison sort can do fewer than Omega(n log n) comparisons.

    Non-comparison sorts (Radix, Counting, Bucket) escape this bound by exploiting the structure of the data itself — but only work for specific data types (integers in a bounded range).
  </Case>
</CaseAnalysis>

## Simple Sorting Algorithms

### 1. Bubble Sort

Repeatedly compare adjacent pairs and swap if out of order. After each pass, the largest unsorted element "bubbles" to its correct position.

<InteractiveStepper>
  <StepperStep title="Pass 1: Bubble the largest element to the end">
    Array: **[5, 1, 4, 2, 8]**

    Compare 5,1 -> swap -> [1, 5, 4, 2, 8]

    Compare 5,4 -> swap -> [1, 4, 5, 2, 8]

    Compare 5,2 -> swap -> [1, 4, 2, 5, 8]

    Compare 5,8 -> no swap -> [1, 4, 2, 5, **8**] ✓ 8 is in place.
  </StepperStep>
  <StepperStep title="Pass 2: Bubble the second-largest">
    Array: **[1, 4, 2, 5, 8]** (ignore position 4)

    Compare 1,4 -> no swap

    Compare 4,2 -> swap -> [1, 2, 4, 5, 8]

    Compare 4,5 -> no swap -> [1, 2, 4, **5**, **8**] ✓ 5 in place.
  </StepperStep>
  <StepperStep title="Pass 3: No swaps  --  array is sorted">
    Array: **[1, 2, 4, 5, 8]** — no swaps needed. The `swapped` flag remains false. Algorithm terminates early.

    **Final: [1, 2, 4, 5, 8]** ✓
  </StepperStep>
</InteractiveStepper>

```java
public void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        if (!swapped) break; // Early termination — already sorted
    }
}
```

**Complexity:** O(n^2) worst/average · O(n) best (with `swapped` flag) · O(1) space · **Stable**

### 2. Selection Sort

Find the minimum of the unsorted region and swap it to its correct position. Performs exactly n-1 swaps regardless of input.

```java
public void selectionSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx]) minIdx = j;
        }
        int temp = arr[minIdx];
        arr[minIdx] = arr[i];
        arr[i] = temp;
    }
}
```

**Complexity:** O(n^2) all cases · O(1) space · **Not stable** (the swap can move equal elements past each other)

<Callout type="warn" title="Selection Sort has no early termination">
Unlike Bubble Sort, Selection Sort performs n(n-1)/2 comparisons even on a fully sorted array. Never use it when the data might already be sorted.
</Callout>

### 3. Insertion Sort

Build a sorted sub-array from left to right by inserting each new element into its correct position.

```java
public void insertionSort(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        int key = arr[i];
        int j = i - 1;
        // Shift elements greater than key one position right
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
}
```

**Complexity:** O(n) best · O(n^2) average/worst · O(1) space · **Stable**

<HighlightCard variant="success" title="When Insertion Sort Wins">
Insertion Sort outperforms Merge Sort and Quick Sort on small arrays (n &lt; ~16) because it has extremely low constant-factor overhead — no recursive calls, no auxiliary arrays. Java's `Arrays.sort()` switches from dual-pivot Quick Sort to Insertion Sort for sub-arrays smaller than 7 elements.
</HighlightCard>

## Advanced Sorting Algorithms

### 4. Merge Sort

Divide the array in half recursively until single elements, then merge sorted halves back together.

<Tabs items={['Recursive Implementation', 'Iterative (Bottom-Up) Implementation']}>
  <Tab>
  ```java
  public void mergeSort(int[] arr, int left, int right) {
      if (left >= right) return; // Base case: single element

      int mid = left + (right - left) / 2; // Avoid integer overflow
      mergeSort(arr, left, mid);
      mergeSort(arr, mid + 1, right);
      merge(arr, left, mid, right);
  }

  private void merge(int[] arr, int left, int mid, int right) {
      int n1 = mid - left + 1;
      int n2 = right - mid;
      int[] L = new int[n1];
      int[] R = new int[n2];

      System.arraycopy(arr, left, L, 0, n1);
      System.arraycopy(arr, mid + 1, R, 0, n2);

      int i = 0, j = 0, k = left;
      while (i < n1 && j < n2) {
          if (L[i] <= R[j]) arr[k++] = L[i++]; // <= preserves stability
          else arr[k++] = R[j++];
      }
      while (i < n1) arr[k++] = L[i++];
      while (j < n2) arr[k++] = R[j++];
  }
  ```
  </Tab>
  <Tab>
  ```java
  // Bottom-up Merge Sort — no recursion, same O(n log n) complexity
  public void mergeSortIterative(int[] arr) {
      int n = arr.length;
      // currSize: size of sub-arrays to be merged
      for (int currSize = 1; currSize < n; currSize *= 2) {
          // leftStart: starting index of left sub-array
          for (int leftStart = 0; leftStart < n - 1; leftStart += 2 * currSize) {
              int mid = Math.min(leftStart + currSize - 1, n - 1);
              int rightEnd = Math.min(leftStart + 2 * currSize - 1, n - 1);
              if (mid < rightEnd) {
                  merge(arr, leftStart, mid, rightEnd);
              }
          }
      }
  }
  ```
  </Tab>
</Tabs>

**Complexity:** O(n log n) all cases · **O(n) auxiliary space** · **Stable**

<PresetCard type="trap">
**Exam trap:** "Merge Sort is in-place." It is NOT. The merge step requires an O(n) auxiliary array. If a question asks for an O(1) space sort, Merge Sort is wrong. Use Heap Sort.
</PresetCard>

### 5. Quick Sort

Pick a pivot, partition the array into elements less than and greater than the pivot, then recursively sort each partition.

```java
public void quickSort(int[] arr, int low, int high) {
    if (low < high) {
        int pivotIdx = partition(arr, low, high);
        quickSort(arr, low, pivotIdx - 1);
        quickSort(arr, pivotIdx + 1, high);
    }
}

private int partition(int[] arr, int low, int high) {
    // Median-of-Three pivot selection
    int mid = low + (high - low) / 2;
    if (arr[mid] < arr[low]) swap(arr, low, mid);
    if (arr[high] < arr[low]) swap(arr, low, high);
    if (arr[mid] < arr[high]) swap(arr, mid, high);
    // arr[high] is now the median — use as pivot
    int pivot = arr[high];

    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(arr, i, j);
        }
    }
    swap(arr, i + 1, high);
    return i + 1;
}

private void swap(int[] arr, int i, int j) {
    int temp = arr[i]; arr[i] = arr[j]; arr[j] = temp;
}
```

**Complexity:** O(n log n) best/average · **O(n^2) worst** · O(log n) stack space · **Not stable**

<CaseAnalysis title="Quick Sort Worst Case  --  When Does It Happen?">
  <Case
    condition="Already sorted or reverse-sorted input with naive pivot (first/last element)"
    explanation="Every partition produces one empty sub-array and one sub-array of size n-1. This creates n levels of recursion, each doing O(n) work: total O(n^2)."
  >
    Example: `[1, 2, 3, 4, 5]` with last-element pivot.

    Pivot = 5, partition: `[1,2,3,4]` | `[]` -> n-1 elements left. Recurse.
    Pivot = 4, partition: `[1,2,3]` | `[]` -> n-2 elements left. Recurse.
    ... all n levels do O(n) work -> **O(n^2)**
  </Case>
  <Case
    condition="Median-of-Three pivot selection (recommended)"
    explanation="By choosing the median of arr[low], arr[mid], arr[high] as the pivot, sorted and reverse-sorted inputs produce near-ideal partitions."
  >
    For `[1, 2, 3, 4, 5]`: low=1, mid=3, high=5 -> median=3.

    Pivot=3 -> `[1,2]` | `[4,5]` — perfectly balanced split.

    This alone eliminates the most common pathological case.
  </Case>
</CaseAnalysis>

### 6. Heap Sort

Build a max-heap, then repeatedly extract the maximum to sort in-place.

```java
public void heapSort(int[] arr) {
    int n = arr.length;

    // Build max-heap (Floyd's algorithm — O(n))
    for (int i = n / 2 - 1; i >= 0; i--) {
        heapify(arr, n, i);
    }

    // Extract elements from heap one by one
    for (int i = n - 1; i > 0; i--) {
        swap(arr, 0, i);      // Move current max to end
        heapify(arr, i, 0);   // Restore heap property
    }
}

private void heapify(int[] arr, int n, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;

    if (largest != i) {
        swap(arr, i, largest);
        heapify(arr, n, largest); // Sift down
    }
}
```

**Complexity:** O(n log n) all cases · **O(1) space** · **Not stable**

<HighlightCard variant="neutral" title="Heap Sort  --  The Theoretically Perfect Sort Nobody Uses">
Heap Sort has the best theoretical properties: O(n log n) worst-case AND O(1) space. But in practice it is slower than Quick Sort because its access pattern destroys CPU cache locality (it jumps between parent and child indices across the array). Use it only when you need guaranteed O(n log n) AND cannot afford O(n) extra memory.
</HighlightCard>

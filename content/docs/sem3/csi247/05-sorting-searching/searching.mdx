# Searching Algorithms

Welcome to your complete guide to searching! We'll start simple and build up to advanced algorithms.

> **Why Learn This?** 
> Imagine finding a name in a phone book with 1 million entries:
> - **Without sorting**: Check every name → 1 million checks (takes hours!)
> - **With sorting + binary search**: Only 20 checks (takes seconds!)
> 
> That's the power of good algorithms!

---

## What is Searching?

Searching means finding a specific item in a collection. Like finding:
- A contact in your phone
- A word in a dictionary
- A product on Amazon

There are two main ways to search:

---

### 1. Linear Search (The Simple Way)

**Simple Explanation**: Check every item one by one until you find what you're looking for.

**Real-World Example**: Looking for your keys by checking every room in your house one by one.

**How It Works**:
1. Start from the first item
2. Is this what I'm looking for? 
   - Yes → Found it! 
   - No → Move to the next item
3. Repeat until found or no more items

**Step-by-Step Example**:
Find the number `7` in `[3, 5, 7, 9, 11]`

```text
Step 1: Check position 0 → Is 3 = 7? No
Step 2: Check position 1 → Is 5 = 7? No
Step 3: Check position 2 → Is 7 = 7? YES! Found at position 2
```

**Code**:
```java
public int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) {
            return i;  // Found it!
        }
    }
    return -1;  // Not found
}
```

**Speed**:
- **Best case**: 1 check (item is first)
- **Worst case**: n checks (item is last or not there)
- **Average**: n/2 checks

**When to use**:
- Small lists (less than 50 items)
- List is not sorted
- You only search once

---

### 2. Binary Search (The Fast Way)

**Simple Explanation**: Instead of checking every item, cut the search space in half each time. Like looking up a word in a dictionary - you don't start from page 1, you open to the middle and go forward or backward.

**Real-World Example**: Guessing a number between 1-100. You'd say "50" first, then based on "higher" or "lower", you'd say "25" or "75", cutting the range in half each time.

**Important**: The list MUST be sorted first!

**How It Works**:
1. Look at the middle item
2. Is it what I want?
   - Yes → Found it!
   - No → Is my target smaller or larger?
     - Smaller → Search the left half
     - Larger → Search the right half
3. Repeat with the half you chose

**Step-by-Step Example**:
Find `23` in sorted array `[2, 5, 8, 12, 16, 23, 38, 45, 56, 67, 78]`

```text
Array has 11 items, indices 0 to 10

Step 1: Middle is at index 5 → arr[5] = 23
        Is 23 = 23? YES! Found in 1 step!
        
Example 2: Find 16
Step 1: Middle is index 5 → arr[5] = 23
        Is 16 = 23? No
        Is 16 < 23? Yes → Search left half [2, 5, 8, 12, 16]
        
Step 2: New middle is index 2 → arr[2] = 8
        Is 16 = 8? No
        Is 16 > 8? Yes → Search right half [12, 16]
        
Step 3: New middle is index 3 → arr[3] = 12
        Is 16 = 12? No
        Is 16 > 12? Yes → Search right
        
Step 4: Only one item left → arr[4] = 16
        Found it in 4 steps!
```

**Code**:
```java
public int binarySearch(int[] arr, int target) {
    int left = 0;
    int right = arr.length - 1;
    
    while (left <= right) {
        // Find middle (safe from overflow)
        int mid = left + (right - left) / 2;
        
        if (arr[mid] == target) {
            return mid;  // Found!
        }
        
        if (arr[mid] < target) {
            left = mid + 1;  // Search right half
        } else {
            right = mid - 1;  // Search left half
        }
    }
    
    return -1;  // Not found
}
```

**Speed Comparison**:

| Array Size | Linear Search | Binary Search |
|------------|---------------|---------------|
| 10 items | Up to 10 checks | Up to 4 checks |
| 100 items | Up to 100 checks | Up to 7 checks |
| 1,000 items | Up to 1,000 checks | Up to 10 checks |
| 1,000,000 items | Up to 1M checks | Up to 20 checks |
| 1,000,000,000 items | Up to 1B checks | Up to 30 checks |

**Binary search is incredibly fast!** Even with 1 billion items, it only takes 30 checks!

**When to use**:
- List is sorted
- Large datasets
- You search many times

---

## Summary

- **Linear Search**: Simple, O(n), for small/unsorted data
- **Binary Search**: Fast, O(log n), requires sorted data

**Key Takeaway**: Always sort your data if you need to search it many times, so you can take advantage of Binary Search!

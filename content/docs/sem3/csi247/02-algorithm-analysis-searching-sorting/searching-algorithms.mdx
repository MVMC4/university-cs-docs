## 2.2 Searching Algorithms

Searching is the act of locating a specific target within a dataset. The efficiency of the search is entirely dictated by the underlying data structure and whether the data is pre-sorted.

<HighlightCard
  variant="neutral"
  title="Definition 2.2.1: Linear Iteration vs. Divide-and-Conquer"
  description="The two fundamental paradigms of searching."
>

- **Linear Search:** Sequentially checks every element. Works on any unsorted dataset. Time Complexity: $O(n)$.
- **Binary Search:** Repeatedly divides the search interval in half. **Absolute Prerequisite:** The dataset *must* be strictly sorted. Time Complexity: $O(\log n)$.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Theorem 2.2.1: Binary Search Logarithmic Bounds"
  description="Why dividing the search space yields logarithmic time."
>

At each step, the search space $N$ is halved: $N, N/2, N/4, \dots, 1$.
Mathematically, we are solving for $k$ in the equation $\frac{N}{2^k} = 1$.
Solving for $k$ yields $2^k = N \implies k = \log_2(N)$.
Thus, the maximum number of comparisons required is strictly bounded by $O(\log n)$.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Required Skill: Tracing Binary Search</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Initialize Pointers</StepTitle>
    Set `low = 0` and `high = n - 1`.
  </Step>

  <Step number={2}>
    <StepTitle>Calculate Midpoint Safely</StepTitle>
    `mid = low + (high - low) / 2;`
    *Crucial:* Using `(low + high) / 2` can cause integer overflow if the sum exceeds `Integer.MAX_VALUE`.
  </Step>

  <Step number={3}>
    <StepTitle>Evaluate and Halve</StepTitle>
    - If `arr[mid] == target`: Return `mid`.
    - If `arr[mid] < target`: Discard left half. `low = mid + 1`.
    - If `arr[mid] > target`: Discard right half. `high = mid - 1`.
    Repeat until `low > high` (target not found, return `-1`).
  </Step>
</StepByStep>

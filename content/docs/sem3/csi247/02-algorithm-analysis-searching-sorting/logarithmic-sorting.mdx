## 2.4 Logarithmic Sorting ($O(n \log n)$)

Logarithmic sorting algorithms utilize the Divide-and-Conquer paradigm to drastically outperform quadratic algorithms on massive datasets by recursively breaking the problem into smaller, manageable subproblems.

<HighlightCard
  variant="neutral"
  title="Definition 2.4.1: Recursive Partitioning & Array Merging"
  description="The core mechanics of Merge Sort and Quick Sort."
>

- **Merge Sort:** Divides the array in half recursively until single elements remain, then merges the sorted halves back together. Guarantees $O(n \log n)$ in all cases, but requires $O(n)$ auxiliary space.
- **Quick Sort:** Selects a 'pivot' element and partitions the array into elements less than and greater than the pivot. Average case $O(n \log n)$, in-place, but worst-case $O(n^2)$ if the pivot selection is poor.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Exam Question: Why is Merge Sort vastly superior to Selection Sort for large datasets?</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Structural Analysis</StepTitle>
    Selection Sort relies on nested iterative loops, comparing every unsorted element against every other unsorted element. This results in a strict $O(n^2)$ time complexity. For 1,000,000 elements, this requires $10^{12}$ operations.
  </Step>

  <Step number={2}>
    <StepTitle>Divide and Conquer Advantage</StepTitle>
    Merge Sort recursively halves the dataset ($\log n$ levels of division). At each level, it merges the halves in linear time ($O(n)$). Total operations: $n \log_2 n$. For 1,000,000 elements, this requires roughly $20,000,000$ operations.
  </Step>

  <Step number={3}>
    <StepTitle>Conclusion</StepTitle>
    As $n$ scales, the mathematical gap between $n^2$ and $n \log n$ grows exponentially. Merge Sort reduces the computational workload by orders of magnitude, making it the mandatory choice for large-scale data processing.
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>Required Skill: Quick Sort Partition Trace (Lomuto)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Select Pivot</StepTitle>
    Choose the last element as the pivot. Initialize pointer `i = low - 1`.
  </Step>

  <Step number={2}>
    <StepTitle>Partition Loop</StepTitle>
    Iterate `j` from `low` to `high - 1`. If `arr[j] <= pivot`, increment `i` and swap `arr[i]` with `arr[j]`.
  </Step>

  <Step number={3}>
    <StepTitle>Finalize Pivot</StepTitle>
    Swap the pivot (`arr[high]`) with `arr[i + 1]`. The pivot is now in its final sorted position. Recursively sort the left and right subarrays.
  </Step>
</StepByStep>

# File I/O & String Parsing

Processing external data is a fundamental skill. This guide covers reading files efficiently, tokenizing strings, and building robust parsers that survive malformed input.

---

## 1. The File I/O Ecosystem

Java provides two primary ways to read text files. Choosing the right one impacts performance and memory usage.

### Scanner vs. BufferedReader

| Feature | `Scanner` | `BufferedReader` |
| :--- | :--- | :--- |
| **Speed** | Slow (parses tokens using regex) | Fast (reads raw character buffers) |
| **Memory** | High overhead | Low overhead |
| **Use Case** | Simple console input, small files | Large files, log parsing, competitive programming |
| **Thread Safety** | Not thread-safe | Not thread-safe |

<HighlightCard variant="neutral" title="Best Practice: BufferedReader + InputStreamReader">

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class FileParser {
    public void readLargeFile(String filePath) throws IOException {
        // try-with-resources automatically closes the stream
        try (BufferedReader br = new BufferedReader(new FileReader(filePath))) {
            String line;
            while ((line = br.readLine()) != null) {
                // Process line
                System.out.println(line);
            }
        }
    }
}
```
</HighlightCard>

## 2. String Parsing & Tokenization

Once you have a line of text, you need to extract specific data fields.

### `String.split()`
The most common way to break a string into an array of substrings based on a regular expression delimiter.

```java
String csvLine = "Alice,25,Engineer";
String[] parts = csvLine.split(",");

String name = parts[0];       // "Alice"
int age = Integer.parseInt(parts[1]); // 25
String role = parts[2];       // "Engineer"
```

<Callout type="warn" title="Regex Pitfalls with split()">
The argument to `split()` is a **Regular Expression**. If your delimiter is a special regex character (like `|`, `.`, `*`, `+`), you must escape it!

- **Wrong**: `line.split("|")` (Crashes or behaves unexpectedly)
- **Right**: `line.split("\\|")` or `line.split(Pattern.quote("|"))`
</Callout>

## 3. Resource Management: `try-with-resources`

Before Java 7, developers had to write verbose `finally` blocks to ensure file streams were closed, preventing memory leaks and file locks.

```java
// The Modern Way (Java 7+)
try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
    // Use br
} catch (IOException e) {
    e.printStackTrace();
}
// br is automatically closed here, even if an exception is thrown!
```

## 4. Handling Malformed Data (Robust Parsing)

In the real world (and in exams), input files are rarely perfect. Lines might be missing columns, or numbers might contain letters. A robust parser must skip bad lines without crashing the entire program.

<StepByStep>
<StepByStepTitle>Exam Scenario: Parsing Server Logs</StepByStepTitle>
<Step number={1}>
<StepTitle>The Problem</StepTitle>
Read a log file line-by-line. Each line is formatted as `TIMESTAMP|ACTION|USER`. 
- `LOGIN` adds 1 to concurrent users.
- `LOGOUT` subtracts 1.
- Calculate the peak concurrent users.
</Step>
<Step number={2}>
<StepTitle>The Robust Implementation</StepTitle>

```java
public int findPeakConcurrentUsers(String filePath) throws IOException {
    int currentUsers = 0;
    int maxUsers = 0;

    try (BufferedReader br = new BufferedReader(new FileReader(filePath))) {
        String line;
        while ((line = br.readLine()) != null) {
            try {
                // Split by the pipe character (escaped for regex)
                String[] parts = line.split("\\|");
                
                // Validate column count
                if (parts.length < 2) continue; 
                
                String action = parts[1].trim();
                
                if ("LOGIN".equals(action)) {
                    currentUsers++;
                    maxUsers = Math.max(maxUsers, currentUsers);
                } else if ("LOGOUT".equals(action)) {
                    currentUsers--;
                }
            } catch (Exception e) {
                // Catch ArrayIndexOutOfBoundsException, NullPointerException, etc.
                // Skip malformed lines and continue to the next
                System.err.println("Skipping malformed line: " + line);
                continue;
            }
        }
    }
    return maxUsers;
}
```
</Step>
<Step number={3}>
<StepTitle>Why this works</StepTitle>
By wrapping the parsing logic of a *single line* inside a `try-catch` block *inside* the `while` loop, an exception on line 42 won't crash the program. The `catch` block logs the error, and the `continue` statement safely advances the reader to line 43.
</Step>
</StepByStep>

## Summary

- **BufferedReader**: Use for fast, line-by-line file reading.
- **try-with-resources**: Mandatory for preventing file handle leaks.
- **String.split()**: Remember that the delimiter is a Regex; escape special characters like `|` or `.`.
- **Error Handling**: Wrap individual line parsing in `try-catch` blocks to build resilient data pipelines.

## 4.2 Optimization Paradigms (Greedy & DP)

When faced with complex optimization puzzles, computer scientists rely on two primary paradigms: Greedy Algorithms and Dynamic Programming. Knowing when to apply each is a critical analytical skill.

<HighlightCard
  variant="neutral"
  title="Definition 4.2.1: Greedy Algorithms (Local Optimal Choices)"
  description="Making the choice that looks best at the current moment."
>

A Greedy algorithm builds a solution piece by piece, always choosing the next piece that offers the most immediate, obvious benefit.
**Requirement:** The problem must exhibit the **Greedy Choice Property** (a global optimum can be arrived at by selecting a local optimum).

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Definition 4.2.2: Dynamic Programming (Overlapping Subproblems)"
  description="When greedy choices fail and exhaustive search is required."
>

If a problem exhibits **Optimal Substructure** AND **Overlapping Subproblems**, Dynamic Programming is required.
**Mechanism:** Store the results of expensive function calls and return the cached result when the same inputs occur again (Memoization/Tabulation).

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Lab Scenario: Botswana Pula Coin Change (Greedy)</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Problem</StepTitle>
    Write a method that calculates change using the absolute minimum number of Botswana Pula notes/coins: `[200, 100, 50, 20, 10, 5, 2, 1, 0.50, 0.10]`.
  </Step>

  <Step number={2}>
    <StepTitle>The Greedy Logic</StepTitle>
    Because standard currency denominations are mathematically designed to possess the Greedy Choice Property, we can simply iterate from the largest denomination to the smallest, extracting as many of each as possible.
  </Step>

  <Step number={3}>
    <StepTitle>The Implementation</StepTitle>
    ```java
    public void makeChange(double amount) {
        double[] denoms = {200, 100, 50, 20, 10, 5, 2, 1, 0.50, 0.10};
        
        for (double d : denoms) {
            if (amount >= d) {
                int count = (int)(amount / d);
                System.out.println(count + " x " + d + " Pula");
                amount = amount % d; // Reduce the remaining amount
            }
        }
    }
    ```
  </Step>
</StepByStep>

<StepByStep>
  <StepByStepTitle>When Greedy Fails: The DP Necessity</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Trap</StepTitle>
    Imagine a custom currency with denominations: `[1, 3, 4]`. Target amount: `6`.
  </Step>

  <Step number={2}>
    <StepTitle>The Greedy Failure</StepTitle>
    Greedy chooses `4`, then `1`, then `1`. Total = 3 coins (4+1+1).
  </Step>

  <Step number={3}>
    <StepTitle>The DP Solution</StepTitle>
    The true optimal solution is `3 + 3 = 2` coins. Greedy fails because the local optimum (4) blocks the global optimum. DP systematically evaluates all combinations to find the true minimum.
  </Step>
</StepByStep>

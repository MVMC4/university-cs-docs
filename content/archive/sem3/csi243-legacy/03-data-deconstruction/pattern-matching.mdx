## 3.1 Pattern Matching Mechanics

Pattern matching is Haskell's primary mechanism for deconstructing data and making choices. It is cleaner, safer, and more expressive than nested `if` statements.

<Card>

### Definition 3.1.1 (Tuples in Practice)

Tuples group a fixed number of values, potentially of different types, into a single compound value. They are the standard way to return multiple values from a function.

```haskell
fst :: (a, b) -> a
fst (x, _) = x

snd :: (a, b) -> b
snd (_, y) = y
```

</Card>

<HighlightCard
  variant="neutral"
  title="Rule 3.1.1: Matching on Literals and Wildcards"
  description="Matching exact values or using the wildcard `_` to ignore unused parts of a pattern."
>

```haskell
isZero :: Int -> Bool
isZero 0 = True       -- Matches the literal 0
isZero _ = False      -- '_' is a wildcard: matches anything else
```

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Rule 3.1.2: Matching on List Cons (`x:xs`)"
  description="The `:` (cons) operator deconstructs a list into its head (`x`) and tail (`xs`)."
>

```haskell
safeHead :: [a] -> Maybe a
safeHead []    = Nothing        -- Base case: empty list
safeHead (x:_) = Just x         -- Recursive case: bind head, ignore tail
```
*Note: Matching on `x:xs` is partial if the `[]` case is omitted, leading to runtime crashes.*

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Rule 3.1.3: As-Patterns (`@`)"
  description="Binds a name to the *entire* matched value while simultaneously deconstructing it."
>

```haskell
firstTwo :: [a] -> (a, a)
firstTwo all@(x:y:_) = (x, y)
```
If called with `[1, 2, 3]`, `all` is bound to `[1, 2, 3]`, `x` to `1`, and `y` to `2`.

</HighlightCard>

<Card>

### Definition 3.1.2 (Exhaustiveness Checking)

The Haskell compiler statically verifies that all possible cases are covered. If a pattern match is non-exhaustive, GHC will emit a warning (`-Wincomplete-patterns`). Relying on partial functions (like `head`) is discouraged in production code.

</Card>

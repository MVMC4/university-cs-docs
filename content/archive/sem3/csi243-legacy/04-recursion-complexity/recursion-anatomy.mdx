## 4.1 Anatomy of Recursion

Recursion is the primary mechanism for iteration in Functional Programming. A recursive function is defined in terms of itself, breaking a problem down into smaller instances of the same problem until a trivial base case is reached.

<Card>

### Definition 4.1.1 (The Anatomy of a Recursive Function)

Every well-formed recursive function must contain two essential components:
1. **Base Case(s):** The terminating condition(s) that do not make further recursive calls. This prevents infinite loops.
2. **Recursive Step(s):** The rule that reduces the problem size and calls the function again with the smaller input, moving toward the base case.

</Card>

<HighlightCard
  variant="neutral"
  title="Rule 4.1.1: Piecewise Mathematical Specification"
  description="Recursive functions are best understood and documented using piecewise mathematical notation before coding."
>

For example, the factorial function $n!$ is defined mathematically as:
$$
fac(n) = 
\begin{cases} 
1 & \text{if } n = 0 \quad \text{(Base Case)} \\
n \times fac(n-1) & \text{if } n > 0 \quad \text{(Recursive Step)}
\end{cases}
$$

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Dry-Running Mechanics: Tracing `fac 3`</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Initial Call</StepTitle>
    Evaluate `fac 3`. Since $3 > 0$, apply the recursive step:
    `fac 3 = 3 * fac 2`
  </Step>

  <Step number={2}>
    <StepTitle>First Recursive Expansion</StepTitle>
    Evaluate `fac 2`. Since $2 > 0$, apply the recursive step:
    `fac 2 = 2 * fac 1`
    Substitute back: `fac 3 = 3 * (2 * fac 1)`
  </Step>

  <Step number={3}>
    <StepTitle>Second Recursive Expansion</StepTitle>
    Evaluate `fac 1`. Since $1 > 0$, apply the recursive step:
    `fac 1 = 1 * fac 0`
    Substitute back: `fac 3 = 3 * (2 * (1 * fac 0))`
  </Step>

  <Step number={4}>
    <StepTitle>Base Case Resolution</StepTitle>
    Evaluate `fac 0`. Since $n = 0$, the base case applies:
    `fac 0 = 1`
  </Step>

  <Step number={5}>
    <StepTitle>Final Evaluation (Substitution)</StepTitle>
    Substitute `1` back up the call stack:
    `fac 3 = 3 * (2 * (1 * 1))`
    `fac 3 = 3 * (2 * 1)`
    `fac 3 = 3 * 2`
    `fac 3 = 6`
  </Step>
</StepByStep>

<Card>

### Definition 4.1.2 (The Importance of the Dry Run)

A dry run is a manual, step-by-step substitution trace of a function's execution. It is a mandatory step in the 5-Part Framework to verify that the recursive logic correctly reduces the problem size and reaches the base case before any code is written.

</Card>

## 7.2 The HOF Trinity & List Comprehensions

Higher-Order Functions (HOFs) allow you to express *what* to compute rather than *how* to iterate.

<HighlightCard
  variant="neutral"
  title="Definition 7.2.1: The HOF Trinity"
  description="The foundational functions for declarative list processing."
>

- **`map :: (a -> b) -> [a] -> [b]`**: Applies a transformation to every element.
- **`filter :: (a -> Bool) -> [a] -> [a]`**: Keeps only elements satisfying a predicate.
- **`foldr :: (a -> b -> b) -> b -> [a] -> b`**: Reduces a list to a single value, right-associative.

</HighlightCard>

<Card>

### Definition 7.2.2 (`foldr` vs `foldl'`)

- **`foldr`**: Right-associative (`f x1 (f x2 (f x3 z))`). Lazy in its second argument, allowing it to work on **infinite lists** if the combining function short-circuits (like `||` or `:`).
- **`foldl'`**: Left-associative and **strict** (`f (f (f z x1) x2) x3`). Forces the accumulator at every step. Ideal for computing a single scalar (like a sum) over **finite lists** to guarantee O(1) space and prevent space leaks.

</Card>

<StepByStep>
  <StepByStepTitle>Example: `foldr` Dry Run Trace</StepByStepTitle>

  <Step number={1}>
    <StepTitle>Initial Expression</StepTitle>
    `foldr (+) 0 [1, 2, 3]`
  </Step>

  <Step number={2}>
    <StepTitle>Expand Right-Associatively</StepTitle>
    `=> 1 + (foldr (+) 0 [2, 3])`
    `=> 1 + (2 + (foldr (+) 0 [3]))`
    `=> 1 + (2 + (3 + (foldr (+) 0 [])))`
  </Step>

  <Step number={3}>
    <StepTitle>Apply Base Case</StepTitle>
    `=> 1 + (2 + (3 + 0))`
  </Step>

  <Step number={4}>
    <StepTitle>Evaluate</StepTitle>
    `=> 1 + (2 + 3) => 1 + 5 => 6`
  </Step>
</StepByStep>

<HighlightCard
  variant="neutral"
  title="Definition 7.2.3: List Comprehensions"
  description="Declarative, set-builder-like syntax for generating and filtering lists."
>

**Syntax:** `[expression | generator(s), predicate(s)]`

- **Basic:** `[x * 2 | x <- [1..5]]` (Equivalent to `map`)
- **Filtered:** `[x * 2 | x <- [1..10], even x]` (Equivalent to `map` . `filter`)
- **Dependent Generators:** `[(x,y) | x <- [1..3], y <- [x..3]]` (Later generators can use earlier variables)

</HighlightCard>

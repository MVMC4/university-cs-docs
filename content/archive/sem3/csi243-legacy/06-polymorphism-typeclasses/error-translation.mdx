## 6.3 The GHC Error Translator

Surviving GHC compiler errors requires recognizing patterns. Here are the 4 most common beginner crashes and how to systematically fix them.

<HighlightCard
  variant="neutral"
  title="Error 1: List vs. Element Mismatch"
  description="`Couldn't match expected type 'Int' with actual type '[Int]'`"
>

**Cause:** You passed a list where a single element was expected, or vice versa.
**Common Culprit:** Using `++` to append a single element instead of `:`. 
**Fix:** Change `xs ++ 5` to `xs ++ [5]` or `5 : xs`.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Error 2: Scope or Spelling Errors"
  description="`Not in scope: variable 'x'`"
>

**Cause:** 
1. Typo in the variable name.
2. The variable is defined in a different scope (e.g., inside a `where` clause but used outside).
3. Indentation error caused the variable binding to be parsed as a separate, unrelated expression.
**Fix:** Check spelling, verify indentation aligns with the binding construct (`let`, `where`, `case`), and ensure the variable is in scope.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Error 3: Parse Errors on Input '=' or '|'"
  description="`Parse error on input '='` or `Parse error on input '|'`"
>

**Cause:** 
1. Missing `in` keyword after a `let` binding.
2. Misaligned guards (`|`) or `where` clauses violating the layout rule.
3. Using guards directly after a `let` binding instead of a `where` clause.
**Fix:** Ensure `let x = 5 in ...` is complete. Ensure guards are indented further than the function name. Use `where` for function-level guards, not `let`.

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="Error 4: Missing Typeclass Instances"
  description="`No instance for (Num [Char])`"
>

**Cause:** You are trying to perform numeric operations (like `+` or `-`) on a `String` (`[Char]`).
**Common Culprit:** Forgetting to convert a string input to a number using `read`.
**Fix:** Use `read myString :: Int` (with a type annotation) or `read myString :: Double` before performing arithmetic.

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Example: Diagnosing a Parse Error</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The Broken Code</StepTitle>
    ```haskell
    classify n = let label = n * 2
      | label > 10 = "Big"
      | otherwise  = "Small"
    ```
  </Step>

  <Step number={2}>
    <StepTitle>The Error</StepTitle>
    `Parse error on input '|'`
  </Step>

  <Step number={3}>
    <StepTitle>The Diagnosis</StepTitle>
    A `let` binding expects an `in` expression to follow it. Guards cannot directly follow a `let` binding.
  </Step>

  <Step number={4}>
    <StepTitle>The Fix</StepTitle>
    Replace `let` with a `where` clause, which is designed to scope over guards:
    ```haskell
    classify n
      | label > 10 = "Big"
      | otherwise  = "Small"
      where
        label = n * 2
    ```
  </Step>
</StepByStep>

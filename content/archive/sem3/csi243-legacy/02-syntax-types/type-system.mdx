## 2.1 The Type System Survival Guide

Haskell's type system is strict, static, and inferred. Understanding the nuances of primitive types and typeclasses is mandatory to avoid compilation errors.

<HighlightCard
  variant="neutral"
  title="Rule 2.1.1: Numeric Types"
  description="Haskell distinguishes between bounded machine integers, arbitrary precision integers, and floating-point numbers."
>

- **`Int`**: Bounded machine integer (typically 64-bit on modern systems). Fast, but subject to overflow.
- **`Integer`**: Arbitrary precision integer. No overflow, but slower and consumes more memory.
- **`Float`**: Single-precision floating-point number.
- **`Double`**: Double-precision floating-point number (the default for fractional literals).

</HighlightCard>

<HighlightCard
  variant="neutral"
  title="The Num Typeclass Trap"
  description="Why integer literals are polymorphic, but decimal literals are strictly fractional."
>

- The literal `5` is polymorphic. Its type is `Num a => a`, meaning it can be an `Int`, `Integer`, `Float`, or `Double` depending on context.
- The literal `5.0` is strictly fractional. Its type is `Fractional a => a`. It **cannot** be used where an `Int` is expected without explicit conversion (e.g., `round`, `floor`, `truncate`).

</HighlightCard>

<Card>

### Definition 2.1.1 (Text: Char vs. String)

- **`Char`**: A single Unicode character, denoted by **single quotes** (e.g., `'a'`, `'\n'`).
- **`String`**: A list of characters, denoted by **double quotes** (e.g., `"hello"`). Crucially, `String` is just a type synonym for `[Char]`.

</Card>

<Card>

### Definition 2.1.2 (Booleans)

The `Bool` type has exactly two data constructors: `True` and `False` (note the uppercase). Logical operators are `&&` (AND), `||` (OR), and `not` (NOT).

</Card>

<HighlightCard
  variant="neutral"
  title="Rule 2.1.3: The Negative Number Trap"
  description="The parser interprets a minus sign immediately following a function as subtraction, not negation."
>

Applying a function to a negative number requires parentheses. 
- **Incorrect:** `f -5` (Parsed as: apply `f` to nothing, then subtract 5, which is a parse error).
- **Correct:** `f (-5)` (Parsed as: apply `f` to the negative number `-5`).

</HighlightCard>

<StepByStep>
  <StepByStepTitle>Example: Type Conversion with `read` and `show`</StepByStepTitle>

  <Step number={1}>
    <StepTitle>The `show` Function</StepTitle>
    Converts a value to its `String` representation. 
    `show 42` yields `"42"`.
  </Step>

  <Step number={2}>
    <StepTitle>The `read` Function</StepTitle>
    Parses a `String` into a value. Because `read` is polymorphic (`Read a => String -> a`), the compiler often requires a **type annotation** to resolve ambiguity.
    `read "5" :: Int` yields `5`.
  </Step>

  <Step number={3}>
    <StepTitle>The Ambiguity Trap</StepTitle>
    `read "5"` without a type annotation will often result in an "Ambiguous type variable" error, as the compiler cannot infer whether you want an `Int`, `Double`, or `Integer`.
  </Step>
</StepByStep>

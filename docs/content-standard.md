# Content standard

One structure, one page template, one component vocabulary and one assessment format for every course, in the style of Google's developer documentation. This extends the chapter shape in [content-architecture.md](content-architecture.md); where the two disagree, this document wins.

## 1. Diagnosis: why the notes feel like components smashed together

Measured on 2026-10-15 across `content/docs`.

### Five separate note systems

| Courses | How notes are produced | What it looks like |
|---|---|---|
| CSI131, CSI141, CSI161, MAT111, COM141, CSI132, CSI142, MAT122, STA122, COM142 | Generated by `TopicNotesFlow`, `ChapterReview`, `ChapterQuestions`, `ChapterExam` from TypeScript data | Page title is just "Notes"; the description is repeated under it; a row of Orient/Understand/Apply/Verify/Transfer chips; a checklist at the top; ten "worked cases" |
| CSI243 | Hand-written MDX, 96 pages | Good prose, but a full quiz card after every section (six on one page), code and its output in separate unlabelled blocks, plus step boxes, comparison tables, diagrams and a checklist |
| CSI213 | Hand-written MDX, 30 pages | Almost no prose: definition cards, example step-boxes and theorem cards stacked one after another; an `##` heading repeats the page title |
| CSI247 notes | Generated study-guide chapters (`features/courses/csi247/study-guides`, about 1,700 lines of their own CSS) | The topic quiz comes before the definition; about 20 collapsed sections per page |
| MAT221 | An embedded copy of a separate site (`features/courses/mat221/source`) with its own CSS and MathJax | Still the old cream, serif and thick-border theme, inside the new site |

## 2. The standard

### 2.1 Course and topic shape (the sidebar)

```text
semN/<course>/
  index.mdx               Overview: what the course covers, topic cards, how it is assessed
  01-<topic>/             Numbered folder; meta.json title "1. Topic name"
    index.mdx             Overview: what you'll learn, prerequisites, the pages below
    notes.mdx | notes/    Notes: one page, or a folder of lessons for a large topic
    cheat-sheet.mdx       Cheat sheet (optional)
    review.mdx            Review: flashcards and a scored quiz
    questions.mdx         Practice: guided questions with worked solutions
    exam.mdx              Exam practice: exam-style problems with marks
    resources.mdx         Resources for this topic (optional)
  resources.mdx           Resources for the whole course
```

The sidebar and the topic tabs use the same labels everywhere, in this order: Overview, Notes, Cheat sheet, Review, Practice, Exam practice, Resources. Overview, Notes, Review, Practice and Exam practice are required; Cheat sheet and Resources are optional. A topic may leave out an optional page; it may not invent another one. A course folder holds only its overview, its numbered topics and its resources page.

### 2.2 Notes page template

Every notes page, in this order:

1. **Title** is the lesson name (never just "Notes"). **Description** is one sentence. Nothing repeats them.
2. **What you'll learn**: three to five objectives (`LearningObjectives`).
3. **Sections**: each `##` section teaches one idea in this order: plain explanation → definition (`KeyTerm`) → why it works → example (code with output, figure or table) → at most one callout.
4. **Common mistakes**: one section of `mistake` callouts, or a table.
5. **Summary**: one `key` callout with the points to remember.
6. **Check your understanding**: three to five questions that expand to show the answer, at the end of the page, not between sections.
7. Pager (automatic).

### 2.3 Component vocabulary

Notes use only these. Everything else is either retired or rendered through one of them.

| Element | Use | Replaces |
|---|---|---|
| Prose, `##`, `###`, lists | Teaching | |
| Code block with `title="File.java"`, then an `Output` block | Programs and their output | separate unlabelled input and output blocks |
| Figure with caption (`SiteDiagram`, image, `Mermaid`) | Diagrams | |
| Table | Comparisons, traces | `ComparisonTable` (renders as a table) |
| `Callout` with `note`, `tip`, `caution`, `mistake`, `key`, `analogy` | Asides, one meaning each | `PresetCard`, `HighlightCard`, `CommonMistake`, `RecognitionStrategy` |
| `KeyTerm` | A definition or theorem | `Card`, `ConceptBlock`, `TheoremBlock`, MAT221 `Concept` and `Theorem` |
| `Steps` | A procedure or a worked example | `StepByStep`, `MethodSteps`, `InteractiveStepper`, `FumaSteps` |
| `LearningObjectives`, `Prerequisites` | Page opening | the generated chip row and top checklist |
| Interactive pieces (`JavaTryIt`, `HaskellTryIt`, algorithm stories) | Running or watching code | one shared frame: title bar, stage, controls |

Retired components keep working: they render through the standard element, so old pages look consistent before their content is migrated.

### 2.4 Assessment

| Kind | Where | Component | Data |
|---|---|---|---|
| Check your understanding | End of each notes page | `CheckQuestions` (expand to reveal, not scored) | in the MDX, three to five items |
| Review | `review.mdx` | `FlashcardDeck` then `QuizRef` | `content/flashcard-data`, `content/quiz-data` |
| Practice | `questions.mdx` | `ExamQuestion` / `SubQuestion` with worked solutions | in the MDX |
| Exam practice | `exam.mdx` | `ExamQuestion` / `SubQuestion` with marks | in the MDX |

Generated courses (Semesters I and II) render through the same four components.

### 2.5 Enforcement

`npm run audit:content-standard` reports every course against this standard (`--verbose` lists each finding, `--course <code>` narrows it to one course, `--json` is for tools, `--strict` exits 1 on any finding). It flags:

- a topic folder contains a page outside the list in 2.1, or lists them out of order;
- a notes page has no description, repeats its title as a heading, or uses a retired component;
- a notes page has quiz components before its last section;
- a review, practice or exam page uses a component other than the one in 2.4;
- a page built by a generator or by the MAT221 source site (counted separately, fixed in phase 4).

Baseline on 2026-10-15: 0 of 16 courses meet the standard, 1,184 findings. It joins `npm run audit:content` with `--strict` once every course passes.

## 3. Migration plan

| Phase | Work | Who |
|---|---|---|
| 1 | Site chrome, tokens, navigation, Overview, timer fixes | Done on `feat/ui-material-theme`, not yet committed |
| 2 | Agree this document; write the audit script; report conformance per course | Opus |
| 3 | Render every overlapping component through the standard elements (no content changes) | Opus |
| 4 | Generators: Semesters I and II, CSI247 study guides, MAT221 | Opus, one at a time, verified in the browser |
| 5 | Hand-written content: CSI243, CSI213, CSI323, the rest of CSI247 | Sonnet agents in parallel, one course each, held to the audit; Opus reviews every diff |

Phase 5 is the only phase that suits cheaper parallel agents: the rules are fixed by then and the audit catches drift. Before phases 2 and 3 exist, each agent would invent its own standard, which is how the site got here.

## 4. Decisions

Agreed on 2026-10-15:

1. **In-note checks.** Quizzes inside notes move to one "Check your understanding" block at the end of each notes page, with answers revealed on demand.
2. **MAT221.** Rebuilt on the standard template, sidebar shape and assessment components; the embedded source site is retired once its content has moved.
3. **CSI247 and CSI243.** The ownership notes in `WORK_ORDERS.md` are out of date; this work may change both courses.
4. **Renamed pages.** Every renamed or moved page gets a permanent redirect from its old URL.

# Recursion and Algorithmic Problem Solving

Recursion is when a function solves a problem by calling a smaller version of itself. The key insight is that the solution structure repeats at every level — like Russian nesting dolls, each one containing a smaller copy of itself.

<PresetCard type="builds">
Recursion is the foundation of **Merge Sort and Quick Sort** (Chapter 5), all **tree traversals** (Chapter 6), and **graph DFS** (Chapter 8). Mastering recursion here pays dividends across the entire course.
</PresetCard>

<PresetCard type="exam">
**Exam patterns to expect:** (1) Write a recursive method with a correct base case. (2) Trace a call stack by hand. (3) Apply the Master Theorem to a recurrence. (4) Identify whether greedy or DP solves a given problem optimally.
</PresetCard>

## 1. Understanding the Call Stack

When a function calls itself, Java saves the current state (local variables, return address) as a **stack frame** on the call stack. Frames are added on each call and removed on each return — exactly like a stack (LIFO).

### Factorial — Step by Step

<InteractiveStepper>
  <StepperStep title="factorial(4) is called  --  frame pushed">
    ```
    Call Stack:
    ┌─────────────────┐
    │ factorial(4)    │  ← waiting for factorial(3)
    └─────────────────┘
    ```
    n=4 is not the base case. Java saves this frame and calls `factorial(3)`.
  </StepperStep>
  <StepperStep title="factorial(3), factorial(2), factorial(1) stack up">
    ```
    Call Stack (top = most recent):
    ┌─────────────────┐
    │ factorial(1)    │  ← BASE CASE: returns 1
    ├─────────────────┤
    │ factorial(2)    │  ← waiting
    ├─────────────────┤
    │ factorial(3)    │  ← waiting
    ├─────────────────┤
    │ factorial(4)    │  ← waiting
    └─────────────────┘
    ```
    `factorial(1)` hits the base case `if (n &lt;= 1) return 1`. The stack now unwinds.
  </StepperStep>
  <StepperStep title="Stack unwinds  --  each frame computes and returns">
    `factorial(1)` returns **1** -> frame popped

    `factorial(2)` computes 2 x 1 = **2** -> frame popped

    `factorial(3)` computes 3 x 2 = **6** -> frame popped

    `factorial(4)` computes 4 x 6 = **24** -> frame popped

    **Final result: 24**

    ```java
    public int factorial(int n) {
        if (n <= 1) return 1;           // Base case
        return n * factorial(n - 1);    // Recursive case — makes progress
    }
    ```
  </StepperStep>
</InteractiveStepper>

### StackOverflowError

```java
// DANGER: No base case — infinite recursion
public void infiniteRecursion() {
    infiniteRecursion(); // Pushes frames forever until memory runs out
}
```

The JVM gives each thread ~512KB of stack space. Without a base case, frames accumulate until a `StackOverflowError` is thrown. This is not catchable in production — always verify your base case is reachable.

## 2. The Two Laws of Recursion

Every correct recursive function must satisfy both:

<HighlightCard variant="danger" title="Law 1: There must be a base case">
The base case is the condition where the function returns a direct answer without calling itself. Without it, recursion never terminates.

```java
if (n <= 1) return 1; // BASE CASE — stops here
```
</HighlightCard>

<HighlightCard variant="warning" title="Law 2: Every recursive call must make progress toward the base case">
The recursive call must bring you closer to the base case. `factorial(n-1)` reduces n by 1 each time — guaranteed to reach n=1.

```java
return n * factorial(n - 1); // n decreases → moves toward base case
```

If the argument does not decrease (or increase toward the base case), you have infinite recursion.
</HighlightCard>

## 3. Recursion vs Iteration

<Columns>
  <Column>
  ### Recursive Factorial
  ```java
  public int factorial(int n) {
      if (n <= 1) return 1;
      return n * factorial(n - 1);
  }
  ```
  - Elegant, mirrors mathematical definition
  - O(n) space (call stack frames)
  - Risk of StackOverflowError for large n
  </Column>
  <Column>
  ### Iterative Factorial
  ```java
  public int factorial(int n) {
      int result = 1;
      for (int i = 2; i <= n; i++) result *= i;
      return result;
  }
  ```
  - More verbose
  - **O(1) space** — no stack frames
  - No overflow risk for reasonable n
  </Column>
</Columns>

<PresetCard type="trap">
**Exam trap:** "Recursion is always slower than iteration." FALSE. Tail-recursive calls can be optimised by some compilers/JVMs. More importantly, some problems (tree traversal, backtracking, divide-and-conquer) are dramatically cleaner with recursion, and the overhead difference is negligible for typical input sizes.
</PresetCard>

## 4. Classic Recursive Examples

### Fibonacci Numbers

```java
// Naive — O(2^n): recalculates the same subproblems exponentially
public int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

// Memoised — O(n): cache results to avoid repeated computation
private Map<Integer, Integer> memo = new HashMap<>();
public int fibMemo(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n); // Cache hit
    int result = fibMemo(n - 1) + fibMemo(n - 2);
    memo.put(n, result);                          // Cache miss — store
    return result;
}
```

### Binary Search (Recursive)

```java
public int binarySearch(int[] arr, int target, int low, int high) {
    if (low > high) return -1; // Base case: not found
    int mid = low + (high - low) / 2;
    if (arr[mid] == target) return mid;
    if (arr[mid] > target) return binarySearch(arr, target, low, mid - 1);
    return binarySearch(arr, target, mid + 1, high);
}
```

### Merge Sort (Preview — Chapter 5)

```java
public void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return; // Base case: single element
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);       // Sort left half
    mergeSort(arr, mid + 1, right);  // Sort right half
    merge(arr, left, mid, right);    // Merge sorted halves
}
```

## 5. Analysing Recursive Algorithms

### Method 1: The Master Theorem

For recurrences of the form **T(n) = aT(n/b) + f(n)**:

<CaseAnalysis title="The Master Theorem  --  Three Cases">
  <Case
    condition="Case 1: f(n) = O(n^(log_b(a) - e)) for some e > 0"
    explanation="The recursive work dominates. The root-to-leaf cost grows geometrically."
  >
    Example: `T(n) = 8T(n/2) + n²`

    `log₂(8) = 3`. Is `n²` = O(n^(3-e))? Yes (e=1). -> **Case 1**: T(n) = **Theta(n^3)**
  </Case>
  <Case
    condition="Case 2: f(n) = Theta(n^(log_b(a)))"
    explanation="Recursive work and non-recursive work are equal at each level. Cost grows by a log factor."
  >
    Example: `T(n) = 2T(n/2) + n`

    `log₂(2) = 1`. Is `n` = Theta(n^1)? Yes. -> **Case 2**: T(n) = **Theta(n log n)**

    This is Merge Sort's recurrence.
  </Case>
  <Case
    condition="Case 3: f(n) = Omega(n^(log_b(a) + e)) for some e > 0"
    explanation="Non-recursive work dominates. The top-level cost eclipses the recursive work."
  >
    Example: `T(n) = 2T(n/2) + n²`

    `log₂(2) = 1`. Is `n²` = Omega(n^(1+e))? Yes (e=1). -> **Case 3**: T(n) = **Theta(n^2)**
  </Case>
</CaseAnalysis>

### Method 2: The Recursion Tree

Draw the recursion tree. At each level, count the total work. Sum across all levels.

```
T(n) = 2T(n/2) + n

Level 0: n               (1 call × n work)
Level 1: n/2 + n/2 = n  (2 calls × n/2 work)
Level 2: n/4×4 = n      (4 calls × n/4 work)
...
Level log n: base cases

Total levels: log n. Work per level: n. Total: n log n.
```

## 6. Backtracking: Try, Explore, Undo

Backtracking is a systematic way to enumerate all possibilities by building a solution incrementally and abandoning ("pruning") paths that cannot lead to a valid solution.

**Pattern:**
```java
void backtrack(State state) {
    if (isSolution(state)) {
        recordSolution(state);
        return;
    }
    for (Choice choice : getChoices(state)) {
        makeChoice(state, choice);    // Choose
        backtrack(state);             // Explore
        undoChoice(state, choice);    // Un-choose (backtrack)
    }
}
```

### N-Queens Problem

Place N queens on an NxN chessboard so no two queens attack each other.

```java
public void solveNQueens(int row, boolean[] cols, boolean[] diag1, boolean[] diag2, List<Integer> placement) {
    if (row == n) {
        solutions.add(new ArrayList<>(placement)); return;
    }
    for (int col = 0; col < n; col++) {
        if (!cols[col] && !diag1[row - col + n] && !diag2[row + col]) {
            // Choose
            cols[col] = diag1[row - col + n] = diag2[row + col] = true;
            placement.add(col);
            // Explore
            solveNQueens(row + 1, cols, diag1, diag2, placement);
            // Un-choose
            cols[col] = diag1[row - col + n] = diag2[row + col] = false;
            placement.remove(placement.size() - 1);
        }
    }
}
```

## 7. Common Complexities

| Recurrence | Pattern | Complexity |
|---|---|---|
| T(n) = T(n-1) + O(1) | Linear recursion (factorial) | O(n) |
| T(n) = 2T(n-1) + O(1) | Doubling (naive Fibonacci) | O(2^n) |
| T(n) = T(n/2) + O(1) | Half-input (binary search) | O(log n) |
| T(n) = 2T(n/2) + O(n) | Split-and-merge (Merge Sort) | O(n log n) |
| T(n) = T(n-1) + O(n) | Selection Sort recursion | O(n^2) |

## 8. Common Mistakes

### Mistake 1: Missing or Unreachable Base Case

```java
// BUG: n can be negative — base case never reached!
public int countdown(int n) {
    if (n == 0) return 0;
    return countdown(n - 2); // Skips 0 for odd n
}

// FIX: Use <= instead of ==
public int countdown(int n) {
    if (n <= 0) return 0;
    return countdown(n - 2);
}
```

### Mistake 2: Not Making Progress

```java
// BUG: n never changes!
public int broken(int n) {
    if (n == 0) return 0;
    return broken(n); // Same argument → infinite recursion
}
```

### Mistake 3: Excessive Stack Depth for Large Input

For n &gt; ~5000, recursive solutions risk StackOverflowError in Java's default configuration. Convert to iterative with an explicit stack, or use tail recursion (if your JVM supports it).

# Stack & Queue Patterns

This page covers the correct Java idioms for stacks and queues, walks through the Shunting Yard algorithm step by step, and gives you a decision framework for choosing between Stack, Queue, Deque, and PriorityQueue.

---

## 1. Idiomatic Java — Stop Using `java.util.Stack`

`java.util.Stack` extends `Vector`, which is a synchronised legacy collection. It carries thread-locking overhead on every operation, even in single-threaded code. The Java documentation explicitly recommends `Deque` instead.

<HighlightCard variant="success" title="The Correct Idiom  --  Use This Everywhere">

```java
// ✅ Stack (LIFO) — push to front, pop from front
Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);          // addFirst
stack.push(20);
int top = stack.pop();   // removeFirst → 20
int peek = stack.peek(); // 20... wait, we already popped. Peek without removing → throws if empty

// ✅ Queue (FIFO) — add to back, remove from front
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(10);         // addLast
queue.offer(20);
int front = queue.poll(); // removeFirst → 10
```
</HighlightCard>

<Callout type="warn" title="ArrayDeque rejects null  --  this is a feature">
Unlike `Stack` (which allows nulls), `ArrayDeque` throws `NullPointerException` on null. This is intentional — `poll()` returns `null` to signal an empty queue, so storing null values would be ambiguous. If you need null-safe behaviour, use `LinkedList` (but note its higher memory overhead).
</Callout>

## 2. Infix to Postfix — The Shunting Yard Algorithm

The Shunting Yard algorithm (Dijkstra, 1961) converts a human-readable infix expression to postfix (Reverse Polish Notation) that a computer can evaluate with a simple stack.

**Operator precedence:**
| Operator | Precedence | Associativity |
|---|---|---|
| `^` | 3 | Right |
| `*`, `/` | 2 | Left |
| `+`, `-` | 1 | Left |

**Rules:**
1. **Operand** -> append to output immediately
2. **`(`** -> push to operator stack
3. **`)`** -> pop and output until matching `(` is found
4. **Operator** -> pop and output any operators on the stack with **higher or equal precedence** (for left-associative), then push the current operator

<InteractiveStepper>
  <StepperStep title="Convert: ( A + B ) * C - D / E">
    We will process each token left to right. Output buffer starts empty. Operator stack starts empty.

    **Token 1: `(`** -> push to stack.

    Stack: `[ ( ]` &nbsp;&nbsp; Output: ` `
  </StepperStep>
  <StepperStep title="Tokens: A, +, B">
    **Token 2: `A`** (operand) -> output directly.

    Output: `A`

    **Token 3: `+`** (operator) -> stack top is `(`, which has lower precedence. Push `+`.

    Stack: `[ (, + ]` &nbsp;&nbsp; Output: `A`

    **Token 4: `B`** (operand) -> output directly.

    Stack: `[ (, + ]` &nbsp;&nbsp; Output: `A B`
  </StepperStep>
  <StepperStep title="Token: )  --  flush until matching (">
    **Token 5: `)`** -> pop and output until `(` is found. Pop `+` -> output. Pop `(` -> discard.

    Stack: `[ ]` &nbsp;&nbsp; Output: `A B +`
  </StepperStep>
  <StepperStep title="Token: *  --  push (stack empty, no pop needed)">
    **Token 6: `*`** -> stack is empty, push directly.

    Stack: `[ * ]` &nbsp;&nbsp; Output: `A B +`

    **Token 7: `C`** (operand) -> output directly.

    Stack: `[ * ]` &nbsp;&nbsp; Output: `A B + C`
  </StepperStep>
  <StepperStep title="Token: -  --  pop * (equal precedence, left-assoc), then push -">
    **Token 8: `-`** -> `-` has precedence 1. Stack top `*` has precedence 2 (higher) -> pop and output `*`.

    Stack now empty -> push `-`.

    Stack: `[ - ]` &nbsp;&nbsp; Output: `A B + C *`

    **Token 9: `D`** -> output directly.

    Stack: `[ - ]` &nbsp;&nbsp; Output: `A B + C * D`
  </StepperStep>
  <StepperStep title="Token: /  --  higher precedence than -, push it">
    **Token 10: `/`** -> `/` has precedence 2. Stack top `-` has precedence 1 (lower) -> push `/`.

    Stack: `[ -, / ]` &nbsp;&nbsp; Output: `A B + C * D`

    **Token 11: `E`** -> output directly.

    Stack: `[ -, / ]` &nbsp;&nbsp; Output: `A B + C * D E`
  </StepperStep>
  <StepperStep title="End of input  --  flush remaining operators">
    Pop `/` -> output. Pop `-` -> output.

    **Final Postfix: `A B + C * D E / -`** ✓

    ```java
    public String infixToPostfix(String expr) {
        StringBuilder output = new StringBuilder();
        Deque<Character> stack = new ArrayDeque<>();
        Map<Character, Integer> prec = Map.of('+',1, '-',1, '*',2, '/',2, '^',3);

        for (char token : expr.replace(" ", "").toCharArray()) {
            if (Character.isLetterOrDigit(token)) {
                output.append(token).append(' ');
            } else if (token == '(') {
                stack.push(token);
            } else if (token == ')') {
                while (!stack.isEmpty() && stack.peek() != '(')
                    output.append(stack.pop()).append(' ');
                stack.pop(); // discard '('
            } else {
                // Operator: pop higher/equal precedence (left-assoc)
                while (!stack.isEmpty() && stack.peek() != '(' &&
                       prec.getOrDefault(stack.peek(), 0) >= prec.get(token))
                    output.append(stack.pop()).append(' ');
                stack.push(token);
            }
        }
        while (!stack.isEmpty()) output.append(stack.pop()).append(' ');
        return output.toString().trim();
    }
    ```
  </StepperStep>
</InteractiveStepper>

## 3. Postfix Evaluation

Once you have a postfix expression, evaluating it is simpler than conversion:

```java
public int evaluatePostfix(String postfix) {
    Deque<Integer> stack = new ArrayDeque<>();
    for (String token : postfix.split(" ")) {
        if (token.matches("-?\d+")) {
            stack.push(Integer.parseInt(token)); // Push operand
        } else {
            int b = stack.pop(); // Second operand (popped first)
            int a = stack.pop(); // First operand
            switch (token) {
                case "+" -> stack.push(a + b);
                case "-" -> stack.push(a - b);
                case "*" -> stack.push(a * b);
                case "/" -> {
                    if (b == 0) throw new ArithmeticException("Division by zero");
                    stack.push(a / b);
                }
            }
        }
    }
    return stack.pop();
}
```

<PresetCard type="trap">
**Order matters when popping two operands.** The first `pop()` is the RIGHT operand (b), the second `pop()` is the LEFT operand (a). For subtraction and division this is critical: `"5 3 -"` means 5-3=2, not 3-5=-2.
</PresetCard>

## 4. Algorithm Selection Framework

<CaseAnalysis title="Which linear structure should I reach for?">
  <Case
    condition="You need to reverse something or track state for backtracking"
    explanation="Stacks (LIFO) are the natural structure for reversal, undo systems, call stacks, DFS traversal, and expression parsing."
  >
    **Use `Deque<T> stack = new ArrayDeque<>()`**

    - Browser back/forward history
    - Balanced parentheses validation
    - Infix to postfix conversion
    - Iterative DFS
    - Undo/redo systems

    Key operations: `push()`, `pop()`, `peek()` — all O(1)
  </Case>
  <Case
    condition="You need to process things in arrival order"
    explanation="Queues (FIFO) guarantee fairness  --  the first item in is the first item processed. Essential for BFS and any scheduling scenario."
  >
    **Use `Queue<T> queue = new ArrayDeque<>()`**

    - BFS level-by-level graph traversal
    - Printer spooler, CPU task scheduling
    - Producer-consumer pipelines
    - Level-order tree traversal

    Key operations: `offer()`, `poll()`, `peek()` — all O(1)
  </Case>
  <Case
    condition="You always need the minimum or maximum element instantly"
    explanation="PriorityQueue maintains heap order so the smallest (or largest) element is always accessible in O(1). Insertion and removal are O(log n)."
  >
    **Use `PriorityQueue<T>` with a Comparator**

    - Dijkstra's shortest path algorithm
    - Huffman encoding
    - Median maintenance
    - Event-driven simulation (next event by timestamp)

    Key operations: `offer()` O(log n), `poll()` O(log n), `peek()` O(1)
  </Case>
  <Case
    condition="You need both ends  --  add/remove from front AND back"
    explanation="Deque (double-ended queue) combines stack and queue semantics. Essential for sliding window problems and palindrome checking."
  >
    **Use `Deque<T> deque = new ArrayDeque<>()`**

    - Sliding window maximum (Monotonic Deque)
    - Palindrome checking (remove from both ends)
    - BFS with priority (add urgent nodes to front)
    - LRU cache (move recently used to front)

    Key operations: `addFirst()`, `addLast()`, `removeFirst()`, `removeLast()` — all O(1)
  </Case>
</CaseAnalysis>
